# 整段曲带团队 HUD：完整动效设计 V1

日期：2026-10-27。状态：**静态造型已获认可，本文件为动效提案；未实现到游戏。**

美术依据：TeamHUD-FullRibbon-20261027/AvatarV2/avatar-size-review.png。采用放大的自定义队伍头像、整段曲带血槽、团队生命值和团队总分。分数第一视觉层级，生命值第二，头像与装饰辅助。此处“分数”暂沿用现有累计总分；新增得分采用短暂反馈，不新增永久信息栏。

## 1. 总体规则

1. 曲带外轮廓不随命中、受伤或回血摆动。血量变化只改变填充边界和区间颜色，不能把整套 UI 弯扭、拉长后反复回弹。
2. 普通反馈只动对应局部。分数反馈最强，HP 次之，头像框最轻；两队独立，不因更新两侧数据而一起跳。
3. 真值当帧提交。分数和 HP 数字直接显示最新真实值，不逐个虚构中间值，不让加分动画延迟实际结算。
4. 所有时间为首轮调参起点，单位秒；位移按 1920×1080 设计坐标。原已调好的损血 / 回血时长先保留，不批量重置。
5. 红蓝共用参数并镜像方向，文字正常阅读。自定义头像图片保留原色、原比例，使用容器裁切；不要求用户图片具备分帧表情。
6. 这套设计覆盖顶部团队 HUD 的全部相关状态。四轨判定灯、技能输入、Combo 撕碎与评价继续遵守此前已定方案，不因这次换顶部造型而另起一套。

## 2. 常态、入场与离场

| 状态 | 设计 |
|---|---|
| 常态 | 总分、HP、头像与血槽安静稳定。叶片不持续摇摆，数字不呼吸，血条不反复流光 |
| 初次入场 | 两队同时以 0.20s 渐显，整组从下方 6px 轻轻到位；无弹簧过冲。真实数值从第一帧就已设置，不从 0 假计数 |
| 从暂停恢复 | 恢复冻结时的显示，不重播入场、加分、回血或过热进入 |
| 切换 / 退出战斗 | 0.15–0.20s 整组渐隐，停止生成新瞬态；头像与数字同组退场，不各自飞散 |
| 重开 | 清理旧加分小字、黄 / 绿区间、闪光、过热和濒死残留，直接同步新局真值，再播一次正常入场 |

## 3. 分数：主要动效

### 3.1 一次真实加分

| 时间 | 表现 |
|---|---|
| t=0 | 累计总分立即换成真实目标值；只标记实际改变的数字位 |
| 0–0.04 | 改变位从 1.00 放大至约 1.075，并向上提 2px；未改变的数字保持不动 |
| 0.04–0.16 | 改变位平顺回到原大小 / 原位置，亮度恢复。总分保持奶油色，不整组闪成纯白 |
| 0–0.28 | 可用的小增量槽显示一枚“+100”之类的真实增量：上移约 5px 后淡出，字号约为主分数的 1/3，不压过总分 |

小增量槽只在安全区内、与总分和血槽均不重叠的空白位置出现；空间不足时不显示该小字，仍保留主数字反馈。红蓝槽位对称，文字不翻转。不能为了加分字强行挤动既定静态造型。

**读感：先注意到总分变了，再感到一次短促有力的“落点”。**

不做整套 HUD 放大，不做长时间滚分，不在同一位置叠出旧分数和新分数。普通命中不另点亮整段血槽，避免误读血量。

### 3.2 连续 / 多轨同时加分

- 主分数每次立刻同步，不合并或漏掉真实计分。
- 同一侧 0.08s 内的增量合并为一枚小增量反馈。每侧最多一枚可见小字，持续更新累计增量，不堆叠文字。
- 数字反馈从当前位移 / 缩放接续，不先强制弹回 1 再重新跳。缩放峰值仍限制在 1.075–1.08。
- 持续高频输入时每 0.08–0.12s 至多一次明显峰值；停止加分后 0.16s 内回稳。低于该间隔的事件仍更新数据。
- 增量小字可续时，但一次连续串的可见长度设上限；旧串结束后再接新串，防止永久悬挂。

### 3.3 位数增长与布局

- 分数靠 HP 的起点固定，红方向右、蓝方向左延伸。
- 使用稳定字形 advance 和预留字距，避免 1 / 8 宽度差导致整组左右晃动。
- 位数变化时只延展曲带中段与末端叶片，头像与 HP 位置不横移；布局在约 0.10s 内完成。
- 可读性高于缓动：若增长过程可能使卷钩 / 叶片穿过新数字，先立即扩容到安全边界，再对小装饰收尾，不强行慢拉伸。
- 变化位的回弹只发生在视觉子层，不参加布局宽度计算，否则布局会跟着跳。
- 新长度下 HP 真值比例保持不变，填充 / 绿区间 / 黄区间共享新的整段几何。不能因为分数使血槽延长，就伪造一次回血或扣血。
- 若达到中央安全间距上限，整组按已批准布局策略等比适配，禁止裁掉分数或与另一队交叉。

### 3.4 系统补分、重置与特殊来源

- 追分 / 保底的总分照常更新，可用很轻的变动位亮度过渡约 0.08s；不播主动得分的小增量、强回弹或成功星点。
- 技能等来源若真正派发了正向得分事件，仍按实际增量反馈，不由 UI 擅自标成 PERFECT。
- 同值刷新完全不播；减少 / 校正直接换数，或 0.08s 轻过渡，不误播正向加分。
- 重置为 0 是无动画同步，不当作负分打击。
- 过热倍率已包含在 ScoreManager 的实际增量内，UI 不二次相乘。

## 4. 整段血槽的统一规则

归一化进度 p = clamp(当前 HP / 当前 maxHP, 0, 1)。整段有效路径包括 HP 下方、分数下方与有效内侧末端；仅外侧头像框 / 身份月牙不计入血量。

建议用路径归一化长度 s 定义进度，所有层共享同一套 UV：
- 队伍色实血：[0, 当前显示进度]。
- 损血黄色区间：[较低的新目标 / 当前实血边界, 可见损血高水位]。
- 回血绿色区间：[当前实血追赶边界, 最新治疗目标]。
- 空槽：其余有效路径，保持低对比底色。

红方从外侧向内侧消耗，蓝方镜像。满血必须覆盖整段；零血不得残留亮色内侧卷钩。头像外圈可以保留队伍色，但不画一条永久发亮的完整血条副本。

### 4.1 受伤

保留已有“实条回落、黄色损血虚条、短闪、回弹、边界扰动”的反馈类别，调整它们的承载位置：

1. HP 数字当帧显示新值。
2. 约 0.06–0.09s 暖白短闪，只作用于血槽有效范围或新增损失区间，不能覆盖空血区、分数或自定义头像图片。
3. 队伍色实条从当前可见位置向新目标回落，使用已有减速曲线。代码字段初始值为 fillDuration=0.4s，实际场景 / 运行配置以当前值为准。
4. 黄色只保留本次损失区间；沿用当前 ghostHold / ghostDrainDuration（代码初始值 0.10 / 0.20s），最终追平消失。
5. HP 数字轻提 / 回落约 2px、0.14s；不放大整条占满分数下方的曲带。
6. 边界扰动限制在实际填充边界约 1–2px，外轮廓不动。不可照搬旧最大 10% 长度的摇晃到新长血条上。
7. 头像框短闪一次，可轻移 1–2px 后归位；图片本身不染红、不压扁。

重大伤害以“实际掉血 / 本侧最大 HP”归一化，在上限内增加闪光与局部位移，不能随绝对伤害无限放大。UI 不重复触发角色受击动画。

### 4.2 回血

1. HP 数字当帧增加。
2. 真正新增的区间先显示绿色虚血，队伍色实条随后追上；绿色区间逐渐缩短，最后完全消失。
3. 沿用现有 healingFillDuration，代码初始值 0.55s；满血溢出或实际没有增加时不播。
4. HP 数字可用 1.03 倍、0.16s 的小回弹；头像框可有一次约 0.14s 的浅绿边缘反馈。
5. 不把整段血槽刷绿、不把头像图片染绿、不点亮未获得的空槽。
6. 血量到满时只在实血边界到达末端后做一次很短的局部收束，约 0.10s；不整条持续发光。

### 4.3 高频、反向与不同上限

| 情况 | 接续规则 |
|---|---|
| 连续受伤 | 从当前可见进度接续，新黄色上界取当前可见高水位，不跳回过期 HP |
| 连续回血 | 扩展到最新目标，从当前显示进度继续追赶，不重走旧段 |
| 回血被伤害打断 | 立刻取消旧绿色，按最新真值计算受伤和黄色区间；旧回血结束回调不能恢复绿层 |
| 受伤后立即回血 | 取消旧黄色尾段，以最新真值与当前显示进度重建绿色；不让黄绿重叠成橙色 |
| 同一帧有伤害与治疗 | 数据照常逐笔结算；UI 保留合法的短受伤提示，最终区间层依当帧最终目标重建，不累积矛盾遮罩 |
| 最大 HP 变化 | 重新读取 maxHP 和实际 HP；单纯分母变化不当作治疗 / 损伤事件。是否需要专门增益表现由真实业务来源决定 |
| 分数长度使路径变长 | 保持 HP/maxHP 比例，只做几何映射，不播回血 / 受伤 |

## 5. 生命状态

### 5.1 濒危

首轮建议：HP 比例 <=25% 进入，恢复至 >=30% 退出，避免阈值附近来回闪。

- 保留红蓝血条原色，仅头像外框 / HP 数字旁的小身份弧作低强度提醒。
- 约 1.5s 一次轻明暗起伏，幅度控制在 15–20%；不缩放总分、不晃动整个 HUD。
- 受伤短闪时暂停这次起伏，短闪收尾后再接回。
- 阈值、周期、强度全部可调；在低血量快速持续受伤时也不能叠成常亮警报。

### 5.2 HP 归零 / 战败

- 真实 HP 立即为 0。血槽主填充、黄 / 绿瞬态在约 0.15–0.20s 内收清；业务战败事件不等待动画完成。
- 头像框与叶片约 0.22s 失去队伍色饱和度，图片不更换成固定失败表情。
- 停止濒危、过热和得分庆祝残留；累计总分保留可读，不因战败改成 0。
- 若有合法的败后复活，只有真实状态允许时才播放恢复；普通迟到回调不能把败方重新点亮。

### 5.3 胜利 / 结算

收到已确认的胜负结果后：
- 胜方总分一次克制回弹（约 1.06、0.22s），头像框一次柔亮收束；不循环庆祝。
- 败方按归零 / 战败收尾。
- 平局不伪造胜方，两队保持中性收束。
- 总分跳到结算统计的转场由结算界面控制；顶部 HUD 不自行重算胜负或创造结算奖励。

## 6. 过热与超级过热：顶部 HUD 联动

以 FeverManager 的实际状态为准，保持现有倍率与门槛；顶部 HUD 不根据总分 / 头像颜色推断状态。

| 状态 | 顶部表现 |
|---|---|
| 进入过热 | 头像外圈有一次 0.22s 轻亮；分数附近已有小笔触一次 0.16s 点亮。不能另外整组放大，抢掉同帧真实加分的主反馈 |
| 过热持续 | 外圈亮度比常态稍高；分数仍使用奶油色。每次真实加分沿用同一套变动位反馈，强度可以小幅提高并仍限幅 |
| 进入超级过热 | 0.30s 内两段有节奏的边框轻亮，强度只比普通过热高一档；不新增大光圈 / 新图标占据头像 |
| 超级过热持续 | 维持更清楚的外圈 / 小笔触，不给血量填充层强行加金色、改长度或常驻扫光 |
| 失败断过热 | 外圈和笔触约 0.18–0.24s 收暗回常态；不撕毁头像、不整条血槽变灰。已有实际受伤时，受伤反馈优先 |
| None -> None 的失败 | 不播放虚假的“退出过热”效果 |
| Fever -> SuperFever | 直接升级，不先播一次退出再进入 |

MISS / BREAK 共用失败功能。若存在 Combo，继续播放此前定稿的分层撕碎灰化（旧值>0 才播，约 0.30s）；这是 Combo 原位置的表现，不把撕碎移到顶部总分上。总分不会因为 MISS 自动清零。

## 7. 自定义头像

- 战斗静态显示头像内容，动效集中在裁切容器 / 外框；不依赖头像是橡果、叶子、人物照片或其他图片。
- 更换图片时仅在设置确认成功后约 0.12s 交叉淡化，保留同一裁切形状和放大后的可见面积；不伸缩框、不卡住战斗。
- 图片未加载好时显示默认占位，加载失败保留占位，不出现空洞、粉色块或错误的队伍图片。
- 当前尚没有正式队伍头像数据接口；后续需要独立的持久化头像数据与 Sprite 提交事件。设计不假设现在已有这条逻辑。
- 头像区是否可点击、是否打开设置尚未定义；本轮不擅自增加战斗中点击反馈或弹窗。

## 8. 同时发生时的优先级

不同数值模块可并行，不能把同一帧“加分+受伤”强行丢掉一项。

- 数值同步始终最高优先，不被任何动画锁住。
- HP 层：归零收尾 > 当前伤害 / 治疗转向 > 旧黄 / 绿尾段 > 常态。
- 头像外框：战败 > 受伤短闪 > 回血短亮 > Fever 进入 / 退出 > 濒危提醒 > 常态。
- 分数：无动画重置 / 结算锁 > 合法真实加分反馈 > 系统补分轻过渡 > 常态。Fever 同帧只调整既有得分包络，不叠第二次跳动。
- 任何新事件从当前可见状态接续；有版本号 / 取消标记，旧完成回调不得隐藏新数字、恢复旧头像框颜色或让旧绿色重新出现。
- 不通过播放动效触发判定灯、角色动画、技能释放或二次得分。

## 9. 源码适配事实与待补内容

本轮只读源码、编写设计，不修改下列代码。

| 当前入口 / 事实 | 设计适配 |

| HPBarLiquid 已有绿区间、黄区间、连续接续 | 复用结算与时间控制，统一替换为新的整段曲带几何 / UV |

| OnPlayerDefeated(side) | 归零终态与清理瞬态 |
| 当前加大头像 + 整段血槽只存在静态设计稿 | 正式头像组件、完整血槽遮罩、变动位动画尚需制作，不能把现有 V9 工程外观当成此方案已经实现 |

## 10. 素材、层级和实现边界

### 素材

- 正式整段曲带遮罩 / 空槽 / 身份月牙，红蓝同源镜像，路径进度覆盖至内侧有效端点。
- 大头像裁切形状、可换图片、独立边框。用默认图作异常兜底。
- 现有手绘 0–9 与 HP 字样优先复用；无需固定写死 5842 / 326。
- 极少量独立叶片 / 小笔触，必要的柔边亮纹；不需要给每个数字生成动画帧，也不需要给每张自定义头像生成受伤 / 回血表情。
- 增量数字可复用同一字库，另补“+”符号。
- 黄色和绿色复用同一遮罩区间着色，不各画一套形状。

### 层级

LayoutRoot（只负责安全区与稳定排版）
- Avatar：ClippedImage / FrameBase / FrameFX。
- Health：同一曲带几何的 Empty / Main / DamageInterval / HealInterval / Flash；所有图层顶点与路径 UV 同步。
- LifeNumber：静态定位根 + 数字反馈子层。
- Score：稳定字位根 + 变动位反馈子层 + 至多一枚小增量反馈。
- ExistingAccents：独立可取消的极轻反馈，不控制真实数据。

动画系统不得直接改布局根的宽高 / 坐标来制作弹动；只允许专门的布局长度变化更新几何。主数字、HP 和可换头像都应有明确的静态姿态，停止动画时准确归位。

### 计时与性能

- 战斗反馈统一随游戏时间走，暂停冻结。独立头像设置换图若发生在设置界面，可使用该界面的 UI 时间；不混用战斗计时。
- Disable / 场景卸载 / 重开时退订事件、取消旧任务、清瞬态。
- 常用数字、增量和亮纹采用预分配 / 池；不每次命中新建材质、PNG 或对象。
- 路径长度只在布局确实改变时更新；每次扣血只改进度区间，不重新采样整条路径。
- 不用全屏 Bloom 把图案打亮，不改游戏已有中央能量槽与溶解。
- 旧 UI 隐藏保留，提供外观回退；新的动效配置独立保存，不覆盖用户已有判定参数。

## 11. 建议实施 / 审查顺序

1. 正式头像与完整血槽的静态接入：审查两侧、不同总分位数及满 / 半 / 残血，确认不复用旧短胶囊。
2. 分数变动位 + 高频合并 + 系统补分区分：先检查最重要的信息。
3. 伤害与绿色回血：检查连续事件、方向反转与实际零增量。
4. 头像框联动、濒危 / 归零：不依赖具体头像内容。
5. Fever / SuperFever 进入退出、Combo 原定撕碎与结算收束。
6. 用户逐步实机审查后再定稿时长、强度与素材清理。
