# 战斗画面与 UI 落地方案 V5 · 待确认版

日期：2026-10-23。依据：历次用户修正、已选美术母版、当前工程源文件与场景序列化配置。

本文件是实施规格，不代表功能已经完成。本轮只做静态读取与方案编写，没有运行 Unity 测试、修改场景或替换运行时代码。运行效果、Shader 兼容性及性能仍须在实施阶段按第十节核对。

## 1. 设计依据与范围

### 1.1 唯一依据顺序

1. 用户最新的明确要求优先：四条音轨；回血绿色虚血；红蓝命中同形；平面简约判定带；直线辅助边光向内柔和渐隐。
2. HUD 造型母版：`battle-ui-option-c-rhythm.png`。珊瑚红 / 柔蓝曲线、奶油手绘字、叶片、Combo 花草底座、开口箭头环。
3. 整体布局参考：`battle-final-four-lanes-healing-v4.png`。它用于说明组合关系，不用于复制角色、地面或光线坐标。
4. 过热美术参考：`fever-animated-backdrop-v2.png`，以及用户提供的暖色植物布景两状态图。
5. 早期歪曲判定带、塑料包边、实体灯、简化网页 UI 样本全部不再作为制作依据。早期文档与本文冲突的内容由本文覆盖。

**概念图偏差必须纠正：**整局 V4 中部分边光过长、过硬，局部分段也不够准确。实际几何由四轨数据生成，光的形状按本文件第 4 节制作。完整 UI 母版优先于生成整局图里被简化的局部。

### 1.2 确定保留

- 原地面贴图、植物 / 石头 / 树桩等场景件的素材、布局、尺寸；角色素材、位置及已有玩法动作；音符形态与运行路径；判定位置、判定时间窗口。
- 中央能量分界、已确认的溶解效果及其玩法驱动。本轮判定带升级不改中央分界。
- 能量槽的原资源、锚点、双段结构、满能闪烁、释放与冷却表现。
- 扣血已有的主填充下降、黄色损失残影、闪白、回弹与液面晃动，重新协调节奏。
- HP / 分数 / Combo / 技能 / 过热的计算来源。除明确确认的规则修正，不改得分、伤害、治疗量、技能成本或过热阈值。

### 1.3 本轮制作内容

HUD 美术资源与动效、统一判定带与四轨辅助线、过热 / 超级过热循环布景、背景补充与克制的场内光影。拟定默认不追加体积雾，也不自动恢复全局雾；这一范围在第十一节确认。

整体风格：保留原手绘地面，以背景层次、局部暖光、弱接触阴影和统一色彩增强精致度。HUD 保持通透；不将画面重新绘制为另一套场景。

| 过热布景 | Fever 主插画、Super 增量插画、分离的可摆动枝叶 / 发光花朵 | 每侧独立显示与循环，不使用烟雾片代替 |

### 3.2 资源规格

- 原画按 1920×1080 基准界面的约 2 倍显示尺寸输出，再依据实际最大占屏大小定稿；背景优先 2K 宽分层资源。不能仅放大已有小图后声称高清。
- 透明 PNG、干净 Alpha、统一命名与 Pivot；UI 字形保持白 / 奶油基础色，可按队伍染色。不要把背景暗色或阴影烘焙进透明边缘。
- HUD 初期使用 RGBA32、Bilinear、Clamp、无 Mipmap；图集保留透明扩边，防止浅色字边出现黑缝。正式压缩依据目标平台实机表现再定，不在本轮猜测。
- 世界布景的 Mipmap / 压缩设置与 HUD 分开，按透视缩放观察锯齿及边缘污染。
- 平面美术不使用金属高光、厚黑描边、塑料倒角。判定线几何保持笔直；手绘的粗细变化放在 HUD 装饰上。
- 新素材进入独立目录并以新 Prefab / 表现配置引用，保存原资源及其 GUID；不覆盖用户原场景贴图。

**制作顺序：**母版造型复刻 → 独立透明资源齐全 → 用这些正式资源做 Unity 静态组装 → 接入动效。完整场景生成图不能直接当遮罩覆盖在游戏上；另一套临时字体或 HTML 圆环不能充当最终美术。

## 4. 判定线、灯与四轨辅助线

### 4.1 几何结构

- 整场四条横向音轨，两方各四个响应段；上下外边界加三条内边界，共五个边界层级。两侧是同四轨的两端。
- 当前轨道中心偏移公式为 `(i - 1.5) × laneSpacing`；相邻中心中点为内边界，首尾各外延半个间距。当前 1.7 间距对应中心偏移 -2.55、-0.85、0.85、2.55，边界偏移 -3.4、-1.7、0、1.7、3.4；均叠加实际 hitPoint 坐标，不作为未来硬编码。
- 延伸方向沿音符行进平面的场内方向，长度由本方判定线至实时中央边界的距离限制。根据相机投影确定屏幕中的上 / 下顺序。
- 每侧一套可管理四段与五边界的视觉组件。LaneIndicator 只接收 Hold / Hit / Sleep 状态，不再独立生成一层常态底线。
- 两个相邻命中段共享的边界取更强包络，不相加；基础线与发光层使用同一边界坐标，避免错位和重复叠亮。

### 4.2 状态表现（拟定制作起点）

| 状态 | 判定带 | 场内表现 | 结束方式 |
|---|---|---|---|
| 常态 | 直、等宽、扁平的本方色带，3 处细微分段 | 五个层级的细低透明辅助线向内渐隐；轨道中央不画线 | 持续 |
| 按下 / 持续按住 | 对应整段柔白亮起，无实体灯 | 一层较宽但很淡的前向光晕，按住稳定，不呼吸闪烁 | 松开约 .10 秒收尾 |
| 非 MISS / BREAK 成功判定 | 同一段近白亮芯 + 本方色柔光，比按下明显更亮 | 该轨道上、下两条直线边缘同步增强；由近白到队伍色，再到低透明紫调尾光 | 峰值约 .04 秒，约 .28 秒内衰减；按住则回到按下态 |
| MISS / BREAK | 不触发成功边光 | 失败由评价表达，普通按键白光按输入状态收尾 | 按已确认失败规则处理 |
| 沉睡 / 禁用 / 场景退出 | 停止当前按下和命中包络 | 清空残留光效；常态结构的隐藏规则沿用角色状态要求 | 恢复时从干净状态进入 |

成功等级包括现有 PERFECT / GOOD / CLEAR / PASS / YES；同一判定事件只触发一次。同一音轨快速连续命中刷新包络并限制峰值，不不断累加亮度或拉大尺寸。

### 4.3 柔光如何实现

- **红蓝使用同一材质逻辑、网格、包络、宽度和距离曲线，只换颜色与镜像方向。**
- 常态目标视觉宽度约为 1080p 下 6–8 px，最终由实际透视投影定世界宽度，不逐帧扭曲轨道以强行等像素。
- 辅助线初始透明度约 .10–.16。最外边界也保持轻，不能围出硬矩形棋盘。
- 命中边光包含细亮芯与宽软光两层。软光近端横向扩散的起点约 16–28 px；这只是调参范围，不是已验收结果。
- 前向作用距离先取本方到中央距离的约 45%；尾段至少占光线长度的 25%，最终 Alpha 连续降到 0。常态辅助线可稍长，仍在中央前完全消失。
- 用片元距离场 / 连续渐变控制纵向衰减与横向羽化；网格中心线始终为直线。宽度收窄、颜色变化与透明度变化共同形成柔和收尾，不靠少量粗网格顶点或全屏 Bloom 糊边。
- 红：近白桃色 → 珊瑚 / 玫红 → 淡紫透明。蓝：冰白 → 青蓝 → 淡蓝紫透明。调整颜色的亮度以使两队感知亮度接近。
- 亮芯只占小面积。不能把整条光做成纯白硬边，也不能新增音轨中轴光条。中央能量墙不因轨道命中而被额外点亮。

## 5. HUD 状态与动效规格

所有时间为拟定的初始制作值；结构与事件规则固定，时长和幅度集中到独立配置中，方便比较调整。暂停时跟随现有战斗暂停机制，不自行推进战斗视觉。

### 5.1 HP：保留扣血，新增绿色回复虚血

宽色带是实际计量区域；弯曲细尾是装饰。量值进度沿固定方向映射到宽色带蒙版，左方左→右填充、右方右→左填充。细尾长度与分数位置不随 HP 变化。

**扣血：**真实数字立即更新；保留 .8 秒主填充、.25 秒黄段停留 + .7 秒回落、.5 秒闪白、.3 秒回弹、.55 秒液面晃动。优化为前 .06–.09 秒集中闪白，后段快速变柔；主体回弹上限建议从当前 1.2 调到 1.12，保留按伤害比例驱动的小伤反馈。花叶约延后 .04 秒轻摆，不整组频繁放大。黄色只表达损失区间。

**回血：**逻辑 HP 和数字立即到真实新值；绿色填充只表达新增区间。红 / 蓝主色以当前显示进度追上，覆盖的绿段消失；初始沿用 .8 秒追赶时长。绿色不是护盾，也不触发受击闪白或回弹。

| 事件组合 | 明确处理 |
|---|---|
| 连续治疗 | 合并绿色区间到最新目标，主填充从当前显示值继续；不排队、不回跳到上一次目标 |
| 治疗中受伤 | 立即撤销旧治疗绿色状态，建立新的黄色损失区间；数值以最新真实 HP 为准 |
| 受伤中治疗 | 取消过时黄色状态，以伤后真实 HP 到新 HP 定义新增绿色区间；主填充若还高于伤后真实值，先收敛到该上限，再开始回复，避免把受伤拖尾误当新增血量 |
| 反向打断后的填充 | 用当前显示值作为起点并限制在新状态合法范围；不能使用旧逻辑中的无条件 Max(current, oldTarget) 制造回血跳跃。超出合法范围时优先纠正血量表达 |
| 满血 / 实际增量为零 | 不出现绿段；超量治疗按真实最大 HP 截断 |
| 初始化 / 重开 / 最大 HP 重设 | 无动画同步，清空旧闪白、虚血、缩放，避免开局假扣血或假回血 |

材质将主体蒙版与归一化进度分开，提供区间裁切；绿 / 黄不能通过一张满长 Image 简单染色实现。HP 数字取真实值，动画只影响显示填充。

### 5.2 分数

- 保留母版奶油手绘数字及两侧叶片。使用 0–9 图集与统一排版，支持位数增减，不能固定四位或截取 5842。
- 同值 SetScore 立即返回；只变化数位参与约 .14 秒的旧字淡出 / 新字提落，移动约字高 4%，峰值缩放不超过 1.04。
- 新目标立即写入数据；不滚动经过不存在的中间分数。快速得分合并到最新值，不排队追数。
- 叶尖约延后 .04 秒、.20 秒内归位；只有实际正常得分触发庆祝。保底补分只更新数值，不冒充一次命中。
- 不能直接把 OnScoreGained 当总分：该事件还有中央推进等用途，保留其语义；UI 以总值变化为数据入口，以原因标记控制庆祝。

### 5.3 Combo

- 保留真实 Combo 数字及当前动态锚点；位置更新由父节点承担，动作放在子节点，避免彼此覆盖。
- +1：数字约 .035 秒压至 .97，.07 秒回至 1.07，再 .10 秒回稳；侧弧略向外展开，叶梢跟随一次，底座固定。
- 被技能削减：数字立即变更，短弧收拢、轻微暖色提示后回本方色；不播放成功弹跳。
- 清零：逻辑立即为 0，旧数字约 .16 秒收起，花草底座约 .20 秒淡出；零时不残留“0”或固定花坛。新命中可从当前透明度中断退场，避免闪断。
- 高频输入只刷新一个动画包络。首版不增加每十连击庆典、额外奖励文案或新的声音。
- BREAK 是否加 / 保留 / 清零由第十一节确认；界面 Combo 与 Fever 独立计数的现有设计不会被 UI 自行合并。

### 5.4 评价

- 母版配套奶油手绘字 + 队伍色细短划线，避免大面板与粗黑外框。
- PERFECT：约 .06 秒到峰值，短暂停留，约 .55 秒退完；峰值 1.06。GOOD / CLEAR / PASS / YES：约 .40–.45 秒、峰值 1.03–1.04。MISS / BREAK：约 .45 秒轻收束，不发成功光。
- 普通手动判定从真实判定点投影；技能清屏从节点位置投影，保留一节点一评价语义。文字偏移约 12–20 px，缓慢上移约 12–18 px，不能压住音符主要读谱区域。
- 同轨快速评价使用有限对象池与短队列：只限制可见旧条目的尾迹，不能吞掉计分事件或跨轨合并。不根据同一个 HoldNote 对象就判为重复。
- 初始化必须先配置文字、色彩、尺寸再启动动画，避免 Awake 捕获默认色后把配置色覆盖。
- BREAK 文案先保留原 MISS，除非用户另外指定。YES 必须有正式字形，不能落回默认字体。

### 5.5 技能输入

| 逻辑阶段 | 视觉 |
|---|---|
| 待机 | 右侧竖排的三个开口环、奶油箭头、低亮连接曲线；按本地玩家阵营着色 |
| 物理按下 | 仅所按箭头 / 环轻压 .95，约 .14 秒回位；点击热区不缩放 |
| Accepted 有效前缀 | 当前环小段亮起，保留已有角色 SkillSelect；不误播释放 |
| Triggered 完整匹配并开始施法 | 连接曲线亮一次，三环轻舒展，约 .40 秒退完；角色原技能动作继续 |
| Rejected | 三环短暂收束，约 .18 秒暖色提示；红方同时用形变和亮度区分错误 |
| 超过现有 inputInterval | 轨迹约 .16 秒清空；主动执行与原有下一次输入时清空一致的超时规则 |

键盘 / 触摸 / 鼠标共用同一逻辑结果。只给本地 side 显示按钮反馈；AI 输入不能闪玩家按钮。保持输入提交时机，新增 PointerDown 只用于触感，不多调用一次 FeedInput。不能为多个不同长度技能硬画三步进度或一个共享冷却圈。首版不新增持续“技能可用”闪烁。

## 6. 过热布景

### 6.1 造型和构图

- 保留选定的暖色植物插画方向：弧形枝条、层叠植被、少量发光花朵，丰富但不过暗。
- 它是完整绘画布景的分层动画，背景实体轮廓可辨；不是灰黑半透明烟片、满屏红蓝染色或幕布边缘。
- 布景位于场地后方。画面主要占后方森林区域，不覆盖原地面、角色、音符、HUD；普通与超级状态的轮廓和高度必须能区别。
- 红蓝两方保留同一插画色彩体系，可用少量局部阵营点色；不把蓝方整幅暖色插画强制染成蓝紫。

### 6.2 状态表

| 状态 | 基础背景 | Fever 层 | Super 层 |
|---|---|---|---|
| None | 常驻 | 隐藏并停止本层更新 | 隐藏并停止本层更新 |
| Fever | 常驻 | 升起并循环 | 隐藏 |
| SuperFever | 常驻 | 保留并循环 | 前方第二层升起并循环 |
| 返回 Fever | 常驻 | 保留 | 降下后禁用 |
| 返回 None | 常驻 | 降下后禁用 | 降下后禁用 |

每方只响应自己的 FeverManager.OnStateChanged，阈值由真实配置决定，不由画面 Combo 推断。当前配置 20 / 50 保持。

### 6.3 可行的动画方法

- 首版采用分层 Sprite / 简单网格的循环动画：主插画稳定、枝叶以各自根部缓慢摆动、发光花朵亮度变化、少量点光沿固定路径漂移。
- 循环约 4–6 秒，起止姿态及速度连续；整体背景不周期性缩放或上下漂移。它看起来是动态广告牌内容在动，升起只是入场动作。
- 初始升起 .5 秒、降下 .45 秒沿用现有时间作为起点。反复升降从当前位姿接续，不瞬移到隐藏坐标重播；直接进入 Super 时同时正确恢复两层。
- 透明前缘的遮挡使用适配当前相机的隐藏区 / 裁切配合场地遮挡；不能只把大图片放到地下就假设已隐藏。
- Awake 即建立隐藏状态，等配置和素材就绪后同步真实 FeverState。编辑态也默认 None；预览仅改专用预览状态，关闭预览后回到正常状态。
- 静态相机按其方向建立布景平面；若相机运行时旋转，再更新朝向，保持地面锚点不滑动。贴图方向单独核对，不仅机械复制 rotation。
- 显式保存材质与贴图引用，使用适配当前 URP 的透明 Unlit 路径。Missing / unsupported 必须有可定位报错；不能静默生成一块替代色板。
- 替换现有 bottom-30% 裁切、整幅染色、BuildBackdrop 色块、重复旧 Banner 入口。保留溶解模块及中央分界。

## 7. 背景、场内光影与卡通化

### 7.1 具体做法

1. 保持原相机 / 原地面 / 原件。新增常态后景衔接现有前景树木，并与过热层使用同一画风。
2. 地面使用独立的低透明冷暖色光遮罩，表现少量暖光落点和较凉的阴影区；不将原纹理替换成生成图。
3. 对确实需要接地的场景件增加与地面贴合的柔和接触阴影贴片；阴影层随其所属场景组管理。已有有效阴影的对象不重复叠加。
4. 林地后景保留一定明度和颜色分离，边缘适度收暗，不压成黑幕。
5. 卡通化先使用克制的色彩曲线 / 色彩统一和局部阴影形状；HUD 维持独立配色。原角色不增加厚描边或强色阶断层。

### 7.2 工程约束

- 先分类现有地面 / Sprite / Spine 是 Lit 还是 Unlit，再决定局部灯是否有作用。Unlit 不响应灯光时用受控光影贴层，不靠不停加大灯强度。
- 现有 SSAO 对哪些对象生效需按实际材质和深度路径判断；不能承诺开 AO 就让全部透明卡片接地。
- 不默认追加全屏卡通后处理。若后续局部方案仍不足，再单独比较可排除 HUD 的轻量色彩处理。
- 能量墙自身已有高亮，因此不为增强新判定光而全面增加 Bloom，避免中心进一步过曝。
- 雾的范围待确认。若最终保留少量局部雾，必须成为独立开关和后续单项验收，不能与本轮自然背景一起默认启用。

## 9. 实施顺序与交付边界

### 阶段 A：固定资源和基线

保存当前场景、配置及相关资源的可恢复副本，不混入历史未提交修改。制作正式透明素材、字形图集与分层布景。交付资源目录、素材清单、静态 UI 组装和四轨几何示意。尚未达到母版造型时，不用临时资源推进整局动效来掩盖偏差。

### 阶段 B：判定 UI

先完成四轨同源几何、常态辅助线、按下与红蓝同形命中。接入原判定事件。交付可在专用预览场景切换 Idle / Press / Hit / Sleep 的真实 Unity 版本。

### 阶段 C：HUD

按 HP → Score → Combo / 评价 → 技能输入顺序替换。每项独立配置和禁用开关，确认事件只作用正确一侧。BREAK 未确认前不改它的玩法结果。

### 阶段 D：背景与过热

先查明粉色材质问题，接入正常 / Fever / Super 的真实资源和循环，再添加自然场内光影。雾入口按最后确认范围处理。

### 阶段 E：整局合成与回归检查

使用原场景、原摄像机完成 1080p 实际录屏和前后比较；补查当前窗口缩放及宽高比适配。目标平台暂以当前 Windows 工程为基准，移动端性能与触控设备兼容不在没有设备信息时承诺。

每阶段交付真实资源、Prefab / 配置、修改文件清单、已完成和未完成项。实现前与实现后分别记录差异；不自动提交 / 推送 Git，也不将当前历史修改清空。后续检查是本方案拟定的工作，目前未执行。

| 检查场景 | 必须达到 |
|---|---|
| 编辑态与开局首帧 | 无粉色布景、场外叠幕、残留雾片；Fever 层默认隐藏；原物件位置与原贴图引用保留 |

## 11. 需要用户确认的三项

### A. 主方案

### B. BREAK 的 Combo 规则

当前代码：画面 Combo +1；过热计数清零；评价显示 MISS。这三个分支冲突，不能当作已确认设计。

建议：BREAK 不增加也不清零画面 Combo，保持已有“中途断连不清零”注释表达的意图；过热沿用现在的退出规则；评价显示 MISS；不触发成功光。另可选择“Combo 也清零”或“完全保留当前 +1”。必须由用户选择，不能由美术迭代擅自决定。
