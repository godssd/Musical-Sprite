# 技能输入落地与合并测试清单

本轮完成于2026-11-03；目录沿用本批启动时的20261102命名。

## 已落地

- 上：勇气（火苗）；中：守护（盾牌）；下：坚韧（破石嫩芽）。内置imagegen按已选手绘风格生成，原图source-icons.png及提示词imagegen-prompt.json保留。正式Sprite按统一256×256透明留白规范化，清理孤立Alpha杂点。
- 圆框复用现有HUD开口环；轻连接曲线统一整体。旧箭头/方块表现作为资源失效或配置回退路径保留。
- 有效前缀：只播放按下反馈，并沿用每个符合角色的SkillSelect动画。多个角色可同时响应同一前缀。
- 无任何可响应角色符合：清空缓冲，整组收灰、轻收束，默认0.28秒重置期；此期间所有入口返回Locked，不追加缓冲、不刷新锁、不重复反馈。
- 完整匹配：仍沿用原先第一个完整匹配运行时的选择规则；调用既有BeginCast。仅技能实际进入释放阶段才播放整组舒展/连接线提亮，默认0.38秒期间输入锁定。角色原SkillStart/SkillLoop/后续技能动作及能量槽不重做。
- 若角色动画优先级等原因导致BeginCast撤回到Standby，保留有效按下表现，清空这次序列，不虚报释放成功，也不将有效匹配误当无人响应失败。
- 超时只把下一步作为新起点，不额外制造错误闪光。A/B/C枚举数据兼容映射到三个语义命令，原技能序列内容与释放计算不改。
- 键盘、触屏按钮、AI均通过同一个FeedInput门禁。AI链式释放会等上一段UI锁结束，并重新检查目标技能阶段；重开会停止旧AI输入协程，防止旧序列接着运行。
- 触屏/鼠标在按下时输入；图标缩放只发生在子节点，热区固定。由技能按钮接管的整段指针手势不会误击下方音轨，拖出也保持接管直到松开。应用失焦清理手势。
- 死亡后禁止新技能输入；重开清空双方缓冲与锁。按键绑定保留。

## 改键

默认物理按键仍为←/↓/→，显示始终为语义图标，不随改键变成键盘符号。

SkillInputUI公开GetBinding、SetBinding、SetBindings、ResetBindings接口；可一次交换多个键位。保存使用PlayerPrefs，仅显式保存时写入。拒绝重复技能键、与红方打击音轨相同的键、None、鼠标与摇杆按钮。

Unity菜单：Tools → Musical-Sprite → V11 → 10 Skill Commands。

Play中可直接发送三种指令、查看缓冲与锁定状态、读取当前键位、保存改键或恢复默认。这个面板走真实输入，会实际释放符合的技能。此轮提供了可持久化改键接口和开发测试面板，尚未另做游戏内正式设置页面。

## 自动验证范围

- 核心：超时、重置/释放锁、锁内输入不改变状态、双方隔离、别名、原子改键交换与无效/重复键拒绝；测试不写PlayerPrefs。
- 真实场景：前缀同时匹配多个可用运行时；完整序列进入实际ActiveSkillRuntime；对应槽能量仅消费一次；两种锁忽略后续输入；超时新起点；键位冲突；UI射线命中；子节点缩放不改变热区；手势拖出仍接管；重置清空状态。
- 场景验证使用无模型的独立技能拥有者夹具，未修改玩家或敌方真实战斗数据。它验证实际输入与技能运行时代码，不代表所有角色Spine技能动画已逐个验收。
- Desktop Unity原生GameView录帧，非手机触屏硬件实测。真实设备仍需检查。
- 死亡、HP结算、血条与重开原有Play smoke通过。

## 晚些时候合并测试建议

1. 先看血条、真实HP刻度与阵营光、Combo、评价是否符合你想要的强度和排版。
2. 找能量已满的角色，按其原技能指令：每个有效前缀应有角色响应和按下反馈；可能有多个角色同时响应。
3. 输入无人符合的指令，重置期间连续按键/触屏不应进入下一条缓冲。
4. 完整释放后，整组反馈期间快速点击不应再次触发；结束后能继续输入其他可用技能。
5. 对照真实角色SkillStart、技能循环与结束动画；本轮沿用这些已有动作。
6. 保存一组与音轨不同的技能键位，重新进Play确认仍有效；图标应保持勇气/守护/坚韧。
7. 手机上点技能按钮、拖出再松开，检查没有误击音轨；多指点音轨与技能时也检查。
8. 在错误重置或释放反馈期间重开，不能残留旧缓冲、锁定、颜色或旧AI输入。
