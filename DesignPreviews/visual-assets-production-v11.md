## 2. 制作顺序与依赖

1. 锁定现有相机截图、角色 / 场景件 / 地面保护层、四轨锚点。背景绘制只针对后景可替换区域。
2. 先完成数字 1、5、8、0 的字形小样、HP 主体遮罩、三图案草稿、单侧 Fever 主画及少量可动层。
3. 制作四个工程小样：任意数字撕碎、一条曲带治疗、一轨软光、一侧双层布景。以实际相机 / Canvas 查看缩小后的效果。
4. 通过后补齐 0–9、其余 HUD / 评价、左右背景与完整循环。已批准造型保持一致；小样只校准制作方式和幅度。
5. 所有素材交付独立源层、导出图、Pivot / 字距 / 遮罩配置及对应 Prefab，不交一张只能观看的拼图。

## 3. 各类素材的制作难点

### 3.1 手绘字库和真正的撕碎

- 生成图中的两个 5 可能并不完全同形；生产字库必须确定唯一 5，重复数字都读同一源图。
- 除纹理外要记录字符裁切框、advance、baseline 和可见笔画范围。透明留白不能造成 1 与 8 的排版跳动。
- 撕碎模板位于整个数字组坐标。先建立穿过字身的主断口，再按中心到外缘逐步加密，不能只有外围剥落。
- 中心大块、中间块、外侧小块都必须来自原笔画面积。纹理 alpha 切掉空白，碎片位移后不能出现矩形卡片。
- 不按每一帧生成新的裂口。模板、父子分片、灰化和淡出共用一条确定时间轴；两阵营仅替换原色。
- 用网格相交和稳定 UV 避免实时截屏。若制作工具导出预切多边形，必须同时保留对应 UV / 索引；单独一张碎屑图无法适配任意分数。
- 大数字组和单个 1 都需检查，不能只看放大 55。断口细边保持哑光，不用发光白描边。

### 3.2 曲带血量与虚血

- 概念图里的曲带包含装饰尾，不能直接整图横向缩放或 Filled Image 裁断。主体和装饰分离后，血量区间才可连续推进。
- 遮罩要覆盖完整可填主体；绿色区间与红 / 蓝实条必须沿同一个 alpha 形状接合，不能浮在条外。
- 黄虚血、绿虚血共用区间逻辑，不各做固定颜色的整条贴图。填充亮度和纸感由可调着色与亮度纹理承载。
- 曲带的尖细末端需要在少血时仍可识别。参考 0%、1%、10%、50%、100% 的可见面积，防止“数值还有血但条已看不见”。
- 若横向区间在选定轮廓中造成明显不均匀读数，优先调整主体有效宽度 / 使用单调进度映射，保留固定细尾；不擅自把手绘造型改为矩形管。

### 3.3 过热插画循环

- 四张现有 PNG 的内容和哈希相同，只有底部旧场景件。需要新画主构图，不能靠裁切或染色得到选定暖色背景。
- 主干、摆动枝叶、花灯、花灯光遮罩分层；枝叶根部多留重叠，移动露出的背景需补画，避免洞、重影或纸片脱节。
- 不对整幅画做大幅 UV 扭曲。枝叶只在小范围网格 / 根部摆动，主轮廓保持稳定；带直线建筑的区域尤其不能被扭弯。
- 同一循环要首尾姿态和速度连续；不同小层错相位，避免全部同拍呼吸。可动组数量保持少量。
- 原截图中的地平线、树丛和场地上缘必须套位。背景下缘可隐藏，过热升起时绘画内容真正增加，不能一开局就在场外堆着。
- 透明花光不能使用原场景件的白色亮度键裁切。专用材质需正确显示半透明、支持整体淡出，避免深度遮挡错误。
- 正常与超级背景共存时分别检视组合轮廓。单张好看不代表叠起来不挡画面。

### 3.4 场内光影与配色

- 源贴图本身的笔触和色块保留；新光影只提供层次。不要把原地面重新画成另一套更精细的纹理，导致场景件风格断层。
- 先核对原件材质是否接收灯光。仅对实际有用的路径调灯，假光照材质使用同一世界空间遮罩协调色光。
- 阴影有明确归属和落点，已有接触影的对象不重复压黑。背景插画光源与场内暖光方向一致。
- 卡通统一不靠强全屏色阶。小样先看物件、角色、音符、中央墙同时存在时的辨识度，再调局部明暗范围。

## 4. 导出与 Unity 导入规范

| 类型 | 颜色 / Alpha | 导入与坐标 |
|---|---|---|
| 手绘 UI / 字形 | sRGB；RGBA，保留细软边与纸感 | Sprite，UI 不开 mip；首版禁图集旋转和 tight packing；统一 Pivot / baseline |
| 主体 mask / 光影数据 | 纯数据按 Linear；只消费需要的通道 | Clamp；不让有损压缩破坏细边；本地 0–1 与 atlas UV 分开 |
| 世界插画 | sRGB；前缘透明、遮挡底画完整 | Sprite 或明确 UV 的 Mesh；Pivot 靠底部根点；mip 按实际缩小闪烁决定 |
| 发光遮罩 | 通道和材质约定一致 | 单独于主画；亮度在 Shader 配置，不烘成白色满屏亮片 |

透明颜色采用与 Blend 配套的 Straight Alpha 或明确的预乘流程；每套材质只选一种并记录。半透明边缘的 RGB 做颜色外扩，图集保留足够 gutter，不能把透明边填黑再指望 Bloom 修补。初始 padding 4–8 px，是否足够要结合最大缩小和 mip 情况检查。

生产图不包含标题、时间标签、箭头、深色展示底板、水印或截图裁切框。图稿字样由专门资源重建，不能从低分辨率概念图抠出带底的文字。

运行时不打开无必要的 Read/Write，不使用每帧动态 Sprite.Create。材质和配置显式序列化引用；保留 .meta 的 GUID，不移动重命名已绑定旧资源来冒充替换。

## 5. 建议目录与交付格式

实施时使用独立目录，命名可按项目既有规范调整：

```text
Assets/Art/BattleVisualV11/UI/       数字、字样、HP、装饰、技能图案
Assets/Art/BattleVisualV11/Backdrop/Normal/
Assets/Art/BattleVisualV11/Backdrop/Fever/
Assets/Art/BattleVisualV11/Backdrop/Super/
Assets/Art/BattleVisualV11/Lighting/
Assets/Materials/BattleVisualV11/   独立材质，不覆盖原共享材质
Assets/Prefabs/BattleVisualV11/     HUD、轨道、布景
Assets/Data/BattleVisualV11/        字形、颜色、动效、分层引用配置
DesignPreviews/                    美术依据、方案、对照与制作记录
```

源层文件保存为工具可编辑格式；同时导出各层透明 PNG 及清单。字库另附字距 / baseline；背景另附图层顺序、Pivot、可动根点、循环周期；UI 另附静态基准、热区与非交互装饰层说明。脚本与 Shader 属于实现资源，在对应模块目录管理，不混入纯美术图集。

## 6. 资源完成条件

- **造型**：与批准母版对照，Combo 简化装饰和 V10 撕碎层次一致；图案具体画稿在全量制作前定稿。
- **独立可用**：导出资源透明干净，不带展示背景；字形 / mask / 背景活动层齐全，无“只交整图”的缺项。
- **缩小可读**：实际 1080p、窗口缩放及安全区下仍清楚；数字、图案和四轨不过细或挤在一起。
- **运行成立**：曲带区间、软光、真实任意数字碎片、双层循环各有实际小样；不以生成概念图代替。
- **资源可追踪**：每项记录母版、最终路径、引用 Prefab / 配置、导入设置与完成状态。尚未制作 / 尚未验证明确保留状态，不报完成。
- **交付记录**：实现阶段输出常态与关键状态的实际截图 / 录屏，连同修改文件表和参数表。当前文档只规定交付要求，没有执行这些检查。
