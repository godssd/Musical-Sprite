# 本轮迭代 V5（2026-10-30）

## 已落地

- 角色卡住：Shit 的资源没有超级过热循环/目标动作，旧代码会停在完成的一次性动作上。该角色现在按实际资源名称映射，超级过热复用现有过热动作，Hit、Dizziness、Victory 的名称也已校正。没有制作新的 Spine 动作。
- 虚血：事件闪光、初始停留和刻度移动采用独立计时。连续事件不会无限重启停留；反向事件不再瞬移刻度，在新闪光期间平滑衔接上次实际血量后追赶新目标。黄色与绿色保留实色，刻度移动时发光溢出。
- HUD：保留原曲带和字形素材，修正数字显示宽高比，分数稍增高并随曲带局部高度排列；HP 标签和数字同步调整。外侧叶片收拢，月牙接口向血带靠近，内侧叶片恢复比例并贴近末端，装饰点随曲带高度排列。六位数固定血槽长度不变。
- 光感：事件闪光接近白色并保留队伍暖/冷色倾向；减少刻度抢白光。光晕由均匀圆盘改为高斯加权采样，减轻重复轮廓。
- Combo：保留位置、字形、逐数字撕裂路径、0.30 秒时长。增强碎片分离、纸边对比和新连击出现后旧碎片的可见性。
- 过热：控制分数背后小火苗高度/宽度，增加错相循环，避免同节奏齐动。场景布景保持原图比例和机位适配，强化分层摆动与灯花局部呼吸，压低靠 HUD 上沿亮度。没有新增背景绘画或雾。
- 音轨：保留明确的分段发光实体与辅助线结构，仅微调近白核心中的队伍颜色、压低过亮饱和。

## 验证与审查入口

- `regression.txt`：真实 Shit Spine 资源动画回归；连续扣血/回血（0.05/0.10/0.15 秒间隔）、两个反转方向、归零后爆点时序。
- `hud/unity-validation.txt`：实际 HUD 渲染和 ScoreManager 事件回归；1–6 位、窄/宽六位数字排布。
- `gameplay-regression.txt`：SampleScene Play 中自动安装、旧 UI 隐藏保留、扣血/回血、失败等待归零、重开。
- `live/runtime-validation.txt`：1920×1080 原生 Game View 截图，包含 Overlay UI；无场景保存。
- `combo.gif`、`combo-new-hit.gif`、`entry.gif`：原生 Game View 截帧的局部动图，分别检查撕碎、撕碎期间新命中和入场节奏。
- `hud/`：各血条状态；`rails/`：五个判定状态；`live/`：完整实机截图。

截图是控制事件时间的实机场景审查，不等于完整自动对战录像。玩法脚本回归与视觉审查分开列证据；仍需在玩家实际改动后的相机与 Canvas 下确认最终观感。
