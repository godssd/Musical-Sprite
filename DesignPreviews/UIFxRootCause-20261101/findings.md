# 光效与Combo剩余问题：实证定位（2026-11-01）

本轮只定位。未修改生产shader、运行时脚本、样式资产、已认可排版或场景。新增Editor隔离诊断及其Shader副本，仅用于本目录对照图。

## 1. 血量光效：不是单纯颜色/亮度不合适

证据：本次用户图1、2、3；`FullRibbonHUD.shader`；本目录00–03逐层关闭实验。所有对照固定素材、相机、时间（变化后0.30秒）、血量起止、颜色和布局。

### 已确认的实现错误

1. **旧刻度内光没有移除**。shader仍执行 `rgb=lerp(rgb,_FlashColor.rgb,innerGlow)`。新的独立marker、nearGlow、farGlow又在后面叠加。此前移除了旧硬刻度，却漏掉其较宽的内光。
2. **三条边界不是同一个几何定义**。虚血边界和旧内光使用 `healthX` 与 `2.5/ribbonWidth` 偏移，新marker使用最大0.012的另一条弯曲公式。当前605单位血带、0.914有效范围、1.12缩放下，截面中心的偏差约4.9屏幕像素；这只是参数计算示例，具体位置随截面变化。足以造成发光核心与实色边界错开、变粗。
3. **整段虚血被叠成多层材质**。bandLight包含中线提亮与rim提亮，pendingWhite混入奶白，pendingHalo又沿全段扩散。因此不是参考中的“实色虚血+薄亮边+清楚的光头”，而是颜色发灰、上下多条亮边的厚胶带。
4. **marker的光场也不是有限光尖**。弧线公式对超出核心长度的cy继续作平方外推，near/far glow仍在外围计算，产生向后弯的宽光瓣；仅在核心上用endTaper并没有限制整个光场。参考的核心与光晕尺寸关系没有被单独标定。
5. 预烘焙距离场只改善轮廓扩光取样，本身不提供参考中的光头造型，也不能消除上面几层的重复提亮。它不是本次效果不匹配的充分解法。

### 关闭实验说明

- 00：现用效果。
- 01：只关闭整段虚血外晕。
- 02：进一步关闭虚血中线/rim内亮层。
- 03：进一步关闭遗留innerGlow，新marker及其光瓣仍保留。

01–03逐步移除了厚重、分层的色带，证明问题来自这些层的组合。03仍有不合适的marker光瓣，所以**不能把03当修好后的设计**；也不能简单把所有光效关闭后交付。

### 修正范围

- 保留当前实血、虚血时序和阻尼，不改已认可的UI排版。
- 定义唯一的曲带截面/边界位置，实色截止、刻度核心、刻度外光都从同一位置派生。
- 删除旧innerGlow路径，清除中心/rim的奶白层叠；虚血先恢复不透明的黄/绿本色。
- 按图3分别标定窄亮核心、近场色光、远场柔光。虚血整体可有薄的贴形辉光，但光头必须是焦点，不能全段一样厚。
- 光尖用有限轮廓和受限光场，不能让曲线在核心以外继续向后展开。
- 核心、近光、远光分别输出单层审查；在深蓝底、普通场景、过热亮背景下都检查。正常透明混合适合实体色，发光应单独控制混合与层级，不再将所有结果一起做浅色透明覆盖。

## 2. 入场：现在仍是逐部件刷白并叠晕，不是参考的整体白光加载

证据：用户图4、5、6；FullRibbonBattleHUD.Apply与FullRibbonHUD.shader。

- 每个头像底、头像框、叶片、文字、血带分别扩光，接近位置反复覆盖，填掉头像框/月牙等原有负形空隙，形成白团。独立alpha叠加的结果不等于“整组遮罩统一扩一次光”。
- 已揭示区域在整个加载阶段都以接近恒定的白色绘制，光头也接近相同的白色；缺少明确的窄亮头、近场光和远场光对比。增加全局亮度只会继续糊白。
- 加载头复用了血量变化的刻度宽度、弧线和外晕参数，不能等价于图4中的局部白亮推进头。
- 揭示仍是屏幕横坐标step，前沿没有使用专用进度遮罩/曲带切线控制。上轮换的是推进速度曲线，并未实现此前方案中的专用加载遮罩。
- resolve阶段同时叠加白色混合和ResolvePulse，继续维持全组较高白度，颜色回落集中在后段。它与“明确推进→终点蓄亮→同拍回色和前向碎光”不是同一节奏。

### 修正范围

- 入场使用整组实际UI的统一轮廓缓存/遮罩，加载阶段从无到有揭示；如需RT，仅在入场准备时抓取/构建一次并复用，不每帧截图。
- 白色实体保留准确轮廓和空隙，外光从统一组遮罩产生一次；不再给所有邻接部件分别堆同等级的大光晕。
- 专门制作加载头：位置由同一进度驱动，方向由曲带局部切线决定；窄亮核心、局部尖光、大而软的外晕各有明确占位。
- 分离“已生成的白色主体”和“最亮的移动光头”，避免全组白色强度都顶到同一个上限。
- 终点完成时保留已确认的前向碎光方向和尺寸方案，统一回色节拍；不改头像内容和最终UI形状，不提前显示分数。

## 3. Combo：标题、弧线和叶片确实没有参与完整离场

证据：图7；ComboDisplay.ResetCombo只调用 `tear.Capture(paintedNumber,...)`；ComboTearGraphic.CopyGlyphQuads只捕获数字。其余四个Image放在另一个CanvasGroup里，只修改alpha。

因此当前结果必然是：数字撕裂并变灰，COMBO仍奶白、弧线仍队伍色、叶片仍绿色且留在原位，直到最后一起淡掉。这是离场对象范围遗漏，不能用调数字的时长解决。

还有渐隐节奏问题：代码已经存在渐隐，不能说完全没有。主片与装饰在0.60秒动画最后0.216秒集中淡出。按现曲线，0.48秒alpha约0.583，0.54秒约0.188，0.57秒约0.053，0.585秒约0.014；最后再清空快照。视觉上从仍明显到几乎消失集中在很短时间，加上部件灰化不一致，显得突然。本次仅有静态图，未据此断言发生过额外异常Cancel；若实机还有跳清，需要进一步区分常规断连结束与重开/禁用导致的强制清理。

### 修正范围

- 快照纳入数字、COMBO、左右弧线、叶片，统一失败时间轴。
- 数字承担主要撕裂；标题、弧线、叶片同步失色、轻微离散、渐隐，保持原造型，不擅自把整个装饰改成另一套碎片风格。
- 数字来自digits-v1，四个装饰来自labels-v1；按两张图集建立两个离场渲染组，保留各自UV、位置、颜色，使用同一时间轴，避免强行用数字贴图去画其他部件。
- 保留快速撕开和阻尼减速；渐隐提前开始并拉长至约0.35–0.40秒，可先采用总时长0.75秒、0.35–0.75秒渐隐作为制作起点。不是将0.60秒曲线整体拉伸。
- 原来的CanvasGroup不再与离场快照各走一个时钟；旧快照所有部件达到不可见阈值后再清理。
- 新连击继续即时显示，旧离场组独立完成；无连击时不产生任何断连表现。

## 4. 验收方法调整

静态排版本轮冻结。先只做一个红方50%损血、一个红方35→75%回血、蓝方镜像，以及加载25/50/75/100%定格。在相同缩放与底色下对照参考的核心宽度、溢出高度、色带是否实心、负形是否保留。每个核心/近光/远光单独审查，合成后再看原速。

Combo审查必须覆盖整个组，检查标题/弧线/叶片是否跟随失色和渐隐，不能只断言数字mesh的alpha。最后若干帧检查全部离场组可见度已接近0，再检查清理。通过这些视觉检查之后才回完整对局验证。

此前逻辑测试没有覆盖“其他部件是否接入”“刻度与虚血边界重合”“入场负形不被光晕填平”等验收点，所以PASS没有拦住本次问题。后续补的是这些明确的视觉检查，不继续用编译通过或动画结束来代表还原设计。
