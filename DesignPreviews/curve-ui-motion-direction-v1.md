## 1. 背景：沿用过热插画的笔触与构图

保留大幅弯曲枝干、前后层叠的花叶、少量花形暖光，把常态环境调整为通透的森林庭院。底色采用苔绿、奶油黄、杏橙，远景偏淡，近景保留深绿和褐色轮廓。

- 背景上部可以丰富；音符经过的场内降低细节密度与明暗反差。
- 日光穿过树冠，地面有大块柔和明暗分区；小范围暖光集中在花灯附近。
- 接触阴影支撑树根、石头和角色落地位置，增强层次；不要用整屏灰黑覆盖制造体积感。
- 不主动添加雾片、浓雾边框或暗角。远景层次靠色彩、对比和遮挡形成。
- 当前图的花叶饱和度偏展示效果；接入时建议先降低背景局部饱和度与锐度，确保音符和角色始终清楚。

### 常态与过热的区别

常态：自然绿金色庭院持续存在。过热：对应一侧的独立插画背景从地面后升起，在背景区域形成新的舞台布景；超级过热：更大的枝叶、花灯和第二层背景展开。禁止将过热做成覆盖场内的雾片。

建议拆成远景底图、枝干中景、花叶近景、少量发光花朵四类资源。常态叶梢摆动周期 4–7 秒、位移约自身尺寸 0.5–1%；过热布景进入 0.55 秒，退出 0.35 秒，内部花灯和枝叶循环持续 3–6 秒。上述均为设计参数，不是当前代码既有数值。场内相机、角色坐标及地面边界保持原布局。

## 2. 动效总原则

曲线负责引导视线，叶片负责表现生命感，数字负责信息。动作主要来自局部展开、短距离回弹和柔光迁移，避免整组 HUD 不断放大。

| 层级 | 适用状态 | 强度与节奏 |
|---|---|---|
| 常态 | 音乐节拍、可用状态 | 叶尖轻摆、极小亮度起伏；数字保持稳定 |
| 即时反馈 | 按下、加分、连击 +1 | 60–180 ms 起效，220 ms 内回稳 |
| 重要结果 | 受伤、技能释放、过热升级 | 300–650 ms，最多一个主动作配少量点缀 |

数字不使用厚黑描边。沿用奶油白、珊瑚红、柔蓝与叶绿；复杂背景下用局部低透明柔影保证阅读。光晕采用窄亮核加大面积低透明渐变，不能靠一条硬边扩大亮度。

## 3. 状态与时间设计

以下时间均为初始调参建议，单位 ms。预览是动作草案，最终材质细腻度需 Unity 中实现。

| 元素 / 状态 | 具体动作 | 时长 / 限制 | 游戏触发依据 |
|---|---|---|---|
| 开场 | 血条曲线沿长度展开，数字短距离淡入，叶尖最后打开 | 总计 650；两侧同时 | 初始化完成后播放一次；重连只同步状态 |
| 常态 | 曲线和数值稳定，叶片每两拍极轻微呼吸 | 旋转 ≤2°，缩放 ≤1.015 | `Conductor.songPositionInBeats`，仅音乐运行时 |
| HP 受伤 | 数字立即更新；血条收缩，旧血量留下杏色残影；受击点短闪 | 主条 320；残影停 80 后追赶 240；整组位移 ≤3 px | `ScoreManager.OnHPChanged` 比较前后值，结合 `OnSideDamaged` |
| 连续受伤 | 从当前显示进度继续下降，合并残影，不回跳到旧目标 | 同元素只留一个动画通道 | 当前显示值 → 最新真实目标 |
| HP 回复 | 色带柔和伸长，末端嫩叶舒展一次 | 400；不震屏、不播放受击色 | HP 增加且未超过各方实际最大 HP |
| 低血量 | 血条末端每两拍低幅亮一次；不持续闪整条 | 建议 ≤25% 开启、≥30% 关闭 | 新增纯表现阈值，可配置，不改变战斗 |
| HP 清零 | 主条收尽，末端卷曲落定 | 250–350 | `OnPlayerDefeated`，结算优先 |
| 分数增长 | 仅变化的一方数字轻提起并回弹，数值短插值到目标 | 120–180；最大缩放 1.045 | `OnScoreChanged` 去重，`OnScoreGained` 区分正常加分 |
| 密集加分 | 多次变化合并为同一数值追赶；不排队累计弹跳 | 同一时刻只追最新目标 | 判定频率高时沿用当前显示值 |
| 保底补分 | 数字平滑更新；若扣血另播受伤；没有命中庆祝 | 150–200 | `ApplyCatchUp` 不派发 `OnScoreGained` |
| Combo +1 | 数字轻压再回弹；两侧小弧线向外展开一点 | 180–220；最大缩放 1.07 | 权威有效判定，不依赖分数变化 |
| 连击里程碑 | 数字回弹略大，侧边叶片展开一次 | 320；不每次额外喷粒子 | 建议每 10 连击；遇过热升级合并为后者 |
| 断连 | 弧线回收，旧数字下沉 4 px 并淡出；无额外 MISS 文案 | 180 | MISS / BREAK 的一致规则需先确认并统一 |
| 技能削减 Combo | 数值回退，侧弧收窄，不使用成功命中弹跳 | 200 | `ComboDisplay.ReduceBy`；不能据此推导过热状态 |
| 进入过热 | 血条旁一片叶展开，曲线亮点滑过一次 | 420；对应侧背景同步升起 | `FeverManager.OnStateChanged` |
| 超级过热 | 第二片叶展开、小花心亮起；局部光晕更丰厚 | 550；禁用整屏闪白 | 同一状态事件；不是每次高 Combo 都触发 |
| 退出过热 | 叶片收回，尾光降回常态 | 250；背景独立回落 | 真实 FeverState 变化 |
| 暂停 / 恢复 | 停止节拍动作；已发生的短反馈收尾后静止，恢复时从当前拍相接 | 不补播暂停期间积压反馈 | 接入实际暂停与音乐状态 |
| 结算 | 停止输入反馈，胜方曲线舒展一次，败方色带落定 | 500–650；只播一次 | 已确认的游戏结果事件，不能单靠两侧分数比较 |

## 4. 技能箭头：输入反馈与释放反馈分开

右侧三个箭头是本地玩家输入入口。当前本地玩家是 side 0，所以即使摆在屏幕右侧，仍使用红方主题色，不按屏幕位置套蓝色。

| 状态 | 表现 |
|---|---|
| 待机 | 开口曲线圆环，奶油白箭头，红色细尾连接；无实体按钮底座 |
| 至少一个技能可输入 | 环尾的小叶片展开一次，保持轻微亮度；避免持续缩放 |
| 物理按下 | 箭头与环缩至 0.95 后回到 1，立即响应，约 120 ms |
| Accepted | 对应环上短弧扫过；留下细小输入痕迹，直到后续输入 / 超时 |
| Triggered | 三个环的连接尾线亮起，弧线舒展，最多 2–3 片小叶散开；350–450 ms |
| Rejected | 当前短弧向内收回、轻偏移 2 px，180 ms 消退；不整组高亮庆祝 |
| 超时 | 清掉已输入痕迹，160 ms 回到可用或待机状态 |
| 角色睡眠 / 技能冷却 | 重新计算可用候选；角色自身能量槽承担其冷却表现 |

不能给这三个箭头统一套一个“技能冷却圆环”：它们同时服务多个角色，而且存在不要求能量的技能。也不能固定画三个输入进度点：真正的技能序列长度由 SkillSO 决定，可能不相同。可点击预览中的 `← ↓ →` 只是演示序列。

## 5. 判定线与判定灯保持已确认方向

- 按下：该音轨整段判定线呈柔白光，带较宽、较淡的向场内渐变。
- 非 MISS / BREAK 的有效命中：同段亮度再提高，白芯偏本方红 / 蓝，同时该音轨上下两侧边缘向内延展。
- 边缘近端宽亮，远端经过红→粉紫 / 蓝→蓝紫的轻微色相变化，透明度和宽度逐步消失；不形成硬矩形。
- 无独立实体灯泡，无额外黑底灯框。常态线保持轻薄，与整套曲线 UI 的节奏一致。
- 连击数字与 HUD 光效不能遮挡这一级操作反馈。连续命中重触发包络但限制最大亮度，避免光效无限相加。

## 6. 已读代码与接入注意点

这部分是源码观察，不代表已经运行验证。

1. **双方分数会一起弹。** `Assets/Scripts/ScoreManager.cs:510` 的 `UpdateDisplays` 每次同时调用双方 `SetScore`；`Assets/Scripts/ScoreDisplay.cs:85` 无数值相同判断，直接重启动画。接入前先做目标值去重，动画只作用于变化方。
2. **连击与过热对 BREAK 处理不一致。** `Assets/Scripts/BattleVisualsController.cs:117` 中灯效排除 MISS / BREAK，但 Combo 仅在 MISS 时重置；`FeverManager` 对二者都重置。需要统一判定事件语义，再接断连动效；不要把 BREAK 误画成成功。
3. **可见 Combo 与 Fever 不是同一个计数。** `ActiveSkillRuntime` 可以调用对手 Combo 的 `ReduceBy`；FeverManager 独立维护计数。因此过热始终订阅 `OnStateChanged`，不能读屏幕数字判断。
4. **技能可用色尚未接上。** `SkillInputUI.cs:268` 的 `RefreshButtonColors` 使用 idleColor。应该根据 ownerSide、Standby、能量门槛、睡眠条件计算候选，而不是只看能量满。
5. **技能超时是惰性清理。** `SkillInputUI.cs:152` 在下一次输入时才检查超时。如果 UI 画输入残留，需要独立到期表现，并补统一的缓冲重置通知，避免 UI 和逻辑两套时钟。
6. **按下的向前光尚不完整。** `LaneIndicator` 的 wash / edges 当前依赖命中包络；按下应有独立的低强度白色 wash，命中才启用强彩色边光。
7. **旧动画幅度偏大。** 源码默认分数缩放 1.2、Combo 1.3、技能按钮 1.35，容易产生粗重感。替换时读取场景 / Prefab 实际序列化值，不只改默认字段。
8. **HP 需防连续扣血回跳。** `HPBarLiquid.SetFill` 的起始进度涉及旧目标值；新动画从当前显示值接续。数字与真实 HP 立即同步，视觉插值不得反写数值。
9. **当前资产阈值为 20 / 50。** `Assets/Data/FeverConfig.asset` 记录过热 / 超级过热阈值及 1.05 / 1.1 倍率。接入必须读取配置，预览直接切换状态仅供比较；不将阈值硬编码进动画。

## 7. Unity 资源与实现结构

### 资源拆分

- 血条：曲线容器底纹、可裁切色带、残影色带、叶片、柔光遮罩分别输出。血量按曲线长度参数裁切，避免横向缩放导致叶尖变形。
- 分数 / Combo：TMP 数字图集或支持等宽数字的字体；标签、数字、两侧弧线独立节点。根节点负责布局，子节点负责弹跳。
- 技能：箭头、开口环、尾线、输入短弧、可用叶片分别输出；透明点击区域尺寸不跟随视觉缩放。
- 光效：软渐变贴图与独立 additive 材质，限制 HDR 亮度；不靠全局 Bloom 掩盖硬边。
- 背景：分层 PNG 与少量局部循环，不直接将整张概念图贴入场景。

### 建议接入

新增纯表现适配层，把已有游戏事件转成 `HPChanged / ScoreChanged / ComboChanged / SkillFeedback / FeverChanged` 等 UI 状态。动画参数集中放到一个可调配置资产。数据层保留原职责，不让 UI 动画决定伤害、得分、能量或过热。

事件订阅在启用时建立，停用时解绑。初始化快照直接赋值，不误播放受伤 / 回血 / 加分。对象池复用时清空残影、计时器、技能痕迹；场景切换与结算取消未完成任务。

同元素冲突优先级：结算 / 禁用 > 断连 / 受伤 / 释放结果 > 普通命中 > 节拍常态。不同数据变化可以同时出现，但不得叠加同一 transform 的缩放协程。动画只维护一个当前包络，并重定向到最新目标。

### 后续实施顺序

1. 确认背景明亮程度和动效力度。
2. 完成事件语义统一及表现适配，不改变玩法规则。
3. 用一侧 HP、分数、Combo、三个技能箭头完成完整链路，再镜像另一侧。
4. 最后接入背景层、过热背景和光照；判定灯单独按原参考校准。
