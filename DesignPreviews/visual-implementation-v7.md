# 战斗画面落地方案 V7：失败判定核对、撕碎 Combo 与语义技能按钮

日期：2026-10-23。阶段：调整方案，尚未实现。

本轮已静态核对相关源代码，未运行游戏或测试，未修改运行时代码 / 场景 / 材质。V5、V6 保留供对照；本文覆盖它们在失败表现、技能按钮和雾方面的规定，其余设计约束继续有效。

## 2. BREAK 的实际情况：代码有，画面显示 MISS

### 2.1 源码证据

| 路径 | 已读取的事实 |
|---|---|
| `Assets/Scripts/HoldNote.cs:1384` 的 Judge | Waiting 时错过起手窗口走 MissHead；Holding 时持续检查所需轨道是否被按住 |
| `Assets/Scripts/HoldNote.cs:1411` | 按住不满足时进度衰退，低于断连阈值调用 Break |
| `Assets/Scripts/HoldNote.cs:1504` | Break 实际发出字符串 `BREAK`，并设 missReported 防止随后重复发 MISS |
| `Assets/Scripts/HoldNote.cs:692` | 起手漏击走另一条路径，上报 `MISS` |
| `Assets/Scripts/NoteSpawner.cs:668` | 将 HoldNote 的评价转发给统一 OnJudge |
| `Assets/Scripts/JudgeFeedbackManager.cs:105` | 明确将 BREAK 的显示文字替换成 MISS |
| `Assets/Scripts/Character/FeverManager.cs:57` | MISS 与 BREAK 都调用 OnNoteMiss，清过热计数并退出过热 |
| `Assets/Scripts/BattleVisualsController.cs:133` | 目前仅 MISS 清 Combo；BREAK 会落入增加 Combo 分支，这是待修正的不一致 |
| `Assets/Scripts/ScoreManager.cs:476` | BREAK 得分为 0，不回滚之前已取得的分数 |

结论：用户记得“失败都显示 MISS”是对的。内部 BREAK 表示 **Hold 已经起手后的中途断连**，并不只限定于跨轨形状；普通长按也走同一 Holding 状态机。普通漏击 / 起手漏击使用 MISS。

`breakThreshold` 是衰退速度的一个配置，触发还受当前进度与起手宽限等影响；本轮不改变断连判定窗口，也不把它简化成全场固定松手几毫秒即失败。

### 2.2 落地规则

- 对外所有这类失败继续显示 MISS，不新增一个 BREAK 评价档位或文案。
- 内部保留失败原因，供节点处理和问题定位使用；不做全项目字符串替换，以免破坏长条防重复上报逻辑。
- 统一失败分类：MISS 或 BREAK 均为失败。画面 Combo 清零，过热内部计数清零，状态立即切 None。
- 失败不触发成功判定光、成功 Combo 回弹或普通成功命中动作；其他独立的受伤、施法动作继续按自身事件执行。
- 数据清零与动画播放分离。不能因为角色沉睡时跳过视觉，就把必须发生的状态清零也提前 return 掉。
- 过去注释中的“BREAK 不清零 Combo”不再是本轮设计依据，应随实际修正一并更新。
- 已得分数和能量不因此倒扣；HP 只听真实伤害 / 治疗事件，不由 UI 推断一次 MISS 要扣多少血。

## 3. 断 Combo：扯碎、变灰、消失

### 3.1 触发边界

只有一次真实的 **旧 Combo>0 → 新 Combo=0** 转变才有可撕碎的数字。初始为零、已经没有数字时再次 MISS、重开和无动画同步，不生成“0”、默认数字、碎片或落叶。

失败和技能导致的真实清零可以复用数字退场，但失败过热反馈只由真实过热状态变化触发。技能削减到非零仍使用轻收束换数，不撕碎。

### 3.2 造型

- 碎的是当时正在显示的手绘数字，保留其笔画纹理和真实位数；不能换成预制的 55、统一小方块或碎玻璃。
- 数字组沿少量不规则斜裂口分成约 4–6 个主要部分；单个数字可减少到 2–3 片，碎片数不随位数成倍增加。
- 两侧向外牵开形成“扯开”的感觉，然后灰化、轻落并消失。轮廓仍能短暂看出原数字的一部分，不做爆炸、尘雾、灰烟或大量纸屑。
- 断口是很薄的纸纤维 / 哑光浅边，无发光描边。花草底座保持完整，淡出即可，不把整个 UI 和场景一起撕碎。

### 3.3 初始时间轴

| 时间 | 数字 | 附属装饰 |
|---|---|---|
| t=0 | 真值立即清零；停止成功回弹，记录当前数字的排版和纹理 | 开始取消成功态高光 |
| 0–.05 秒 | 数字整体轻微横向拉伸到约 1.04，纵向压至 .98，出现不规则细裂口 | 侧弧略向外拉，配合牵扯 |
| .05–.15 秒 | 主要片向左右分离约 6–12 px，并下移约 3–6 px；旋转约 3–8°；本方色逐渐转为偏暖的中性灰 | 侧弧和 COMBO 标题开始淡出 |
| .15–.30 秒 | 灰色数字片再下落少量、持续变透明，直到全部消失 | 标题 / 侧弧约 .20 秒消失，底座及叶片约 .26 秒淡出 |

位移为 1080p 参考界面的等比 UI 单位。参数是首版起点，核心顺序固定：轻拉 → 撕开 → 变灰 → 淡出。

### 3.4 可行实现

使用正式数字 Sprite 图集的真实 UV 与当前排版，将数字四边形沿预设的折线裁切成片，每片继续采样原字形 Alpha。裂线统一在数字组局部坐标中定义，片的位移 / 旋转围绕片自身中心进行。

这允许任意连击数使用同一逻辑，不需要为每个数字单独做逐帧动画，也不依赖截取整屏。裁切片使用对象池、保留 UI 遮罩和裁切规则；结束后还原颜色 / UV / 姿态。字体资源改变时仍以新图集为准。

新命中到来时立即显示新 Combo；残片快速在约 .05 秒内退完，不能继续覆盖新数字、延迟新数值或被旧结束回调再次隐藏。碎片只是退场残像，不参与 Combo 数据。

## 4. 断过热与数字撕碎的配合

沿用 V6 的布景退出结构，仅把原“数字下沉”替换为撕碎动作。

- 同一失败当帧：Combo / 过热计数清零，倍率回到普通态；一次 MISS 正常显示。
- 前 .12 秒：数字被拉开，同时本方过热插画中的花灯由上至下短暂错开熄灭，枝叶停止循环并回稳。
- 普通 Fever：约 .06 秒开始沿原路径降下，约 .45 秒隐藏。
- SuperFever：前层先退，后层晚约 .06 秒；两层约 .50 秒内隐藏。逻辑直接 None，不保留中间 Fever 加成。
- 数字约 .30 秒退完，背景继续完成最后短暂降下；正常森林光照、原地面、对方布景和中央分界不跟着变灰。
- 若没有旧 Combo 数字，但因独立计数仍处于过热，只播真实存在的过热退出，不补造一组数字。
- 多轨同帧失败只产生一次该侧 Combo 清零退场、一次过热退出；每个真实判定的 MISS 仍按对应位置表达。

## 5. 技能按钮：只有按下和重置两种按钮动效

### 5.1 哪种情况叫输入错误

沿用当前匹配条件：追加本次动作后，在本方角色中寻找技能有效前缀匹配。候选还必须具有主动技能、处于允许响应的 Standby 阶段、满足该槽能量门槛、未被沉睡规则屏蔽。

**匹配集合为空，才进入本次要求的输入重置流程。**不因为尚未凑齐完整序列就报错；角色存在但正在冷却 / 能量不满足、因而实际无人可响应时，也属于当前匹配集合为空。

### 5.2 正常输入

- 当前按钮图案和开口环轻压到 .95，再约 .12–.16 秒回到 1；一层很轻的奶油色提亮随动作消退。
- 有效前缀和完整技能序列使用相同的按下表现。取消 V5 / V6 的前缀亮弧、输入步数进度、成功连线扫光、三环舒展和可用提示脉冲。
- 完整匹配仍正常施法、清空输入缓冲；按钮不额外庆祝，也不进入错误锁定。
- 现有角色的 SkillSelect / SkillStart / 释放动画保留，这是角色行为；本次删去的是新增按钮阶段动效。
- 超时按原输入规则清空旧缓冲，本次有效输入可作为新起点；超时本身不增加重置动画或禁输期。若新起点仍无人匹配，则进入错误重置。

### 5.3 错误重置：初始建议 .24 秒

| 时间 | 数据与输入 | 视觉 |
|---|---|---|
| t=0 | 清空本方输入缓冲与时间戳，进入 Resetting；锁住本方三个技能输入动作 | 停止当前按下回弹，三个图案同步略收小 |
| 0–.08 秒 | 拦截新技能输入，不记录、不排队 | 开口环从末端向起点短暂收回，图案降低饱和度与亮度，保持可认 |
| .08–.16 秒 | 继续拦截 | 图案保持收束，表示输入正在归零 |
| .16–.24 秒 | 直到结束前都不接收新动作 | 开口环恢复原轮廓、图案回到正常色与比例 |
| t=.24 | 缓冲为空，解除锁定，必须有一次新的有效按键 / 点击才能输入 | 回到待机 |

不用三个红色大块闪烁、失败震屏、旋转加载圈或技能冷却倒计时。重置动作本身表达这段短暂不可输入状态。

### 5.4 输入锁的具体边界

- 锁定在统一技能输入入口完成，不能仅把三个 UI Button 设为不可点：键盘、触摸和鼠标都必须经过同一检查。
- 锁住的是本方技能序列输入；四条音轨的正常打谱、另一方输入及已经开始的技能运行不受这个锁影响。
- 锁定期间的尝试没有额外按下回弹，不延长锁定、不播放第二次重置，也不在解锁后补发。
- 按键在锁定时按住并保持到解锁，不自动补一记。触摸若在锁定时开始，即便抬手发生于解锁后，该次手势也不能提交。
- 每个指针保留自己的手势是否被接收及重置版本信息，防止锁定前按下、锁定后抬起的旧点击泄漏。
- 保持当前正常触摸点击提交语义；PointerDown 可提供即时按下触感，但不能同时在 Down 和 Click 各提交一次动作。
- 重置状态和 UI 计时由同一状态源控制，暂停 / 切场景时一致清理，不能出现“看起来恢复了但仍被锁住”。
- 共享 FeedInput 的调用方需识别 Resetting / Ignored 结果；不能把锁定中的忽略当成第二次 Rejected。若 AI 使用同一重置规则，状态按 side 独立，需更新其调用处理，避免串到玩家按钮。
- `TouchInputManager` 当前直接对画面发射物理射线，未见 UI 指针排除。接入时要处理技能按钮手势的归属，避免按钮点击同时触发背后的音轨；已有音轨触摸的释放仍须正常执行，不能因跨入 UI 而卡住按住状态。

### 5.5 当前实现缺口

`SkillInputUI` 当前 matching.Count==0 会清缓冲并 FlashError，但没有 Resetting 锁；后续调用仍可继续 FeedInput。故“重置期间不能输入”需要实际增加控制状态，不能仅制作一段动画。

## 6. 勇气、守护、坚韧：独立于键位的三个图案

### 6.1 固定顺序与映射

| 游戏内位置 | 动作含义 | 拟定图案方向 | 当前数据的兼容映射 |
|---|---|---|---|
| 上 | 勇气 | **跃起的火苗**：粗圆火身与一个上挑尖端，中心留一处小负形，传达主动向前 | 对应旧序列 A / Left |
| 中 | 守护 | **两片叶子合抱一颗种子**：宽而稳定的包护轮廓，内部圆核清晰 | 对应旧序列 B / Down |
| 下 | 坚韧 | **裂石中长出的芽**：低矮石块加一株挺立嫩芽，表现承受压力仍生长 | 对应旧序列 C / Right |

顺序与含义是用户要求；图案具体造型是本轮提案，尚未出正式原画或获最终美术确认。它们表示三个技能输入动作，不代表只给某一种角色使用，也不自动改变任何角色属性。

### 6.2 与已选 UI 的统一

- 继续使用原母版的手绘开口环、柔和本方色和奶油主图案，右侧竖排不变。
- 三个图案的视觉重量、占框比例接近，但外轮廓明显不同：火苗上挑、守护横向包合、坚韧下稳上直。小尺寸和灰度下也应能辨认。
- 主体采用少量块面和清楚的负形，避免写实火焰、复杂石纹、金属徽章、厚黑边和小字标签。
- 勇气不做持续燃烧特效，守护不做持续罩光，坚韧不做持续摇枝；待机稳定，主要反馈来自按下 / 重置。
- 主图案不画键盘箭头或键帽。中文名称可用于设置页 / 首次教学；战斗按钮不必常驻文字。
- 现有细连接曲线只作为静态装饰，不再承担前缀进度或施法成功扫光。

### 6.3 改键与移动端

输入链路应为：实际设备输入 → 玩家绑定配置 → 勇气 / 守护 / 坚韧动作 → 技能序列匹配。触摸按钮直接发动作，不模拟某个键盘 KeyCode。

- 默认键位可继续是 ← / ↓ / →，但玩家修改后须以真实配置为准。修改键位不改变图案、竖排顺序或技能序列。
- 当前读取到的 `SkillInputUI.cs:47` 和 Update 仍硬编码方向键；这证明该入口尚未接入可配置动作，不等于断言整个项目完全没有改键系统。
- 现有 `InputSystem_Actions.inputactions` 中读取到的是通用 Player / UI Action，未见这三个技能语义动作；实施时先找到实际改键配置入口再接线，不能凭空假定已有可用的 Skill Action。
- 若现有改键系统确实尚未覆盖技能动作，补齐这三个动作的配置、保存与恢复；避免在旧 Update 和新 Action 回调里同时消费同一次输入。
- 保留 `SkillInputStep` 现有序列化值和历史 A/B/C、L/D/R 解析兼容。通过适配层映射新语义，不重排枚举或把历史资产数字值批量改掉。
- PC 若需要提示当前绑定，在设置 / 教学或独立小提示中显示真实键位，不重新把键帽做成主按钮图案。移动端不显示键盘提示。
- 触摸热区与图案动画分离；按钮周围留安全间距，适配 Safe Area。重置锁必须同样覆盖触摸。

## 7. 雾：可选，不能决定画面基调

V6 的“本轮绝对不做雾”改为以下执行方式：

1. 先以无雾完成背景、过热布景、局部暖光、接触阴影与整体色彩，确保本身自然美观。
2. 不自动启用当前旧局部雾入口，也不恢复全局雾。旧入口仍需解除自动创建，避免是否有雾由遗留代码决定。
3. 只有后景衔接或局部空间层次确有需要时，增加独立可开关的小范围薄层；颜色取邻近环境，强度以不遮盖角色、音符、原场景件为限。
4. 不要求实现真正体积光线步进；手绘薄层或局部大气透视已经足够时采用更简单的实现。
5. 若开雾版本出现发灰、阴郁、幽灵形状、幕布边缘或大面积遮挡，就保留无雾版本，不把雾列为完成指标。
6. 如制作可选雾，交付同相机同状态的开 / 关比较与默认状态说明；不以牺牲地面保留和读谱清晰为代价。

| 判定带 | 四轨、每侧四段、五边界；平面直线；按下柔白、成功队伍色更亮；红蓝几何一致；上下边光向内渐隐 |
| 过热 | 正式分层动画插画、正对相机、默认隐藏、每侧独立；Super 叠加第二层；退出见本文 |
| 能量槽 / 中央分界 / 溶解 | 保留原方案；不因技能输入重置或 UI 撕碎而清空、变形或重染 |

## 9. 实施清单与新增完成标准

### 9.1 资源阶段

制作三个语义图案、数字图集、数字撕裂所需裁切参数、原母版开口环及独立装饰。保持 Fever 花灯可单独熄光。先核对静态造型再接动画，不能用箭头占位当最终图案。

### 9.2 逻辑接入阶段

- `BattleVisualsController`：统一失败分支，修正 BREAK 加 Combo / 播成功动作的问题；保持失败原因信息。
- `ComboDisplay`：清零数据与碎片显示分离，旧值为零不播放，动作可被新命中取消。
- `JudgeFeedbackManager`：对外继续 MISS，一次事件只产生一次评价。
- `FeverManager` / `FeverSceneryController`：沿用真实状态驱动退出；初始化与调试不误播失败。
- `SkillInputUI`：语义图案 Prefab、可绑定动作入口、按下 / 重置两态；统一 Resetting gate，更新返回结果及共享调用方。
- 玩家绑定配置：找到真实改键来源；需要时只补技能动作覆盖，不直接重写全项目输入系统。
- `TouchInputManager` / 技能指针代理：处理 UI 与打谱手势归属、锁期手势丢弃、多指与释放，避免误触和重复提交。
- 雾：去掉无条件自动生成；新薄层若使用，显式开关并单独验收。

### 9.3 完成标准

- 普通漏击、Hold 起手漏击和 Hold 中途断连均只向玩家显示 MISS；清零 Combo 与过热，既有得分不回滚。
- 零 Combo 失败时没有数字撕碎；有连击时撕碎的恰是当时数字，灰化并完全退完。
- 撕碎期间新命中能即时显示新连击；旧碎片不把新组隐藏。
- 技能有效前缀 / 完整匹配都只给按钮按下反馈，角色原选择 / 施法动作正常。
- 无人匹配时一次清缓冲、一次重置；锁期的键盘、鼠标、触摸输入全部丢弃，解锁后不补发，连续点不会无限续锁。
- 技能重置期间，正常四轨打谱仍可用；没有按技能按钮却误击后方音轨的输入穿透。
- 改键后新键有效、旧键按实际绑定结果失效，图案顺序不变；移动端同样三个语义动作，不出现键盘箭头主图案。
- 初始化 / 重开 / 暂停恢复没有假失败和遗留输入锁。
- 无雾版本本身满足自然美观要求；选用薄雾时不能遮读谱或形成诡异灰幕。

这些是后续核对标准，当前没有执行运行验证。
