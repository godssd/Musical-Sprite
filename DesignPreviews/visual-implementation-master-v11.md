# 战斗画面统一落地方案 V11

整理日期：2026-10-23，完成更新：2026-10-24。状态：**设计要求已汇总；代码与资源完成静态审查；实施前汇报版**。

本轮用户已批准 Combo 撕裂 V10，并要求分析全部后续工作的技术细节、素材与可行性。本文件合并 V5—V10 中仍有效的内容，解决冲突；旧版本仅作历史记录。本轮仅写文档，未改 Unity 运行时代码、场景、材质，未运行游戏或构建测试。

## 1. 可行性结论

**现有 Unity 6 / URP / uGUI 架构可以承载全部核心需求，无需更换渲染管线或引入新的付费插件。** 已有判定、血量、技能、过热事件可以接入；需要补齐正式美术素材、统一状态反馈，并修正已经查到的逻辑和渲染接入问题。

可行不等于现成：概念图不是透明切图、动画帧或 Prefab。Combo 撕裂、曲形血条与双层过热需要先做小样；粉色故障还需在实际相机中复现和定位。不能把静态源码审查写成“运行效果已验证”或保证移动端帧率。

| 模块 | 判断 | 必要条件 / 风险 |
|---|---|---|
| 四轨判定带、辅助线、按下与命中 | 可实现，接入明确 | 重建共用几何与软边 Shader；共享边避免双倍亮；实际透视下校准 |
| 手绘 HP、绿色回血虚血 | 可实现，需制作遮罩 | 血量区间裁切、连续事件接续、图集 UV；不能只换一张血条图 |
| 分数换位、Combo 回弹、评价 | 可实现 | 新字形 / 评价资源，消除旧双侧重复弹动和清屏重复评价路径 |
| 已确认的数字分层撕碎 | 可实现，视觉难度较高 | 自定义 UI 碎片网格与真实数字纹理；先做任意数字小样，不能用固定 55 帧动画替代 |
| 技能图案与输入反馈 | 可实现，含逻辑修正 | 真实释放成功返回值、独立锁定状态、语义映射、触摸归属；三图案具体画稿仍需定稿 |
| 正常背景、过热 / 超级过热循环 | 可实现，素材工作量较大 | 新分层插画、独立背景材质、构图裁切、相机朝向；当前四张临时图不能承担这个目标 |
| 场内光影、画面卡通统一 | 可实现，需原场景对照 | 混合材质不能一律靠实时灯；先受控色光与接触阴影，保留原地面和角色 |
| 可选局部薄雾 | 非必做项 | 默认关闭；仅在确实改善画面时另做对照，不作为交付依赖 |

### 粉色问题的证据边界

当前 PNG 能正常读取，材质和 Shader 的引用链存在；本轮读取到的 Editor.log 没有匹配到相关 Shader 错误。这**不能证明历史粉色已修复，也不能认定是“丢图片”**。实施第一步需要捕获出现粉色时的实际 Renderer、材质实例、Shader 支持 / 编译日志和当前相机渲染路径。

专用 URP 布景材质会解除不合适的 AlphaTest / 亮度裁切耦合；若编译故障来自共享 include、变体或管线设置，仍需修复实际根因。丢失引用时禁用该层并报出对象与资源路径，不生成大色板掩盖错误。

## 4. 事件与状态的统一约束

### 4.1 失败与判定

`IsFailure(rank)` 集中定义为 MISS 或 BREAK。业务与画面消费者共享分类，保留内部原始原因；未知 rank 记录诊断，不默认当成功。

| 事件 | Combo | Fever | 分数 / 能量 | 评价与判定光 |
|---|---|---|---|---|
| 合法成功：PERFECT / GOOD / CLEAR / PASS / YES | 按既有节点规则增加，不重算计数 | 按既有成功事件增加 | 保留原得分与充能规则 | 对应评价，成功光 |
| MISS / BREAK | 当帧清零；旧值>0 才撕碎 | 计数清零、None、倍率立即正常 | 本次不加分不充能，不倒扣旧值 | 一次 MISS；无成功光和普通成功动作 |
| 技能削减到非零 | 真实扣减、轻收束换数 | 保留原业务处理 | 原技能逻辑 | 不误播命中回弹 |
| 技能造成 Combo 真正归零 | 同款旧数字退场 | 只响应真实 Fever 状态变化 | 原技能逻辑 | 不由 Combo UI 擅自退出 Fever |
| 初始化、重开、无动画同步 | 设置真实数值 | 同步真实状态 | 设置真实值 | 清残留，不伪造事件 |

一次失败的逻辑清零不等待 .30 秒撕碎或 .45 秒布景退出。退出动画只负责旧视觉残像，不能延长得分倍率。已开始技能保存的 `releaseFever` 按现有“释放瞬间捕获”规则继续使用，不因 UI 退出倒改正在运行的技能。

节点生命周期仍由原音符管理。普通长按和跨轨长条均可能 BREAK；不改 breakThreshold、节点判定窗、宽限或 `missReported` 防重。同一个 Hold 源对象可以合法产生多个评价，不能按 source 对象一刀切去重。

### 4.2 动画优先级与生命周期

- 数值 / 状态先提交，表现后读取；UI 永不反向计算 HP、分数、Combo 或 Fever。
- 同模块只有一套当前状态；成功回弹被清零退场打断，新命中优先于旧退场。动画使用版本号 / 取消标记，旧完成回调不可隐藏新数字或解开新锁。
- 布局根节点与动画子节点分开；缩放不移动世界定位锚点，不缩小触摸热区。
- 订阅与退订成对；Disable / 重开 / 场景卸载取消协程、回收池、清 held 状态和输入锁。
- 战斗动画统一使用游戏时间，暂停时冻结；暂停 / 失焦处理输入取消，恢复后不重放锁期输入。
- 不为表现重写整套玩法总线。必要时在 NoteSpawner 的统一报告入口补充展示上下文（side、lane、span、nodeIndex、事件序号），旧玩法订阅保持兼容。

## 5. 四轨判定 UI：精确几何与软光

### 5.1 数量、坐标和常态

战斗是**四条音轨，红蓝半场各有四个对应判定段**，不是八条不同玩法轨道。每半场五条轨道边界，两相邻轨共享一条。

读取实际战斗所绑定的两侧 NoteSpawner；当前 `laneCount=4`、`laneSpacing=1.7`。相对 hitPoint 的四个 z 中心为 -2.55、-.85、.85、2.55，五个边界为 -3.4、-1.7、0、1.7、3.4。实现从配置计算，不把这些数值再写死一遍，也不扫描所有场景测试 Spawner 来造额外 UI。

- 判定带：一条纤细平面队伍色色带，分成四个响应段，细小间隔；不加黑底座、描边套管、倒角、塑料高光、圆形灯珠。
- 辅助线：五条笔直细线从判定带边界向场内渐隐；初始 1080p 参考近端约 1 px、透明度 15–20%。不加中轴光条、箭头、刻度或封闭网格。
- 判定带初始参考 6–8 px。像素数是实际相机中校准的视觉目标，几何位于真实地面平面、保持自然透视；不能让远近所有部分强制等屏幕宽而脱离世界位置。
- 长度随判定点到当前中央边界的可见距离限制，始终停在分界前。移动分界不拉长出界或产生尾端直立截面。

### 5.2 状态与时间起点

| 状态 | 判定段 | 场内渐变 / 边界 |
|---|---|---|
| Idle | 平面红 / 蓝，低对比 | 五条弱辅助线 |
| Press / Held | 整段柔白芯，光晕比常态明显 | 一层较弱的前向软渐变；不显示成功等级 |
| Hit | 整段更亮，近白芯偏本方色 | 对应轨道上下两边同步增强，宽软晕向场内渐淡；保留更弱内侧 wash |
| Hit 收尾 | 约 .24–.30 秒衰减 | 回到辅助线；若仍按住，回 Press 而非熄灭 |
| 松开 / 控制结束 | 约 .08–.12 秒收尾 | 无成功事件不补播 Hit；沉睡时取消该轨 held 残留 |

红蓝用同一个几何与时间配置，只镜像方向和换色：红为暖白→珊瑚 / 粉→微紫透明，蓝为冷白→青蓝→淡紫透明。暖冷感允许不同，峰值与覆盖面积按相同可读性目标校准。

### 5.3 Shader / 网格实现

- 每侧一个轨道根，四段判定带 + 五条共享辅助边；状态来源统一。旧 LaneIndicator / Rail 只保留事件适配或被替换，不能两套 Renderer 重叠。
- 光芯、软晕分别计算。局部 UV 的前向 `u` 控制长度衰减，横向 `v` 控制软边，采用平滑连续函数；尾部最后约 25% 完全归零。形状中心线保持直线，柔和的是透明边界。
- Hit 初始延伸约可用半场宽度的 45%，近端宽晕约 16–28 px 参考；均是小样调参起点。Press 更弱，Hit 更亮、更宽。不是放一块硬矩形再依赖 Bloom 模糊。
- 细芯用受限加法，宽晕用低强度透明 / 受限加法；避免多层把原地面冲成白色。当前中心墙已有强光，不提高全局 Bloom 来解决新轨道问题。
- 相邻命中共享边取最大包络并限幅；同轨高频命中从当前强度接续，不无限相加。
- 地面偏移只用于避开 z-fighting；ZTest 保持合理遮挡，不能 Always On Top 穿透角色。排序结合场景 AlphaTest、透明音符与中央墙校准。
- Linked 音符按实际覆盖的两轨点亮两段，边界仍共享；Hold 按本次节点的 `nodeLaneSpans`，不使用整条链最大宽度错误扩亮。展示上下文补充 nodeIndex；不把一次成功重复计分两次。

## 6. 手绘 HUD 与动效

### 6.1 排版与资源

以 1920×1080 为设计坐标、CanvasScaler 等比适配。顶部 HP / 分数靠安全区；Combo 保留当前“判定线与分界之间”的动态世界锚点。评价从实际事件位置投影。屏幕坐标用 Canvas 的真实 RectTransform / camera 转换，不能默认所有 Canvas 都中心锚定。

手绘数字制作 0–9 共用字形，HP 与 Combo 可按队伍色着色，分数奶油色；保留纸感亮度细节。HP、COMBO 与六种评价可用专门字样 Sprite。先校验 1、4、7、9 的识别和基线、字距、进位空间。分数数字槽使用稳定 advance，避免每次更新整组横跳；位数增长允许整体有限重排。

### 6.2 HP：伤害保留，治疗新增绿色区间

| 项目 | 方案 |
|---|---|
| 真值 | ScoreManager 的当前 HP / maxHP；数字当帧更新，326 只是示意 |
| 扣血 | 主条回落、黄色损血虚条、闪光、轻震 / 回弹、水面扰动继续保留 |
| 初始节奏 | 主条 .8s；黄虚血等待 .25s 后 .7s 追平；闪 .5s 中前 .06–.09s 较强；回弹 .3s；波纹 .55s |
| 风格优化 | 替换为手绘曲带遮罩；降低塑料表面反光，收小原大幅 punch，初始上限约 1.12 |
| 回血 | 真值即时增长，新增区间先显示绿虚血；队伍色实条追上，绿区间归零消失；初始追平约 .45–.6s |
| 连续治疗 | 从当前显示进度接续并扩大到最新目标，不回到旧起点；满血或实际增量为零不播放 |
| 连续伤害 | 损血虚条从当前可见高水位接续，不跳回过期数值 |
| 治疗 / 受伤交替 | 切换到最新事件方向，清掉另一方向过期虚条；新动效从当前显示值开始，真值始终准确 |

**实现细节：**主条、黄虚血、绿虚血都用同一主体 alpha 遮罩。主条在 `[0, displayedFill]`；伤害虚血仅在主条与其高水位之间；回血虚血仅在显示实条与当前目标之间。数值 clamp 到有效范围。方向改变时先确定新的区间和起点，再切包络，不能同时留下黄色与绿色重叠带。当前 `SetFill` 中以 `Max(currentFill, oldTarget)` 处理起点的做法需要拆分，不能原样用于连续回血。

曲带宽主体承载血量，细尾和与分数连接的装饰独立固定；右侧镜像。用遮罩内局部横坐标推进，不能缩放整条曲带或用 UI Filled 拉断固定尾部。保持已有 UI stencil / RectMask2D 裁切兼容；atlas 采样 UV 和 0–1 填充 UV 分开。首版主体遮罩可独立纹理，减少图集旋转 / 裁边错误。

### 6.3 分数

- 变化的数字位以旧字轻上移淡出、新字轻入位替换，约 .14 秒，轻回弹不超过约 1.04；不滚动中间虚构分数。
- 两侧分别更新。同值无动画；同帧多次加分合并显示最新值，原计分事件仍完整结算。
- 初始化、补分 / 追平等静默同步不播放得分庆祝；不依赖只在部分业务路径触发的 OnScoreGained 来维持真值。
- 高频更新中断旧位动画并接续当前状态，尾迹最多一代，进位不重叠遮住新值。

### 6.4 Combo 正常增长与 V10 断连

正常有效增长：数字 .97→1.07→1，侧弧短暂呼应。缩放作用数字子节点；数量变化不挪动态锚点。非零技能削减用收束换字，不做成功弹跳。

**V10 已批准规则：**数字确实被大裂口扯成块，不保留完整中央核心；中央碎块较大，向外中等，外缘更细碎。大小层次是原块状撕碎的细分，不能做成周围撒纸屑、毛边剥蚀、灰烟或石块爆炸。红蓝同模板、同时间，只在灰化前颜色不同。

| 时刻 | 要求 |
|---|---|
| 0.00s | 逻辑已清零；保存旧数字的真实字形和排版用于退场 |
| 0.05s | 轻微横向牵扯，主裂口打开，外缘出现少量二级断口 |
| 0.13s | 主体断开成块，中心大 / 向外中 / 边缘小的层次清晰，逐渐灰化 |
| 0.23s | 同一组碎块继续少量分离并淡出，小块稍早淡去；不换一套随机碎片 |
| 0.30s | 全部消失；没有“0”、残影或常驻装饰 |

COMBO 标题、侧弧、两枚叶片只淡出。旧值为零不生成动作。新成功事件立即显示新 Combo；旧碎片快速回收，旧协程不得隐藏新数字。

**可行制作方法：**

1. 使用正式 0–9 字形图集的真实 UV；建立退场专用 `MaskableGraphic` 网格，显示当次数字，而非 55 的固定图。
2. 在整个数字组的局部平面中设置几条不规则主断裂，使裂口穿过字身；在其基础上建立层级分片，按距数字组中心的位置加密外侧切分。
3. 分片多边形与各数字 quad 相交后，保持原纹理 UV。透明区域由原字形 alpha 剔除，不能渲染整个矩形碎片。中心大块仍被主断裂切开。
4. 子片初期跟随父片，后期拉开少量，形成连续的大小层次；避免每帧随机噪声改变裂口。灰化由同一参数驱动，哑光浅断口边只保留极薄宽度。
5. 首版每个数字组约 18–30 个有效片，长数字可有限增加并设上限（初始 48）；按实际字形检查，不能为了限数丢失笔画。不是每个数字各生成几十个 GameObject。
6. 一个 UI 网格承载该组碎片，缓存模板 / 三角化结果；每帧只更新片变换、颜色、透明度。无需实时截图、CPU ReadPixels、Compute Shader 或把整张字库设为 Read/Write。
7. 首个小样覆盖 1、8、55、100、12345，确认细字、大孔洞、重复数字、进位后宽度都能成立。图稿只定义美术，不替代这个过程。

### 6.5 评价 UI

六套正式字样 PERFECT / GOOD / CLEAR / PASS / YES / MISS；BREAK 使用 MISS。奶油手写字与短细拖笔，少量本方色；MISS 减色和较弱下沉，与成功区分。不增加重边框和大面积底牌。

初始寿命 .4–.55 秒；在真实判定点附近偏移约 12–20 px、轻上移约 12–18 px。技能清屏在被清节点实际位置，不统统堆到判定线。普通成功次数、合法 Hold 节点数保持原值。

使用池化对象，先配置字样和基色再启动。对同一次 ReportJudge 的重复直调用收敛为一条路径；视觉队列过密时提前淡出旧条目，不能删业务事件。初始化 / 失败不会误用成功色和成功光。

## 7. 技能语义按钮、输入与锁定

### 7.1 语义和设备适配

上勇气、中守护、下坚韧；手绘开口环 + 专属图案 + 一条低亮静态连接线。对应旧序列 Left / Down / Right，A / B / C 的原解析含义兼容；保留枚举整数值和存量序列数据，不直接改名重排导致资源含义变化。

输入入口统一为“本方 + 语义动作”。键盘读取实际绑定，触摸点击同三个图案，图案不随键位改变。当前已查路径只有技能硬编码方向键；项目虽有 Input System Actions，但尚未在已审查路径中发现完整玩家技能改键接口。实施先对接已有设置；若确无入口，补最小三动作绑定配置及保存 / 冲突提示，不扩大为整套游戏输入迁移。

当前非空角色配置序列包括 ↓↓←、←←↓、↓→←、←↓←、→↓→、←←←；前缀重合是正常情况。所有匹配角色可一起呼应，不等于同时释放全部技能。当前完整匹配选择一个技能，首版保留单次释放；候选多义时使用稳定阵容 / 槽位顺序，记录碰撞，不能依赖 FindObjects 的未排序结果。

### 7.2 三类结果与状态机

| 状态 / 结果 | 表现 | 输入规则 |
|---|---|---|
| Ready + 有有效前缀 | 当前图案轻压 .95、提亮，约 .14s 恢复；所有匹配角色各播一次原 SkillSelect | 可继续输入；无额外确认灯 / 前缀进度 |
| 无任何可响应角色 | 清序列，三个环 / 图案收束、减色、恢复，约 .24s | 进入 Resetting，锁本方技能输入；四轨照常 |
| 全序列完成且技能已提交释放 | 最后一步并入按钮组轻舒展（最大约 1.04）、奶油连接流光；约 .30s | 进入 Confirming，锁本方技能输入；结束 Ready |
| 锁期收到输入 | 不补播、不闪、不改序列 | 丢弃，不排队、不重启锁时长 |
| 前缀超时后下一步到达 | 清旧前缀，当前步按新起点匹配 | 沿用 inputInterval=1.2s；超时本身不新增重置锁 |

按下反馈就是该步成功反馈，必须取得匹配结果后播放。无人匹配时不先闪成功再报错。一个角色有多个候选槽时 SkillSelect 按角色去重；完整释放角色的 SkillStart 优先，其他匹配角色仍可呼应。

### 7.3 释放提交与异常边界

- 将 BeginCast 提供为 `TryBeginCast` 返回结果或等价提交事件；保留必要兼容入口。条件失败 / SkillStart 被高优先级动画拒绝时，不进入 Confirming，也不消耗能量或占槽。
- 只有进入有效施法阶段、既有提交工作完成后，UI 才宣告释放成功。匹配筛选与释放前校验复用同一“可响应 / 可释放”条件，避免沉睡条件口径不同。
- 极少数“匹配后提交失败”：清掉已完成序列，只保留已成功的单步反馈，不冒充无人匹配错误；不播整体成功，记录拒绝原因，不自动排队重放技能。
- 两侧有各自输入状态；AI 经同一门禁，懂得 IgnoredLocked / Rejected / Accepted / Triggered 结果。对方输入不闪本地按钮；本方 UI 锁不冻结对方。
- 表现锁仅覆盖这三个技能动作，不影响节奏按键、已启动技能运行、人物自身动画时序。无实际本地显示的一侧，状态时长仍由同一配置决定，不依赖 Canvas 是否启用。

### 7.4 触摸与连点细节

- 保留当前点击提交时机（Click），PointerDown 只记录起始资格和指针。不要同时在 Down 与 Click 各提交一次。
- 锁内开始的触摸，即使抬起时已解锁也不提交。一个有效输入进入锁后，同帧后续输入立即被门禁拒绝。
- UI 指针从按下到结束归 UI；取消 / 拖出按钮不触发成功。场内已按住音轨的指针若转入 UI，先正确释放旧轨，不把简单全局 return 留成卡键。
- 其他手指可同时打谱；控制 UI 触摸与模拟鼠标事件重复，避免一次触摸算两次。
- 视觉和热区分离；安全区、横向窄窗口下仍可点中。装饰图和叶片关闭 raycastTarget，不能挡住场地。

## 8. 正常背景、过热、断过热

### 8.1 正式资源与场景关系

制作自然明亮的常态后景，衔接当前树和场地；过热第一层与超级过热第二层采用用户选定的暖色植物插画。局部可有队伍色点缀，不能把整幅插画红蓝染色。

布景占场地后方森林区域，玩家能看出完整背景轮廓。原地面、原场景件、音符和角色作为构图锁定层；画稿使用原相机截图套位，不生成重画了全场的“替代截图”。两个阵营各自控制，整体连接处要连续，无方形接缝。

每层资源至少拆稳定主画、少量可摆动枝叶、发光花 / 点光遮罩，移动后会露出的底画必须补全。首版每个活动层只选 2–3 组局部运动，主轮廓稳定；按根部 1–3° 小幅摆动、花灯低幅度呼吸，循环约 4–6 秒且位置与速度连续。其观感是插画内部循环，不是整个背景浮动或呼吸缩放。

### 8.2 状态表

| 状态 | 常态后景 | Fever 层 | Super 层 |
|---|---|---|---|
| None / 编辑默认 | 显示 | 禁用 | 禁用 |
| Fever | 显示 | 升起后循环 | 禁用 |
| SuperFever | 显示 | 保持循环 | 前方第二层升起并循环 |
| Super→Fever | 显示 | 保持 | 降下、禁用 |
| 任一活动态→None | 显示 | 退场、禁用 | 退场、禁用 |

进入初始约 .5s，退出约 .45s；反复切换从当前位姿继续。直接 None→Super 时两层都正确出现，不能依赖先触发 Fever 事件。

**断过热表现：**失败当帧逻辑退出，花灯亮度在约 .08–.12s 收掉，局部枝叶循环减幅；活动布景随后顺势降下回到常态，约 .45s 完成。超级状态两层回落略错开约 .04s，仍在同一退出窗口结束，避免硬切成空白或砸下黑幕。不新增大字、全屏红闪或烟团。原状态 None 时不播放假退出。短时间重新过热，从当前画面接续新入场，旧回调不得禁用新层。

### 8.3 渲染、隐藏、相机

- 独立 `FeverBackdrop` Prefab / 材质，明确引用 URP 透明 Unlit Shader 和贴图；不复用写深度、白色键裁切的 `M_SceneProp`。花灯亮部保留，不被当近白背景裁掉。
- 底部 Pivot / 锚点固定，面板朝向实际游戏相机；检查正反面、缩放与构图边界。相机变化时再更新朝向，避免每帧旋转导致根部滑动。
- 隐藏不是“把大图放地下就算结束”。使用相机下校准的揭示裁切边界配合真实场地遮挡；待机 Renderer 关闭，Awake 即设置，编辑态场景序列化为 None，不等 Start 才移走首帧可见物。
- 过热两层之间采用显式排序；与原树木、AlphaTest 地面仍以实际深度关系处理，不能认为 sortingOrder=-70 就必然在所有 Renderer 后方。必要时细分稳定的前 / 后景平面，不能将布景设成穿透角色的覆盖层。
- 去掉 bottom-30% 裁切、程序 BuildBackdrop 色板、整幅临时染色；禁止复用 Fever 资源作普通背景。预览开关与运行时状态分开，退出预览恢复 None。
- 资源直接序列化引用并随构建带出，不依赖 Editor AssetDatabase 或偶然 Shader.Find 才能加载。失败层禁用并给出明确诊断，常态后景继续可见。

## 9. 场内光影与卡通化

当前 SceneProp 是贴图假光照，GroundEdge 有自己的着色与主光阴影分支；它们不等于全部支持常规 PBR 灯。先保留既有光照 / 溶解分支，新增统一且可关闭的局部光影层。

1. **原地面上做色光分布**：少量暖光落点、偏冷阴影区，使用受场地范围限制的世界空间遮罩；只调局部颜色与明暗，不换地面图片。可在地面材质专用分支乘 / 混合，不依赖全屏雾。
2. **接触阴影**：确实浮起的场景件加柔和接地影；与现有 BlobShadow / 实时阴影重叠前先核对，已有就不加第二层。地面投影贴片保持贴地，避免压到音符和角色脸上。
3. **场景件协调**：需要响应同一暖光时给原件材质受控的世界空间颜色影响，保留 territory clip / 世界溶解和原像素 alpha，不直接替换全材质。角色默认不加新厚描边或重调色。
4. **背景与前景分层**：后景适度降对比但保留色彩，游戏场地保持可读；光源位置与插画花灯 / 林隙合理对应，不全场随机撒亮斑。
5. **卡通化**：先通过新插画、统一色盘、柔和局部明暗达到手绘感。必要时给环境材质增加克制的曲线 / 色彩调整；全屏色阶、粗描边、重 LUT 暂不默认加入，避免改坏角色、HUD、中央墙。
6. **雾**：关闭旧自动生成入口，默认无新增雾。只有后景确实需要空气层次时独立增加很薄局部层并做有 / 无对照；不加入大面积灰黑遮罩或强制体积 raymarch。

特效软晕由自身 Shader 保证；全局 Bloom、SSAO、色调映射不作为修补硬边的代用品。HUD Overlay 不自动受场景 Bloom 影响，HUD 高光通过自身素材 / shader / 动画实现，避免为此迁移全部 Canvas。

现有场景有多份序列化 UI / 测试组件，只替换实际 BattleVisualsController、ScoreManager 绑定对象；不按名字全删。保留旧 Prefab / 材质及 .meta 可回退；本轮不自动提交或推送 Git。

## 11. 素材制作与性能约束

完整逐项资源规格见 [V11 素材制作清单](<D:/unity/plan go/Musical Sprite/DesignPreviews/visual-assets-production-v11.md>)。

- 不采用整张概念图裁出带背景的 UI；重建独立透明层、共享数字字形与遮罩。当前图片是画风依据，不是直接可播放的帧序列。
- UI 基础着色纹理按 sRGB 导入，纯 mask / 数据纹理按 Linear；Straight Alpha 与材质 Blend 匹配，边缘颜色外扩，避免黑边 / 白边。不是在透明外沿填黑再压缩。
- 自定义 UV 的 HP / 数字资源首版使用稳定的 Full Rect / 禁旋转图集；atlas 纹理坐标与局部形状坐标分离。显示版字形可复用图集，撕碎不能误用 tight mesh 的矩形 UV。
- UI 不开 mipmap；远景世界贴图是否开 mipmap 按缩放闪烁对照决定。UI 字形压缩先保真，世界资源再按目标平台压缩，不未经观察统一重压缩。
- 不制作全屏 30fps 大序列作为过热主动画。2D 拆层 + 网格 / transform 循环更可控；需要局部逐帧时仅给小光花，用小图集。
- 一张 2048² RGBA32 基础级约 16 MiB；2048×1024 约 8 MiB；全 mip 约再增加三分之一，图集、压缩及平台格式会改变实际占用。这是资源预算依据，不是运行内存测量。
- 不为每个字或每帧新建材质，不在每次命中 Instantiate / Destroy 整组 UI；池化评价和退场实例。动态图层分离 Canvas，避免动一个数字重建全 HUD。
- 每侧五条边界共享；重复命中按包络覆盖。关闭的背景停止自身 Update / 动画与渲染；不冻结 FeverManager 业务。
- 新 Shader 明确 URP Pass、混合与深度规则；UI stencil / clipping 完整。MaterialPropertyBlock 与材质实例的批处理代价按实际路径比较，不声称使用 MPB 自动获得 SRP Batcher 合批。
- 压力场景为双侧四轨同时亮、两边超级过热、连续评分与断连。记录相同画质基线的 CPU / GPU、Draw Calls、GC 与峰值纹理；没有实际设备数据不承诺 FPS。

## 12. 实施后的完成标准（本轮尚未执行）

1. **首帧与引用**：编辑 / 开局均无粉色与场外叠幕；活动布景默认 None；正常背景独立；正式资源不靠 Editor 才存在。
2. **四轨**：每半场四段、五边；全部对应真实判定位置；红蓝同形，几何直，渐变柔，远端归零；无中轴亮线、黑框灯座、硬远端封口。
3. **输入 / 命中**：空按有中性反馈，Hit 更强；按住回落正确；相邻 / Linked / Hold 节点无扩错轨或共享边过曝。
4. **HP**：伤害原反馈保留；绿仅表示新增 HP 区间；连续治疗、反向打断、满血与真值同步都正确。
5. **分数 / Combo**：同值和另一侧不误跳；位数变化可读；V10 碎片来自实际数字，有大小层次；0 不碎，新连击不中断显示。
6. **失败**：MISS / BREAK 同功能、计数和倍率当帧清；各自生命周期不重复上报；普通成功角色动作不被失败触发。
7. **评价**：YES 等字样齐全；技能清屏没有双播；合法多节点评价不被误吞。
8. **技能**：成功按下即成功反馈；多角色前缀呼应去重；实际释放才整体确认；错误 / 确认期锁本方技能，节奏和另一侧继续；锁内起手跨解锁抬手不提交。
9. **设备**：改键映射保持语义、旧序列兼容；键鼠 / 多指触摸不双触发或穿透音轨；暂停 / 失焦 / 取消不留 held 状态。
10. **过热**：双侧独立、None→Super / Super→None / 快速反复状态连续；断过热降下；循环无接缝，底部隐藏真实有效。
11. **原内容**：地面、场内摆件、角色、能量槽、中央分界、溶解无非预期替换；既有角色施法 / 命中动画优先级保留。
12. **构建 / 负载**：实际主相机 Renderer 下正确，运行包可加载；资源压缩与移动触摸需在实际目标上检查，不只依靠编辑器大图。

至少交付实际常态、按下、红蓝同轨 Hit、受伤、治疗、Combo 断连、Fever、Super、断过热和技能重置 / 确认的帧或短录屏。动画时长与亮度可在这些实机对照中微调，状态语义与已批准造型不随意改。

## 13. 尚未完成 / 不应假定已批准的部分

- **技能三个图案的具体画稿**：语义、顺序、反馈已确定；火苗 / 护种 / 破石芽只是制作建议，需用实际图确认可识别性。
- **正式分层素材**：字库、曲带遮罩、六评价、背景及循环层尚需制作；不能把现有生成图标成生产资源完成。
- **粉色的实际根因、各 Shader 的运行和构建结果**：本轮静态证据不足，阶段 A / B 先验证；不会先宣布已修好。
- **小样的美术还原度**：尤其碎块尺度、曲带回血、按下与 Hit 的软边。技术路线明确，实际参数需实机小样校准。
