# V7 光效结构重建与验证

本轮保留已认可的基础素材、UI 排版、Combo 位置和血量规则，重建血条与入场渲染路径。没有保存 SampleScene；旧 HP、旧分数继续保留并隐藏。备份位于 `.codex-backups/ui-fx-rebuild-v7-20261101/`。

## 根因与实际修改

| 原问题 | 原因 | V7 处理 |
| --- | --- | --- |
| 黄绿虚血像胶体、多层厚边 | 实体、内部亮带、边光和泛光混在同一 shader 中重复叠加 | 实体色只绘制一次；独立 additive Graphic 负责刻度核心、近光、远光和细边光 |
| 刻度与色块边界不吻合 | 颜色裁切和发光采用不同边界算法 | 两个 shader 共用 RibbonBoundary.cginc，CPU 由实际血条上下轮廓求同一个有限曲线截面 |
| 大块白光、破坏头像环与月牙间隙 | 每个部件各自扩光，重叠处堆积 | 所有原部件先做 max-alpha 轮廓合并，再生成统一近光、远光；只渲染一套加载轮廓 |
| 加载头部不明确 | 白色整段提亮，前沿没有独立光源 | 前沿沿实际曲带中心运动，包含细高亮截面、热点和局部光晕；完成时一次切回常规色，与前向碎光同步 |
| Combo 只数字灰化，其他部件残留 | 数字碎片与标题、弧线、叶片使用不同退出逻辑和贴图 | 对数字和装饰分别抓取原图集快照，使用同一时钟、灰化和渐隐；新连击不会取消正在退出的快照 |
| 撕碎结束突兀 | 短时退出、快照被新事件替换 | 总时长 0.75 秒，先快撕开再减速；最后约 0.41 秒渐隐；最多四组退出快照同时存在 |

## 血条状态语义

- 红方血量从左向右填充，蓝方从右向左填充，蓝方受伤从左侧开始扣除。
- 血量值立即更新；变化区闪白一次，红方暖白、蓝方冷白。黄绿虚血是实色，不用 alpha 淡出代替减少。
- 损血：黄色变化区延迟后缩短，刻度跟随旧显示血量向真实血量移动。
- 回血：先出现绿色变化区，刻度随绿色区域收缩向目标移动，绿色最终被常规血色接替。
- 刻度常驻时收在血条内部；运动时增亮、伸出并带局部光晕。实体边界与刻度完全使用同一几何定义。
- 使用解析临界阻尼，连续同向血量事件保留速度；反向事件通过局部白闪衔接，不直接传送刻度。
- 归零爆开只在刻度抵达零点后触发；对局失败等待这个时刻。
- 濒危仍为降低亮度的暗闪，不叠加强白闪。

## 入场

初始无 UI、无分数。头像白色占位、框、叶片、HP 数字及原曲带由贴形白光推进生成。自定义头像不绘制定制内容动画；白色占位完成后恢复实际头像。推进约 0.78 秒，完成衔接约 0.10 秒。加载轮廓不包含分数。常规 UI 在完成拍点接替白色轮廓，避免两层透明交叉淡入造成中间态发灰。

统一轮廓生成曾测得约 400ms/边，不能放在正常开局冷生成。现已预烘焙两边默认布局缓存，运行时校验布局和血量字形 key。本次实际场景命中缓存：红/蓝约 0.166ms / 0.119ms（仅该机器该次测量）。自定义布局或初始血量改变时允许一次重新生成，不逐帧重算。

## V7b：光晕可见性修正

上一轮光晕强度不足，且入场的普通 alpha 混合无法在复杂背景中表现光照。入场改为单次预乘覆盖＋独立辐射 RGB（Blend One OneMinusSrcAlpha）：实体 alpha 只决定轮廓覆盖，轮廓外 alpha 为零但 RGB 仍可加亮背景，不依赖相机 Bloom。保留原来的 max-alpha 轮廓缓存，无需重烘焙。

刻度增加白色近光与队伍色远光；运动近光半径 3.4、远光 11 UI 单位。黄绿虚血增加软边光，实体仍不透明。变化区白闪同时发出柔光。色块两端的柔光改成二维距离衰减，避免增强后出现方形截边。入场轮廓与头部均增加暖白光晕。未修改血量时序、排版、基础 UI 或 Combo。

`glow-review/before-after.png` 是相同预览状态的修复前后截图；`glow-review/entry.gif`、`damage.gif`、`heal.gif` 是最新实机场景原速序列。根目录对应动图也已更新。`glow-regression.log` 和 `glow-live-capture.log` 记录本次验证。

## V7c：运动节奏、同色光和数字回弹

- 黄色色块改为用户新参考中黄区的 RGB 中位数（250,191,64），即 #FABF40；替换原偏褐黄色。回血绿色保留。黄绿变化时，运动刻度和近远光均跟随变化区色相，刻度细核心仍为偏白高亮。白闪实体仍保留既定队伍白色差异。
- 血量移动采用初速度匹配的解析临界阻尼，开始快、随后减速；损血移动时长 0.64 秒、回血 0.70 秒。保留既定白闪 0.11 秒、停留 0.10 秒。连续同向事件保留速度，反向和归零规则不变。有限结尾只校准不足 0.3% 的尾差。
- 新共享组件 DampedNumberPulse：约 0.04 秒压缩、0.07 秒回弹、之后阻尼回稳，总时长 0.42 秒。生命数字幅度略弱于分数和 Combo。真实数值事件触发，不依赖 OnScoreGained，所以其他途径的分数变化也有反馈。重复触发保留当前尺寸、速度，不瞬间跳小。各数字围绕整组中心缩放，静态布局和字高不变。
- Combo 旧场景中的 growthDuration=0.16、growthPeak=1.07 在运行时升级为新默认节奏，无需重写场景；自定义其他取值继续生效。数字撕碎、装饰灰化与离场位置不变。
- 入场完成不再额外等待 entranceResolve；此旧序列化字段隐藏保留兼容。推进曲线取消末尾长时间减速驻留，UI 变色、前向碎光、音效在完成帧同拍发生，跨帧时只推进真实超出的时间，不双算 dt。

验证增加：血条前 50ms 位移大于尾段 50ms 的三倍；数字压缩、放大、最终恢复、重复触发连续性和帧率一致性；入场完成前一刻不可完成，到终点后立刻完成且粒子年龄正确。真实 Play 模式通过扣血回血、归零等待与重开测试。

最新动图：motion-v7c/entry.gif、damage.gif、heal.gif、number.gif、number-combo.gif。均来自当前 Unity 1920×1080 原生 GameView 逐帧渲染，按模拟时间播放，末尾额外停留0.6秒供审查。number-keyframes.png 展示数字完整尺寸变化。根目录血条动图也已同步。基础 UI 素材、整体排版、Combo 位置、背景布景未修改。备份：.codex-backups/ui-motion-v7c-20261101/。

## 2026-11-02：黄绿条去描边与 Combo 下部渐变

黄绿外光改为填充区域的柔化覆盖，使用原血条素材 alpha 排除实体内部。移除 edgeDistance 线状发光与其白色混合项，保留刻度独立高亮与同色光。白闪的外光也使用区域覆盖，避免瞬间又出现上下两条白边。旧 opticalEdgeStrength 隐藏保留；新 pendingHaloStrength 只控制实体外柔光。

Combo 原数字增加 24% 的下部暗色渐变；数字碎片按原字形高度继承渐变，装饰不变。没有改字形、基础位置、回弹、灰化或渐隐时钟。血条1.2秒与绿条优先抵扣逻辑保持不变。

回归与原生GameView捕获均通过。最新截图、原速动图与后续方案位于 DesignPreviews/VisualPolish-20261102/。下一步先收敛血条的亮度主次、暂停/恢复、连续变化和小尺寸可读性；随后按最新确认内容处理评价UI、技能语义图标和输入反馈、自然背景与局部光影，最后整局适配。用户认为其余现有模块无大问题，本轮不对它们进行大改。
