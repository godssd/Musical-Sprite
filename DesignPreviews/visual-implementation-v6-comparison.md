## 三、断 Combo：新增动效

### 3.1 当前实现与 V5 的不足

当前 `ComboDisplay.ResetCombo()` 把数值设成 0 并立即清空文字，没有专用退场动画。V5 提出短暂收起、淡出，但成功与中断的区别还不够明确。

V6 保持已选的完整 Combo 造型，以数字、侧弧、花叶表达中断。数字不用碎裂贴图，原手绘字形仍保持完整。

### 3.2 V6 时间轴

以下是制作起点，单位秒；位置按 1920×1080 参考界面的等比 Canvas 单位计算。

| 时段 | 画面表现 | 逻辑 |
|---|---|---|
| t=0 | 当前 Combo 立即停止成功回弹；捕获退场数字与装饰的当前姿态 | 真实 Combo 当帧清零；之后得分和新连击都按新状态处理 |
| 0–.05 | 数字轻压至正常高度的 .96、宽度约 1.02；队伍色减饱和并略降亮度。侧弧原本的完整弧形出现一个细小缺口 | 不闪白、不先放大；与成功弹跳区分 |
| .05–.16 | 数字向下移动约 6 px，透明度降到约 .35；左右侧弧各向外移约 4 px、向下约 3 px，同时退去 | 保留完整数字的短暂退场残像，不显示假的“0”或倒数 |
| .16–.24 | 数字、COMBO 标题及短弧完全淡出 | 该侧不再显示连击数 |
| .06–.28 | 花叶向内收拢约 4–6 度并渐隐；花草底座只淡出、不位移、不坍塌；最多两枚原有小叶点从侧弧附近短距离落下 | 不新增烟雾、碎石或漫天粒子；每侧一个动作包络 |
| t=.28 | 装饰组隐藏，所有变形恢复默认基线供下一次使用 | 等待下一次有效命中 |

花叶动作与数字动作同时收尾，不让底座残留成一个假的场景物件。红蓝两方使用相同几何、幅度与时间，只更换主题色。

### 3.3 可辨识程度

- 成功：队伍色鲜明、数字向外轻弹、短弧舒展。
- 断连击：数字失色下沉、侧弧出现缺口后退去、花叶收拢。
- 普通技能削减到非零：数字换成较小值、短弧轻收，Combo 继续保留，不播完整断连击退场。
- 仅用局部运动和色彩变化，画面地面、角色、分数与 HP 不参与这一动作。

## 四、断过热：新增动效

### 4.1 当前实现与 V5 的不足

`FeverManager.OnNoteMiss()` 已立即清零内部计数并切至 None；状态改变后，当前 `FeverSceneryController.MoveTo()` 用 fallDuration=.45 秒移动布景到隐藏位置。因此现状是“有降下逻辑，但没有独立的中断反馈”，并非完全没有退出动作。

V5 保留降下。V6 在降下前半段加入插画自身的发光花朵熄灭和动态枝叶回稳，让状态结束更清楚。基础森林仍然自然可见。

### 4.2 普通过热退出

| 时段 | 画面表现 | 逻辑 |
|---|---|---|
| t=0 | 停止新增循环光点，现有光点准备收尾 | FeverState=None，倍率立即回正常值；不能等布景退完才生效 |
| 0–.12 | 本方过热插画的发光花朵由上方到下方错开约 .02 秒熄灭；亮度回到未发光的插画颜色。枝叶从当前循环姿态轻收回稳定姿态 | 保留绘画本色，不把整个背景染灰、染黑或变透明烟片 |
| .06–.45 | Fever 布景沿原入场路径反向降回遮挡区域；底部先被场地遮挡，轮廓自然退出 | 以当前位姿为起点，快速变化时不瞬移 |
| .12–.22 | 原有零星光点淡出完毕，无新的光点飞向中央 | 不影响常态森林的灯光或场内固定暖光 |
| t=.45 | Fever 层完成隐藏并停止更新 | 常态背景保持 |

### 4.3 超级过热退出

两层都退出，逻辑直接到 None，**不先按普通 Fever 结算一段时间**。

- t=0：两层循环发光都开始衰减；Super 前层先降下。
- t=.06：Fever 后层开始降下，形成很短的前后层次差。
- 前层约 .42 秒、后层约 .50 秒完成隐藏；总退出时长约 .50 秒，不连续播放两段 .45 秒动画。
- 只有本方过热布景的花灯熄灭；正常场景照明、对方布景、角色能量与 HUD 配色保持各自状态。
- 普通过热与超级过热的区别来自退出层数和纵深，不通过全屏闪光、相机震动或黑幕强化。

## 五、断 Combo 与断过热同时发生

### 5.1 同一失误的一条节奏

| 时间 | Combo | 过热背景 | 评价与判定光 |
|---|---|---|---|
| 0 | 逻辑清零，取消成功回弹 | 状态与倍率立即复位 | 失败判定处显示一次 MISS；失败轨不触发成功光 |
| 0–.08 | 数字失色、侧弧开始退去 | 花灯开始熄灭 | 若该轨还有旧命中光，快速退去；仍按住则回到柔白按下态 |
| .08–.24 | 数字下沉并消失 | 布景开始降下 | MISS 保持可读，随后淡出 |
| .24–.28 | 花叶收尾、整组隐藏 | 布景继续退出 | 不追加第二个 FAIL、BREAK 或大警告框 |
| .28–.50 | 等待下一次有效连击 | 回到普通背景 | MISS 约 .45 秒内退完 |

不让 Combo、评价、背景各自触发一次强闪。用户应读到同一个原因：这一拍失败，连击和过热同时结束。

### 5.2 哪些情况触发

| 真实事件 | 断 Combo 动效 | 断过热动效 | 其他 |
|---|---|---|---|
| MISS 或 BREAK，旧 Combo>0，旧状态为 Fever / Super | 播放 | 播放对应层数 | 该侧逻辑同时复位 |
| MISS 或 BREAK，旧 Combo>0，旧状态 None | 播放 | 不播放 | 不凭空创建一层布景再退掉 |
| MISS 或 BREAK，旧 Combo=0，旧状态 None | 不重复播放 | 不播放 | 正常显示判定 MISS |
| MISS 或 BREAK，旧 Combo=0，但旧状态为 Fever / Super | 无数字可退，不虚构旧 Combo | 播放 | 两套计数可能因技能减连击而不同，要按真实旧状态处理 |
| 技能削减 Combo 但仍大于零 | 仅原削减反馈 | 不由 UI 自行退出 | 沿用原技能逻辑 |
| 技能削减到零 | 播放 Combo 收尾 | 只有实际 FeverState 也退出时才播 | 当前回复确认的是 BREAK；不把它扩大为所有技能都能打断过热 |
| 技能输入错误 / 能量不足 | 不播放 | 不播放 | 只播按钮错误反馈 |
| 初始化 / 重开 / 结束对局清理 / 调试切状态 | 不默认播放失败动作 | 静默同步或普通过渡 | 这些操作不是一次 MISS |

### 5.3 连续输入与打断处理

- 断连击收尾期间出现新有效命中：逻辑立即得到新的 Combo；取消旧数字退场，从当前装饰透明度转入新的 Combo=1。不能等 .28 秒结束才显示，也不能让旧动画随后隐藏新数字。
- 快速连续 MISS：旧值已经为零时不反复生成侧弧、落叶或重置背景退场时间；评价仍按真实判定显示并受可见对象数量限制。
- 过热退场中重新达到条件：停止旧退场，从当前位姿和亮度转为目标状态，不能在动画尾回调中再把新状态禁用。
- 两方同帧失败：各自处理；没有共享的全屏黑闪或全局震动。
- 同侧多轨同帧失败：一次有效的 Combo>0→0 变化、一次 Fever→None 变化分别只播一次，局部 MISS 仍对应各自判定。
- 高速曲谱中同帧先失败后成功，按实际事件顺序结算，最终显示新的连击；先成功后失败则显示清零结果。视觉不能重排玩法事件。
- 暂停、禁用与切场景时清理动作实例；复用时恢复原色、位置、缩放、Alpha 与叶片角度。

## 六、实现接点与逻辑边界

### 6.1 Combo

在 `BattleVisualsController.OnJudge` 明确区分 `MISS / BREAK` 与成功分支：两种失败都清零，不再让 BREAK 落入 `AddCombo(1)`，也不再触发普通成功命中角色动作。既有受伤 / 技能动作仍按原事件运行。

`ComboDisplay` 的数据清零与动画退场分开。接口需接收旧值、新值及原因，例如 Miss / Break / SkillReduce / Reset；清理调用不能误播失败。沉睡等条件是否屏蔽视觉要与玩法状态分离，不能因提前 return 阻止必须发生的清零。

### 6.2 Fever

沿用 `FeverManager` 为状态权威，保留原有订阅者使用的 `OnStateChanged(old,new,side)`。为表现补足退出原因，或在唯一判定协调入口记录原因，不能仅凭看到 None 就猜测“失误”。

`FeverSceneryController` 增加“失败退出”与“静默同步 / 普通过渡”的表现分支，使用旧状态确定退出一层还是两层；两层动作共享一次退出序列。返回 None 的逻辑不能被动画时长延后。

### 6.3 同步与重复控制

判定事件记录 side、lane、rank、事件顺序、源对象和节点信息；状态变化携带前后值。UI 不依赖事件订阅先后来猜旧状态，也不直接再次修改 Fever / Score 数据。

仅一次状态变化产生一次退场。长条不同节点可以产生不同合法判定，不能用“同一个音符对象”作为所有节点共用的去重键。控制背景 / Combo 动画时使用状态版本或等效取消机制，旧动作尾回调不能覆盖新状态。

### 6.4 新资源

复用已选 Combo 数字、两侧短弧与花叶。短弧的缺口通过局部裁切 / 两段独立 Sprite 实现，保持母版轮廓；不另画一套风格。过热发光花朵与枝叶必须在素材拆分阶段独立导出，才能熄光而不把整幅画染暗。

不增加新音效，待用户另有声音设计要求再处理。

## 七、V5 实施顺序的调整

1. **素材阶段**：新增短弧可分段结构、可摆动叶片、过热花灯发光层；造型母版不更换。
2. **轨道阶段**：补失败轨的残留命中光快速收尾；四轨 / 红蓝同形方案保持。
3. **HUD 阶段**：实现 BREAK 与 MISS 清零分支、Combo 失败动作、评价配合、连续事件取消。
4. **背景阶段**：完成 Fever / Super 正常循环和失败退出；关闭旧雾自动生成入口。
5. **整局阶段**：把断连击、断过热及两者同发的实际录屏纳入原完成标准。

主方案尚在对比确认阶段；此处仅规定后续顺序，没有开始上述实现。

## 八、新增完成标准

- BREAK 发生的当帧，Combo 与过热计数清零、过热状态 None；没有残留加成，分数不回滚。
- 画面清楚区分成功弹跳、被技能削减、失败清零三类 Combo 行为。
- 普通 Fever 退出一层，Super 退出两层；正常森林和对方布景不被暗化。
- 同一失误只出现一次组合反馈；不会产生两次 MISS、两次失误闪光或重复落叶。
- 已零连击重复 MISS 不凭空重建装饰；断连击期间新命中能立即接起新数字。
- 没有突然黑幕、灰烟、地面整体染黑、中央墙闪烁、HP 误扣或能量误清。
- 增加实际对比帧：断 Combo t=0/.08/.16/.28；断 Fever t=0/.12/.30/.45；断 Super t=0/.12/.30/.50。
- 录屏覆盖：仅断 Combo、Combo+Fever 同断、Combo+Super 同断、连续 MISS、退场中重建 Combo、两侧同帧失误、技能削减到零、初始化无失败反馈。

以上是实施后拟核对的标准，本轮没有执行这些检查。

## 九、待确认的表现方案

BREAK 断 Combo / 断过热，以及本轮不做雾，均已经确定，不重复征询。

请对比确认：

1. 断 Combo 采用“失色下沉 + 侧弧断开退去 + 花叶收拢”，约 .28 秒完成。
2. 断过热采用“插画花灯先熄灭 + 布景降下”，Fever 约 .45 秒、Super 两层约 .50 秒结束。
3. 同时中断时共用一次节奏，保留一次 MISS，不加全屏震动或大幅闪烁。
4. 整套 V6 是否可作为后续执行方案；其余 V5 模块按第二节表格沿用。

若需要增强中断感，优先加大侧弧位移、数字失色程度和花灯熄灭节奏；不以增加烟雾或全屏遮罩强化。
