# 战斗表现方案 V8：统一失败规则、Combo 撕碎预览与技能成功确认

日期：2026-10-23。本轮交付方案修订与效果图；未修改 Unity 运行时代码、场景或材质，未执行运行测试。

本文覆盖 V7 中失败功能及技能按钮反馈规则。V5—V7 保留作历史对照，未被本文覆盖的素材母版、四轨判定 UI、HP / 分数、自然背景、过热布景、原场景保留与可选雾约束继续有效。

## 1. 用户最新确认

1. MISS 与 BREAK 功能一致，只是触发情况不同。内部可记录原因，玩家看到的失败评价统一为 MISS。
2. 断 Combo 采用数字被扯碎、变灰并消失；没有连击数时不生成该表现。本轮先展示效果图。
3. 按键的按下反馈就是该步输入成功的表现：有角色符合当前输入时，按钮反馈并由所有匹配角色播放专门动画；无人符合则失败重置。
4. 完成技能全部指令且释放成功时，增加按钮 UI 整体成功提示；提示期间不能再次提交技能点击。

## 2. MISS / BREAK：失败功能完全一致

代码核对事实仍成立：`HoldNote.Break()` 发出内部 BREAK，`JudgeFeedbackManager` 将其显示为 MISS。触发差异：普通漏击 / Hold 起手漏击为 MISS；Hold 已起手后未继续正确按住导致断连为 BREAK。该内部原因不应产生不同的玩法奖惩。

统一失败行为如下：

| 行为 | MISS 与 BREAK 的统一结果 |
|---|---|
| 得分 / 充能 | 本次失败不加分、不充能，之前已获得的值不倒扣 |
| Combo | 清零；旧值大于 0 才播放数字撕碎 |
| Fever | 计数清零、状态 None、倍率当帧回到正常；旧状态过热时才播放布景退出 |
| 评价 | 显示一次 MISS，不新增 BREAK 字样 |
| 判定光 / 角色普通命中动作 | 不触发成功光或普通成功命中动作 |
| 额外扣血或惩罚 | 不由 UI 新增；若玩法本身另有失败处理，两者接到同一失败规则 |

节点的失效、残留图形和清理位置按各自音符生命周期执行；不能为统一失败功能就删除 `missReported`，导致一次中途断连又额外上报第二个 MISS。相关消费者统一使用一个失败分类，避免某处只判断字符串 MISS、另一处漏掉 BREAK。

## 4. 技能按钮：三类结果对应三种反馈

### 4.1 一步输入成功

一次实际输入进入序列匹配后，至少有一个可响应角色符合当前前缀：

- 当前被按的图案 / 开口环播放一次成功按下反馈：约 .04 秒压至 .95、轻提亮，再约 .10 秒恢复。
- 所有符合条件的角色各播放一次已有 SkillSelect 动画，允许多个角色同时呼应。
- 若同一角色有多个候选技能槽，不因此重复播放多次同一个角色动画；按角色去重。
- 不另加一套前缀确认灯、输入进度或“Accepted”提示。按钮的这次按下动作就是成功反馈。

这覆盖 V7 的“未经匹配就先播放成功按下效果”：先取得匹配结果，再选择反馈。物理 PointerDown 可记录手势，但不能预先宣告该步成功或和 Click 各提交一次。

### 4.2 无人符合：失败重置

追加本次动作后，没有任何可响应角色匹配：

- 清空本方技能输入，直接播放三个按钮的重置动作；不先播放单键成功高光或角色成功呼应。
- 保留 V7 的重置方向：环线收回、图案短暂收束减色、恢复。
- 初始时长 .24 秒，整个期间锁定本方技能输入；锁期按键 / 点击丢弃，不排队、不延长锁期。
- 锁住技能动作，四轨打谱及已经开始的技能运行继续。

### 4.3 全部指令完成且真正开始施法：整体成功确认

最后一步满足完整序列，且选中技能确实开始释放：

- 最后按键仍有“该步成功”的触感，但其动画并入整体确认，不叠加两次缩放。
- 三个按钮图案 / 开口环同步轻微舒展、提亮；静态连接曲线出现一次短促的奶油色流光，随后全部回到待机。
- 被释放技能的角色播放原有 SkillStart / 后续技能动作；这一帧 SkillStart 优先于该角色的 SkillSelect，避免重复动作互相覆盖。
- 从释放提交成功的当帧开始锁定本方三个技能动作，整体 UI 动画结束后解锁。
- 该 UI 确认不等待整个技能施法 / 附魔 / 攻击结束，也不显示成共享冷却条。

#### 整体成功初始时间轴（.30 秒）

| 时间 | 按钮组表现 | 输入 |
|---|---|---|
| t=0 | 最后一步成功，接入整体包络；不新增大框或文字 | 当帧锁定，清空已完成序列 |
| 0–.06 | 三个图案和开口环同拍提亮，尺度最多约 1.04；保留本方色，奶油亮部面积有限 | 锁定 |
| .06–.16 | 连接曲线从最后输入的按钮位置向其余部分短暂亮过一次；图案稳定可读 | 锁定 |
| .16–.30 | 高光和尺度一起回到常态 | 锁定到结束 |
| t=.30 | 待机，开始接收新的技能指令 | 解锁 |

成功与失败的动作方向清楚区分：成功是轻舒展、亮起后归位；失败是收回、减色后复位。两种状态都不晃动场景、不闪中央墙，也不改 HP / Combo / 能量的真实值。

## 5. 输入状态和边界

拟定输入状态：Ready、Resetting、Confirming。Ready 可以已有有效前缀；其余两态拒绝新的技能输入。

| 当前条件 | 处理 |
|---|---|
| Ready，有有效前缀但未完成 | 单键成功 + 所有匹配角色呼应；继续 Ready |
| Ready，无匹配 | 清缓冲并进入 Resetting |
| Ready，完整匹配且施法已提交 | 清缓冲并进入 Confirming |
| Resetting / Confirming 收到输入 | 忽略，不修改缓冲、不播第二次反馈、不重新计时 |
| 重置 / 确认结束 | Ready，要求新一次按键边沿或有效新手势 |
| 旧前缀超时 | 按原规则清空旧前缀，以本次输入作为新起点后匹配；不凭超时单独加确认动画 |

键盘读取玩家实际绑定，触摸直接提交勇气 / 守护 / 坚韧动作；两者经过同一个入口。锁期开始的手势不能在解锁后通过 PointerClick 补交。UI 动画缩放不改变热区。保留 V7 的 UI / 打谱手势归属与多指释放规则。

每方状态独立。共享入口的 AI 调用也需识别锁期忽略结果；不能将 AI 输入表现投到玩家按钮上。相同完整序列若对应多个技能，本次“多个角色呼应”不等于授权改变为同时释放所有技能；先保持原有完整匹配选择规则，角色前缀动画可以多个。

## 6. 必须修正的真实提交反馈

当前 `ActiveSkillRuntime.BeginCast()` 是 void 方法，存在以下拒绝 / 撤销分支：阶段非 Standby、角色无技能、沉睡、能量不足、技能配置缺失、SkillStart 动画未能启动。`SkillInputUI` 调用后直接返回 Triggered，因此仅收到这个返回结果并不能证明释放成功。

接入方案：

1. 为开始释放返回明确结果，或在完成状态提交后派发唯一的成功事件。兼容现有调用方，不依靠动画名字猜成功。
2. 只有越过拒绝分支、真正提交释放后，才能启动 Confirming、播放按钮组成功反馈。
3. 若完整匹配但实际释放被拒绝，不播放成功确认。应返回明确原因并清理本次未完成的输入事务，按失败重置收尾；配置 / 动画缺失等工程问题另行定位，不用 UI 假成功掩盖。
4. 校验、提交、成功锁的建立应在同一次输入处理完成，避免同帧第二个输入抢在视觉协程启动前进入。
5. 角色原有技能动画和能量消耗仍由技能运行时控制，按钮 UI 不再次调用 BeginCast 或再次扣能量。

技能按钮保留勇气 / 守护 / 坚韧语义及 V7 图案提案，不恢复箭头为主图标。图案具体造型仍待美术确认。

## 7. 更新后的验收补充

- MISS 与 BREAK 在成功 / 失败消费逻辑中的待遇一致，触发来源和节点清理仍正确，一次失败不重复报告。
- 画面上的撕碎效果使用真实数字，零连击不出现，两队使用同一动作，末帧完全退出。
- 有匹配角色才播该键成功反馈；多角色匹配时各呼应一次，未匹配角色不动。
- 最后一步实际释放成功时只有一次整体确认；被拒绝的 BeginCast 不显示假成功。
- Resetting 和 Confirming 都拦截键鼠触摸；解锁后无排队输入、无旧手势补交，打谱仍可操作。
- 成功确认在约 .30 秒结束后即可重新输入技能，不等待完整技能生命周期。
- 快速输入、同帧输入、暂停、禁用、重开时状态和画面一致，旧动画结束回调不能解除新的输入锁。

上述为实施后要检查的条件。本轮仅交付本方案和关键帧效果图，尚未实现或验证。
