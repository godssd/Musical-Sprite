# 技能引用与角色解耦规则（底层逻辑铁律）

> 本文档固化项目一条**不可违反的底层逻辑**：技能与角色解耦。
> 它定义「哪些数值由角色文档决定、哪些由技能库决定」的职责边界。
> **本文档规则未获用户明确「修改」指令，任何人都不得擅自变更字段归属、不得把职责串味（让技能库去持有非技能数值，或让角色文档去持有技能系数）。**
> 配套 schema 说明见同目录 `Characters_README.md`（xlsx 列 → CharacterDataSO 字段）；附魔换色规则见 `Assets/Art/UI/sprites/附魔规则.md`。

---

## 0. 核心铁律（一句话）

**角色（CharacterDataSO / Characters.xlsx）只持有「技能引用 id + 非技能数值」；技能库（SkillSO / Resources/Skills）持有「技能本身逻辑 + 所有系数数值」。**

技能**不绑定角色**：一个技能被谁用、冷却多久、要多少能量、怎么按出来、介绍怎么写——都写在角色文档里；技能自己只管「释放后做什么、系数多大」。

---

## 1. 职责边界

### 1.1 Characters 文档（角色侧）决定的「非技能本身的数值」（共 5 项）

| # | 项目 | 含义 | 取值规则 |
|---|---|---|---|
| 1 | **技能引用 id**（`skillId`） | 决定该角色使用技能库里**哪一个**技能 | 填技能库的 `skillId` 字符串（如 `skill_4_croissant_heal`）；空 = 该能力不存在 |
| 2 | **技能冷却**（`cooldown`） | 引用技能在游戏中的冷却时间（秒） | 填数值 = 释放后再冷却 N 秒；0 / 未填 = 无冷却（立刻可再放）。**主动技能**：冷却从释放结算完毕起算，冷却时间内技能完全不可用，归零后才回到可释放状态（逻辑已实现，见 `ActiveSkillRuntime`）。**被动技能**：同样适用冷却——冷却时间内被动技能完全失效，直到冷却结束（被动逻辑未制作，此为规则预留，详见 §1.4） |
| 3 | **能量需求**（`energyCost`） | 引用技能充满可释放所需能量 | **填数值** = 能量门槛（满能量才能放、释放清空）；**写「无」/0** = 玩家专属主动技能，不消耗能量即可释放（走玩家专属技能逻辑）；**空（未填）** = 被动技能（逻辑与主动不同，目前未制作） |
| 4 | **输入方式**（`inputMethod`） | 引用技能的释放方式（按键序列） | 填序列（如 `←←←` / `AAB`）；空 = 视为被动技能（无需输入，满足条件持续生效） |
| 5 | **能力 x（数字）介绍** | 对引用技能的简单文字介绍 | 仅供阅读/理解，**不参与任何判定**；对应文档「能力1」~「能力5」列组 + 「过热状态」列 |

> 第 3 项「能量需求」三态语义是铁律核心，不得简化：
> - 数值 → 主动技能，需能量门槛；
> - 「无」/0 → 玩家专属主动，免能量；
> - 空 → 被动技能（走另一套逻辑，未制作）。
> 判定见 `SkillSlot.IsPassive`（2026-09-26 修正）：**主动技能 = 输入方式 和 能量需求 都不为空；被动 = 输入方式 为空**。`NeedsEnergy => !IsPassive && energyCost>0`。
> 注：能量需求 空/无 在导入时均解析为 `energyCost=0`（无哨兵区分），可靠判别信号是 输入方式 是否为空；被动技能按定义无输入方式、持续生效。判定**不再依赖技能冷却**，避免与「被动技能冷却」规则冲突。

### 1.2 技能库（SkillSO）决定的内容

- **技能本身逻辑**：`effectType` 路由（Heal / Buff / Bomb / DogHowl / ClearScreen…）、结算方式、附魔/清屏/沉睡等行为。
- **所有系数数值**：伤害率、回血率、附魔音符数、buff 乘子、清屏范围倍率、过热档加成等——全部在 SkillSO 调参面板 / 生成器里维护。

### 1.3 硬约束（违反即视为瞎改）

1. **不得让技能库去持有或决定非技能数值**（冷却 / 能量 / 输入方式 / skillId 引用）。
2. **不得让角色文档去持有技能系数**（伤害率 / 回血率 / buff 乘子等）。
3. 改 `cooldown` / `energyCost` / `inputMethod` / `skillId` **必须走 Characters.xlsx + Character Importer 这条管道**（落进 CharacterDataSO / SkillSlot）。
4. 改系数 / 逻辑 **必须走 SkillSO**（技能库调参面板 / SkillLibraryGenerator 等生成器）。
5. **运行时真相源约定**：非技能数值以角色侧 `SkillSlot` 为准；SkillSO 同名字段（如 `energyCost` / `inputSequence`）仅作「兜底/默认值」，当角色侧 `SkillSlot` 字段非空/有效时以角色侧为准（见 §3 代码实况）。

### 1.4 被动技能冷却（2026-09-26 补充规则）

- 被动技能**同样适用冷却**：技能冷却（`cooldown`）对被动技能也有效——**冷却时间内被动技能完全失效，直到冷却时间结束**才恢复。
- 被动技能不「释放」，其进入冷却的触发方式由技能自身逻辑决定（与主动技能「释放结算完毕起算冷却」不同）；具体如何进入冷却属于被动技能实现范畴（当前被动逻辑尚未制作，此处先固化规则）。
- ✅ 与「主动技能冷却」共用同一 `cooldown` 字段与同一失效语义；不冲突，因为 `IsPassive` 判定已不再依赖 `cooldown`（见 §1.1 第 3/4 项与 `SkillSlot.IsPassive`）。

### 1.5 过热状态 / 超级过热状态（说明类，供阅读）

- 性质：**仅供玩家阅读理解的说明文字，不构成逻辑、不参与任何判定**（与「能力 x 介绍」同性质）。
- 取值来源：xlsx「过热状态 / 超级过热状态」列 → `Character Importer` 写 `SkillSlot.overheatDesc / superOverheatDesc` → 技能库 `Rescan` 展示。
- 技能库里把这两项与技能介绍一并显示即可，无需任何逻辑处理。

## 2. 字段归属对照表（代码实况，2026-09-26 核对）

| 职责 | 字段 | 所在 SO | 真相源 / 兜底 | 说明 |
|---|---|---|---|---|
| 技能引用 id | `SkillSlot.skillId` / `CharacterDataSO.skillId` | CharacterDataSO | 真相源 | 运行时 `SkillSO.FindById(skillId)` 反查 |
| 技能冷却 | `CharacterDataSO.skillCooldown` + `SkillSlot.cooldown` | CharacterDataSO | 真相源 | **SkillSO 已无 cooldown 字段**（SkillSO.cs 注释明示「技能库 SkillSO 不再持有 cooldown」）✓ |
| 能量需求 | `SkillSlot.energyCost`(int) / `CharacterDataSO.activeEnergyCost` | CharacterDataSO | 真相源 | 运行时 `CharacterClass.cs:118` 读 `s.energyCost`（角色侧）；SkillSO.energyCost 仅兜底/遗留，不参与角色能量门槛 |
| 输入方式 | `SkillSlot.inputMethod`(string) | CharacterDataSO | 真相源 | 运行时 `CharacterBattleSystem.cs:120` 先 `ParseInputMethod(slot.inputMethod)`；空才回退 `so.inputSequence`（SkillSO 兜底）✓ |
| 能力 x 介绍 | `SkillSlot.description` / `activeSkillDescription` / `passiveSkillDescription` | CharacterDataSO | 真相源 | 只读，不参与判定；SkillSO.description 同理但属技能库侧文本，二者可并存 |
| 技能逻辑 | `SkillSO.effectType` | SkillSO | 真相源 | 路由键 |
| 系数数值 | `bombDamageRate` / `healHpRate` / `healCombatRate` / `regenPerTickHpRate` / `comboHpDamageRate` / `charmBonusFever` / `charmBonusSuperFever` / `buffCombatMult` / `buffDamageReduce` / `clearOverheatCombatMult` / `clearSuperCombatMult` / … | SkillSO | 真相源 | 全部在 SkillSO（✓ 符合「技能库决定系数」） |

### ⚠️ 代码残留（非偏差，属兜底/遗留，不得据此把真相源挪回技能库）

- `SkillSO.energyCost`（float）：运行时不用作角色能量门槛（角色侧 `SkillSlot.energyCost` 为准），保留仅为字段兼容/兜底。
- `SkillSO.inputSequence` + `SkillSO.ParseInputMethod`：仅当角色侧 `slot.inputMethod` 为空时回退使用（如 AI 槽位只填了 skillId、未填输入方式）。
- 这两处若未来清理，必须**保持「角色侧优先」语义**，不得擅自改为「以 SkillSO 为准」。

## 3. 数据流（引用解析）

```
Characters.xlsx（飞书「角色系统」原表）
   │  Tools > Musical Sprite > Character Importer
   ▼
CharacterDataSO（含 SkillSlot[]：skillId / energyCost / cooldown / inputMethod / description）
   │  运行时 skillId → SkillSO.FindById
   ▼
SkillSO（技能逻辑 effectType + 所有系数数值）
   │
   ├─ 非技能数值（冷却/能量/输入方式/引用）→ 从 CharacterDataSO / SkillSlot 读取
   └─ 技能逻辑与系数 → 从 SkillSO 读取
```

- 角色上场：1 玩家（isPlayer=true）+ 4 队伍（lane 0~3），同 characterId 不重复（见 `Characters_README.md` §3）。
- 进入战斗：`CharacterBattleSystem.InitializeFromData` 把 CharacterDataSO 拆成 `CharacterClass`（activeSlots / passiveSlots 按 `inputMethod` 非空划分）。

---

## 4. 与「描述文本滞后」的关系（重要）

技能介绍文本（能力 x / 过热状态）**仅供人阅读、不构成逻辑**，改文档滞后属正常现象（见用户约定）。
- 文本当前存于 `CharacterDataSO`（导入器写入）与 `SkillSO.description`（技能库侧）两处，可并存。
- 若要让「改文档即时生效」到编辑器技能库窗口，需由 Character Importer 把文档描述同步进 `SkillSO.description`，并避免生成器在重载时覆盖——**具体实现以用户另行下达的「执行」指令为准，本文档不规定其代码细节**。

---

## 5. 全局数值精度（附）

伤害 / 回血 / HP 相关所有战斗数值一律 **`Mathf.CeilToInt` 向上取整为整数**，不保留小数（用户铁律，跨技能一致）。
系数本身（如 `0.1`、`0.002`）在 SkillSO 以 float 存储，结算时向上取整。
