## 0. 探查结论（已核实）

- 工程**零美术资产**：无 prefab / fbx / png / mat / anim。所有可见物由代码程序化生成。
- 战斗 rig 是**重度 prefab**（场景含 572 个 `PrefabInstance`），角色 / 音符 / 指示灯都是 prefab 实例。
- **角色外观**：运行时由 `CharacterCubeMarker` 驱动（挂在小立方体上），身份色来自 `CharacterDataSO.blockColor`。当前场景不序列化 `CharacterCubeMarker`，由 `CharacterBattleSystem` 的迁移逻辑在 Start 时挂上。
- **音符**：Tap 走 `NoteSpawner.notePrefab`（可换预制体）；Hold 在运行时由 `HoldNote.BuildVisuals()` **程序化生成网格**（无 prefab，节点=圆柱/圆角矩形，连接带=细分条）。
- **技能 VFX**：能量冒烟(`EnergyVFXPlaceholder` 3D) / 团队光环(`TeamAuraVfx` 3D) / 技能 Shockwave(`SkillSO.shockwavePrefab`) / Fever 是 **Canvas UI 叠层**（非 3D）。
- **材质管线**：项目用 URP/Lit。多数代码已用 `Universal Render Pipeline/Lit`，但 `EnergyVFXPlaceholder.cs:171` 仍用 `Shader.Find("Standard")` —— 在 URP 下会异常，需修正。
- **多网格隐患**：`CharacterCubeMarker` 与 `ActiveSkillRuntime` 技能 VFX 都只用 `GetComponent<Renderer>()`（只取**第一个**渲染器）。新角色模型若有多网格（身体+眼睛+乐器），上色 / 发光 / 沉睡会只作用于局部 —— 这是接入美术前**必须修的代码点**。
- **待清理（已确认）**：两个无用编辑器工具 `DemoBeatmapGenerator.cs`（Create Demo Beatmap）、`SceneSetupWindow.cs`（Setup Demo Scene）。已确认采用「内联保编辑器」方案（见 §6），仅删 Editor 工具、不碰任何运行时 / Demo 功能。

## 4. 模型导出方案（方式 / 格式待你选，见末尾提问）

### 4.1 输出目录（新建）
`Assets/Art/Models/`（角色、音符、指示灯、场地、VFX 各自子目录）。

### 4.2 通用规范（无论哪种生成方式都遵守）
- **枢轴**：放在几何中心（角色脚底可选下沉，但需标注，我先统一用中心，便于 Unity 里对齐旧 cube 的 Transform）。
- **尺寸**：严格贴合游戏逻辑数值——
  - 音符直径 ≈ `noteRadius×2 = 0.9`，厚 ≈ `0.12`；连轨音符 Z 向跨度 = `laneSpacing×(span-1) + 0.9`（laneSpacing 默认 1）。
  - 角色方块整体缩放匹配现有 cube（导出时按 1×1×1 单位基准，Unity 里再调 scale）。
  - 轨道间距 = `NoteSpawner.laneSpacing`（默认 1 单位）；指示灯 8 个沿 Z 排布。
- **命名**：`Char_Xiong`(小熊)/`Char_Dog`(大狗)/`Char_DuDu`(嘟嘟)/`Char_BuMu`(布姆)/`Char_Hei`(小黑)、`Note_Tap`、`Note_Hold_Ref`、`LaneIndicator`、`JudgeLine`、`CenterBar`、`Ground_Red`、`Ground_Blue`、`VFX_Energy`、`VFX_Aura`、`VFX_Shockwave`。
- **材质**：统一用 **URP/Lit**，开启 Emission（方便代码染身份色 / 过热发光）。顶点法线需正确（否则 URP 下光照发黑）。

### 4.3 生成方式（已确认：程序化精确网格）
采用**程序化精确网格**：我用脚本按游戏逻辑数值生成比例/枢轴精确的基础网格。本机已确认安装 Blender（`/d/Game/blender.exe`），执行时用其无头模式在脚本内搭建场景并导出 FBX，无需你手动操作。

### 4.4 文件格式（已确认：FBX）
统一导出 **FBX**（Unity 原生、Blender 直接打开、保留层级与材质槽）。
