# 练习模式 · 功能对接文档（技术落地）

> 面向对象：程序。本文给出可直接落地的架构、数据模型、接口签名、现有战斗代码改造点与里程碑。
> 配套：01_需求文档（做什么）、02_说明文档（为什么）、03_流程思维导图（流程）。

> ⚠️ **代码对账修订（v4 只读审计后）**：本文档已按当前 demo 真实代码对齐。关键修正——① 曲目数据类名为 `BeatmapSO`（非 `TrackSO`），需扩展 `name / difficulty / speed` 字段；② 循环接口为 `NoteSpawner.ResetSpawner()`（非 `Restart()`）；③ 真实代码**无 `BattleResult` / `NoteInputController` 类**：胜负在 `GameManager.CheckAndShowWinner`，键盘输入在 `NoteSpawner`、AI 输入在 `OpponentInput`；④ 角色 `characterId` 为 **int 型**，主角 = `1`（SO 的 `displayName`="小熊"，`m_Name` 遗留旧名"宝宝（玩家自己角色）"）；⑤ `CharacterDataSO` 当前**缺 `prefabPath` 与角色类型 `type` 字段**，需新增才能支撑角色卡立绘与标签。

## 1. 架构总览

```
GameFlowManager  (单例, 常驻 GameObject)
 ├─ GameState 状态机: Login / MainMenu / PracticeEntry / BandSize / CharSelect
 │                    / AIRoster / TrackSelect / InBattle / Result
 ├─ 持有 SaveData (当前槽)
 ├─ 驱动 SceneManager.LoadScene + Panel 叠加
 └─ 接收 ModeContext 启动战斗, 战斗结束(自定义回调, 非 BattleResult 类)写存档

SaveSystem (静态类, 独立场景)
 └─ Load/Save/Delete/GetLastSlot/HasAnySave  →  JSON @ persistentDataPath/saves/slot_{N}.json

Meta UI 层 (PracticeEntryPopup / BandSizePopup / CharacterSelectPanel /
           AIRosterSelectPanel / TrackSelectPanel / PracticeBattleHUD /
           PracticeResultPopup / SkinEditorPanel)
   ↓ 构造 ModeContext
GameFlowManager.StartBattle(ctx) → 加载 BattleScene 注入 ctx
   ↓ 战斗结束
战斗结束回调 → 写 SaveData → 回对应 Lobby / 弹结束窗
```

### 2.2 ModeContext.cs
```csharp
public class ModeContext {
    public ModeType mode;            // PracticeAI / PracticeSolo
    public TeamData playerTeam;      // 含主角(固定小熊) + 队伍
    public TeamData botTeam;         // AI对战=AI阵容; 单人练习=1机器人占位

    public float speedMultiplier = 1f;
    public Difficulty difficulty = Difficulty.Normal;

    public PracticeAIConfig botConfig; // 单人练习机器人参数
}
public enum ModeType { PracticeAI, PracticeSolo }
public enum Difficulty { Easy, Normal, Hard, Insane }
```

### 2.3 TeamData / TeamSlot
```csharp
[Serializable]
public class TeamData {
    public int protagonistId = 1;             // 固定主角 characterId=1 (displayName="小熊"; 资源已重命名为 小熊（玩家自己角色）_1.asset)
    public List<TeamSlot> slots = new();  // 长度 = 开放音轨数
}
[Serializable]
public class TeamSlot {
    public int characterId;      // 具体角色 characterId(int); 未选=-1
    public bool isRandom;        // 是否为随机卡
    public string resolvedId;    // 进战斗时随机解析结果(同局固定)
    public string skinId;        // 当前皮肤
    public int trackIndex;       // 占用的音轨 (开放音轨之一)
}
```

### 2.4 PracticeAIConfig.cs

public class PracticeAIConfig {

### 2.5 BandSize.cs
```csharp
public enum BandSize { Two=2, Three=3, Four=4, Five=5 }
// 规模→开放音轨: 2→[2]; 3→[2,1]; 4→[2,1,0]; 5→[0,1,2,3]
public static class BandSizeMap {
    public static int[] OpenTracks(BandSize s) => s switch {
        BandSize.Two   => new[]{2},
        BandSize.Three => new[]{2,1},
        BandSize.Four  => new[]{2,1,0},
        BandSize.Five  => new[]{0,1,2,3},
        _ => new[]{2}
    };
}
```

### 2.6 RandomRosterResolver.cs
```csharp
public static class RandomRosterResolver {
    // 进战斗/再来一局时调用; 对单侧 slots 解析 isRandom→resolvedId

    public static void Resolve(TeamData team, List<int> ownedIds);  // 真实 characterId 为 int
}
```

## 3. 各脚本职责与接口签名

| 脚本 | 职责 | 关键接口 |
|---|---|---|

| `SaveSystem` | JSON 读写 | `Load(int)`, `Save(int,SaveData)`, `Delete(int)`, `GetLastSlot()`, `HasAnySave()` |

| `SkinEditorPanel` | 皮肤页签 | `OpenFor(string charId)`, `ApplySkin(string skinId)` |
| `AIRosterSelectPanel` | AI 阵容 | `Build(int bandSize)`, `OnGO()` |
| `TrackSelectPanel` | 歌曲选择 | `OnSelectTrack(BeatmapSO)`, `OnSpeed(float)`, `OnDifficulty(Difficulty)`, `OnGO()` |
| `PracticeBattleHUD` | 单人练习 HUD+暂停层 | `ShowPause()`, `OnResume()`, `OnTuneBot()`, `OnBackToTrack()`, `OnBackToChar()`, `OnBackToBand()`, `OnExit()` |
| `PracticeResultPopup` | AI 结束弹窗 | `OnRetry()` / `OnChangeBand()` / `OnChangeChar()` / `OnChangeTrack()` / `OnExit()` |

| `RandomRosterResolver` | 随机解析去重 | `Resolve(TeamData, ownedIds)` |

### 3.1 关键事件流（单人练习）
```
CharacterSelectPanel.OnGO()
  → TrackSelectPanel → ModeContext(isPractice=true, botTeam=1机器人占位, botConfig)
  → GameFlowManager.StartBattle(ctx)
  → BattleScene: NoteSpawner 正常生成玩家侧音符
                  BotPracticeController 协程每 intervalSec 给 botTeam 加 scorePerTick
                  NoteMirrorPreview 把玩家音符半透明渲染到 bot 侧场地
                  ScoreManager.HP下限=1 (双方)
  → 曲结束: NoteSpawner.OnTrackEnd → ModeContext.isPractice → ResetForReplay() 自动循环
  → ESC/暂停按钮 → PracticeBattleHUD.ShowPause() (6 项)
```

## 5. 现有战斗代码对接点（改造项）

| 现有脚本 | 改造项 | 触发条件 |
|---|---|---|
| `CharacterDataSO` | 新增 `prefabPath`(立绘资源路径) 与 `type`(角色类型标签, 对应文档"角色类型"列) 字段；标签/战力/HP 经 `CharacterImporter` 从 Characters.xlsx 落到 SO | 角色卡渲染 |
| BattleScene 入口 | 由裸 Sample 改为读 `ModeContext` 启动 | 始终 |
| `NoteSpawner` | 加 `BeatmapSO track` 字段 + `ResetSpawner()` + `OnTrackEnd()` 回调 | isPractice 循环 |
| `ScoreManager` | 加 `ResetForReplay()` + `MinHpFloor=1`（双方） | isPractice |
| `BattleVisualsController` | `isPractice` 标志 → 隐藏对方侧音符/HP UI、显示「个人练习」提示 | isPractice |
| `CharacterCubeMarker` | 复用做机器人占位 prefab（参数 = PracticeAIConfig） | isPractice |
| `LaneIndicator` | 隐藏对方侧指示灯 | isPractice |
| 输入系统 | 练习模式禁用对方侧输入（键盘判定在 `NoteSpawner` / AI 在 `OpponentInput`，**无独立 `NoteInputController` 类**） | isPractice |
| 胜负判定 | 真实代码在 `GameManager.CheckAndShowWinner`；练习模式不弹/不结束，AI 对战照常弹 `PracticeResultPopup`（**无 `BattleResult` 类**） | isPractice / AI |

> **半透明音符实现要点**：`NoteMirrorPreview` 监听 `NoteSpawner` 的音符生成事件，在 bot 侧场地克隆一个**仅渲染、不参与判定**的半透明副本。副本不进入 `ReportJudge` 管线、不被输入系统响应（键盘判定在 `NoteSpawner` / AI 在 `OpponentInput`）。这样附魔/清屏等依赖「未显现音符」的逻辑照常运行。

## 10. 实现注意点（防坑）
1. **随机解析时机**：每次「开局」调用一次 `Resolve`，单局内 `resolvedId` 固定；「再来一局」重新调用。
2. **去重范围**：仅本侧；两侧可同角色。
3. **半透明音符必须逻辑隐身**：只克隆渲染对象，不进判定/输入管线。
4. **HP≥1 双方**：`ScoreManager` 在 isPractice 下 clamp 玩家与 bot 两侧。
5. **开放音轨关闭位不渲染**：`CharacterSelectPanel` 仅按 `BandSizeMap.OpenTracks` 生成槽位。
6. **主角固定小熊**：`protagonistId` 默认 `1`（int，即 characterId=1，displayName="小熊"；代码资源已重命名为 小熊（玩家自己角色）_1.asset），更换交互保留但当前无其他主角可选。
7. **GO 前置校验**：所有开放槽位（含主角）选满才可进入 Step C。
