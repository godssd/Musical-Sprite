## 2. P2 · 剧情模式 · 第一章节

### 2.1 定位
- 单机剧情体验：玩家按主线进度推进，从「第一章」开始游玩。
- 优先级在 P3（快速 / 排位 / 讨伐）**之前**——即**不依赖服务器**即可开发。

### 2.2 已确定的结构（来自你最初的主界面描述 + v4 优先级）
- 主界面点「**剧情模式**」→ 进入 `StoryLobby`。
- `StoryLobby`：章节列表 → 选小关（第一章含若干关）→ 进战斗。
- 战斗 = 复用 P0/P1 的 `BattleScene` + `ModeContext`（mode=Story），对手为 AI（同 P0 AI 对战内核）。
- 关卡完成写存档：`storyProgress{ chapter, level }`。

### 2.3 待细化需求（进入详细设计时需你确认）
1. **章节 / 关卡数据结构**：`ChapterSO`（章节名、关卡列表、每关曲目 / 对手阵容 / 解锁条件、过场对话）。
2. **剧情对话系统**：每关前后过场对话——先占位 TODO（读 `ChapterSO.dialogueLines[]` 弹气泡），文案由你后续提供。
3. **第一章体量**：包含几章、每章几关、对手阵容是否就是现有 5 角色库。
4. **剧情战斗差异化**：是否 HP 致死、是否结算段位、是否允许中途暂停编辑队伍。
5. **奖励 / 解锁联动**：通关解锁新角色 / 皮肤如何写 `SaveData`。

### 2.4 与 P0/P1 的复用
- `ModeContext`（已有草稿）加 `storyChapter` / `storyLevel` 字段。
- **队伍编辑复用**：玩家用同一套「乐队规模 + 角色选择 + 随机卡」UI 进剧情战斗（与练习一致），避免重复造轮子。

## 3. P3 · 快速对战 / 排位模式 / 讨伐模式

### 3.1 共性：必须搭服务器 / 联机
- 三者本质是多玩家**实时**对战 / 协作，必须搭设服务器（匹配 / 房间 / 状态同步）。
- **当前决策**：主菜单对应按钮**可见但置灰**，附「待服务器就位」提示；**不删入口、不实现内核**。
- P0 的「AI 对战」作为 P3 联机前的单机占位体验（玩家先和 AI 打）。

### 3.2 快速对战（Quick）
- 原始描述：以当前存档展开**快速对战**的 pvp 游玩。
- 细化方向：快速匹配 / 自定义房间，短局 pvp。

### 3.3 排位模式（Ranked）
- 原始描述：以当前存档展开**排位对战**的 pvp 游玩。
- 细化方向：段位（`rankedTier`）、积分（`rankedPoints`），需服务器匹配 + 防作弊 + 赛季。
- 存档字段已预留：`SaveData.rankedTier` / `rankedPoints`。

### 3.4 讨伐模式（Hunt）
- 原始描述：匹配或召集队友**挑战强力 boss**。
- 细化方向：协作 PvE，Boss 战（`BossSO` 数据驱动），队友匹配（服务器）或本地召集。
- 存档字段已预留：`SaveData.huntRecords[]`。

### 3.5 待细化（进入设计时需你确认）
1. 服务器选型 / 架构（自研 / 第三方如 Photon / Unity Netcode）。
2. 匹配规则、房间协议、断线重连。
3. 排位赛季与奖励；讨伐 Boss 列表与难度曲线。

- **定位**：在「第一章（P2）」与「P3（快速 / 排位 / 讨伐）」**之后**开发。

- **依赖**：P2 框架稳固 + P3 联机能力（部分后续章节可能含联机协作关）。
- **待细化**：章节总数量、跨章节存档、可能的多结局。

## 5. 跨模式公共需求（P2~P4 通用）

### 5.1 存档系统（`SaveSystem` 已规划）
- 需扩展支持：`storyProgress`、`rankedTier` / `rankedPoints`、`huntRecords`、`unlockedCharacters`、`unlockedTracks`、`skins`。
- 3 槽 JSON 落盘：`Application.persistentDataPath/saves/slot_{N}.json`。

### 5.2 美术资源储备与替换（你当前正在准备）
- **目标**：战斗内资源（角色立绘 / 方块贴图 / 技能特效 / UI 图标 / 场景背景）与流程 UI（登录 / 主菜单 / 各 Lobby / 角色卡 / 歌曲选择）后续替换为正式美术资源。
- **替换策略**（P0/P1 需求中已约定）：所有可视元素经 ScriptableObject 配置——
  `UIStyleConfig` / `CharacterDataSO.prefabPath` / `ChapterSO` / `BeatmapSO`(曲目) / `BossSO` / `CosmeticSkinSO`，
  美术到位**只换资源不动 C# 逻辑**。
- ⚠️ **当前缺口**：`CharacterDataSO` 仍缺 `prefabPath`（立绘路径）与 `type`（角色类型标签）字段——P2 角色卡渲染、P3 头像等都需要，须优先补上（见 `05_代码现状审计.md` § 末注 / `04_功能对接文档.md` §5）。
