# 练习模式 · 需求文档（P0 AI 对战 · P1 单人练习）

> 文档版本：v1（需求确认版，待开发）
> 项目：Musical-Sprite（Unity 6 + URP + C#）
> 关联文档：02_说明文档 / 03_流程思维导图 / 04_功能对接文档
> 本版范围：**练习模式**下的 P0（AI 对战）与 P1（单人练习）。P2–P4（剧情第一章 / 快速排位讨伐 / 剧情后续）不在本版开发，仅占位说明。

## 0. 范围与优先级

| 等级 | 模式 | 本版状态 | 说明 |
|---|---|---|---|
| **P0** | 练习 · AI 对战 | **本版开发** | 现有战斗 demo 已接近 AI 双方对战，复用 BattleScene 成本最低，置前 |

## 1. 练习模式入口弹窗

### 需求描述
主界面点击「练习模式」后，弹出居中半透明小窗，提供两个模式入口与回退：
- **AI 对战**（P0 实装，可点）
- **单人练习**（P1 实装，P0 阶段可置灰或同批做入口）
- 窗口右下角「✕」回退到主界面

### 制作内容
- `PracticeEntryPopup.cs`：半透模糊背景 + 居中弹窗（约屏 1/3 大小）。
- 两个大按钮（图标 + 文字）：AI 对战 / 单人练习；未实装按钮置灰 + 「敬请期待」角标。
- 右下角「✕」关闭弹窗。

### 验收标准
- 点击主界面「练习模式」弹出该窗；点 ✕ 关闭回主界面。
- AI 对战按钮可进入 Step A；单人练习按钮在 P0 阶段不可进入（置灰），P1 阶段可进入。

## 2. 乐队规模选择弹窗（Step A）

### 需求描述
进入任一练习模式后，先弹出乐队规模选择：双人 / 三人 / 四人 / 五人。确认后据此开放对应队伍音轨槽位。默认选中「三人」，记忆上次选择，并提供「重置回三人」。

### 制作内容
- `BandSizePopup.cs`：4 选项卡片 + 右下「下一步 →」+ 左上「← 上一步」/ 右上「✕」。
- 默认选中 = 上次存档值，无存档则三人。
- 「重置」按钮：清回三人。
- 选择结果写入 `SaveData.lastPracticeBandSize`。

### 验收标准
- 4 选项可点选，未选时「下一步」置灰。
- 选择「三人」开放 2 个队伍槽位、「五人」开放 4 个，对应关系见 §4.3。
- 重开后默认选中上次值；点「重置」回到三人。

## 3. 角色选择界面（Step B）

### 需求描述
乐队规模确认后进入角色选择界面（布局参照提供的角色选择参考图）。玩家从左侧仓库选角色填入右侧队伍槽位，可拖动换位，可切到皮肤页签编辑当前角色皮肤。所有开放槽位选满后方可「GO」。

### 制作内容
- `CharacterSelectPanel.cs`：整体容器。
  - **顶部状态栏**：左 = 总战力 + HP（红心）+ 攻击力（剑）合计；右上 = Home + ⚙ 设置。
  - **左侧 ~30%**：角色仓库（2 列纵向滚动）+ 紧贴右缘侧边标签 `[角色][皮肤]`。
  - **右侧中央**：队伍展示位（主角主位 + N-1 个开放音轨槽位），半圆分布。
  - **底部中央**：「GO！」大金按钮，未选满置灰。
- `CharacterCard.cs`：单张角色卡（仓库卡 / 队伍卡 / 随机卡），字段映射见 §3.1。
- `SkinEditorPanel.cs`：皮肤页签内容，列出当前编辑角色已拥有皮肤，点击应用。

### 3.1 角色卡字段映射
| 卡位置 | 含义 | 数据来源 |
|---|---|---|
| 左上小圆（彩色） | **角色标签** = 文档「角色类型」列 | Characters 文档 |
| 左上 "E" | **删除/隐藏**（无该数据） | — |
| 右上 | **角色名**（原 "Yp:47" 改为显示名字） | CharacterDataSO |
| 中央 | 立绘 | 待新增：CharacterDataSO.prefabPath（当前 SO 缺此字段，临时用占位方块）|
| 底部两数值 | **战斗力 + HP** 两项 | Characters 文档 |
| 灰色 ? 槽 | 未解锁角色 | unlockedCharacters |

### 3.2 仓库交互
- 单击仓库角色卡 → 填入**当前选中**队伍槽位（替换逻辑：仓库角色替换槽位角色，原槽位角色回仓库）。
- 已上场角色卡右上角打「使用中」标记，不可再选到别的槽位。
- 单击队伍槽位角色 → 选中该槽位（用于拖动换位 / 皮肤编辑目标）。

### 3.3 队伍位置与音轨
- 主角固定占**主位**（中央，非音轨位），不可换、不可拖动（更换交互功能保留，当前仅小熊可选）。
- 队伍角色占**开放音轨**；开放音轨之间允许拖动换位。
- 关闭音轨位置完全不显示（不渲染空框）。

### 3.4 皮肤页签
- 侧边标签 `[角色][皮肤]` 切换仓库右缘页面。
- 当前编辑目标 = 当前点中的队伍角色（未点任何角色 = 主角）。
- 皮肤列表 = 该角色已拥有皮肤卡（缩略图 + 名称），点击即应用 → 本次战斗立即生效 + 写存档。

### 3.5 GO 触发
- 所有开放槽位（含主角位）选满才可点 GO；未满时置灰 + 提示「还需选 X 个角色」。

### 验收标准
- 界面布局与参考图一致（仓库左 / 队伍中 / 皮肤标签右缘）。
- 角色卡显示：标签色块、名字、战斗力、HP，无 "E"。
- 仓库角色可填入槽位；已上场角色标记「使用中」不可重复选；拖动仅在开放音轨间换位。
- 切到皮肤页签可编辑当前角色皮肤并即时应用。
- 未选满 GO 置灰；选满后可进入 Step C。

## 4. 随机人物卡规则（两种练习通用）

### 需求描述
人物仓库**第一张卡 = 「随机人物」卡**。放入队伍槽位后，进战斗瞬间解析为仓库已有角色中的随机一个（同局内固定）。场上不得出现重复角色；随机解析范围仅限本侧队伍内；**每次开局重新随机一次**（同局内固定）。

### 制作内容
- `RandomRosterResolver.cs`：
  - 输入：本侧槽位数组（含具体角色 / 随机标记）。
  - 解析：随机槽 → 从「本侧已拥有且未被本侧其他槽占用」的角色池中随机取一个；多个随机槽互不相同；随机结果 ≠ 本侧已选具体角色。
  - 时机：每次「开局」（含 AI 对战「再来一局」）重新解析一次；单局内结果固定。
  - 去重范围：仅本侧（玩家侧与 AI 侧各自独立去重，两侧可同角色）。

### 验收标准
- 仓库首卡为随机卡；放入槽位显示「随机」占位。
- 同一队伍内不出现重复角色（无论随机/指定混用）。
- 每次重开对战，随机槽重新随机；同一局内不变化。

## 5. AI 阵容选择界面（P0，Step B'）

### 需求描述
玩家队伍编辑完成后，进入 AI 阵容选择：初始全部成员显示为随机人物卡；**AI 规模与玩家完全一致**；玩家可保留全随机或改为指定角色。若以**指定阵容**开局，存档记录该阵容；若保持**全随机**，则依旧每次随机（不记录具体角色）。

### 制作内容
- `AIRosterSelectPanel.cs`：复用角色选择界面结构，但编辑对象为 AI 侧。
  - 初始全员 = 随机卡（规模 = 玩家规模）。
  - 支持把随机卡改为指定角色（同 §3 仓库交互）。
  - 「GO」进入 Step C。
- 存档：`SaveData.lastAIRoster = { mode: "preset" | "random", roster: [...] }`。
  - 加载时：preset → 恢复指定阵容；random → 全员随机卡（每局重随机）。

### 验收标准
- AI 阵容规模 = 玩家规模，自动同步。
- 初始全员随机卡；可改为指定；指定开局后下次进入恢复该指定阵容；全随机开局后下次仍为全随机。
- GO 后双方阵容确认，进入歌曲选择。

## 6. 歌曲选择界面（Step C）

### 需求描述
双方阵容确认（AI 对战）或玩家阵容确认（单人练习）后，进入歌曲选择：选曲目 / 速度倍率 / 难度。选曲后右侧显示预览（时长 / 难度 / 推荐战力）。切歌/速度/难度实时生效。

### 制作内容
- `TrackSelectPanel.cs`：曲目列表（BeatmapSO）+ 速度倍率（0.5/0.75/1.0/1.25/1.5/2.0x，默认 1.0）+ 难度（简单/普通/困难/疯狂，默认普通）+ 预览区 + 右下「GO」+ 左上「← 返回队伍编辑」。
- 选择结果写入 `ModeContext.track / speedMultiplier / difficulty`，并记忆到 `SaveData`。

### 验收标准
- 曲目 / 速度 / 难度可切换并实时预览。
- 「GO」携带选择进入战斗；「←」回 Step B（保留阵容）。

## 7. AI 对战战斗 + 结束弹窗（P0，Step D）

### 需求描述
歌曲 GO 后开始**真实双方对战**（复用现有 BattleScene + AI 对手），正常判定 / 胜负 / 结算。战斗结束弹出小窗：再来一局 / 更改乐队规模 / 更换角色 / 更换歌曲 / 退出练习。

### 制作内容
- BattleScene 经 `ModeContext`（mode=AI, playerTeam, botTeam, track, speed, difficulty）启动，复用现有判定/计分/连击/技能管线。
- `PracticeResultPopup.cs`：结束弹窗 5 项：
  - 再来一局 → 重新随机（若随机阵容）后重开本场。
  - 更改乐队规模 → 回 Step A。
  - 更换角色 → 回 Step B（玩家）/ Step B'（AI）。
  - 更换歌曲 → 回 Step C。
  - 退出练习 → 回主界面。
- 写入存档：双方阵容、曲目、速度、难度、乐队规模。

### 验收标准
- AI 对战为真实双方对战，判定/胜负正常。
- 结束弹窗 5 项各自跳转正确；再来一局按随机/指定规则重开。

## 8. 单人练习战斗（P1，Step D）

### 需求描述
对手 = 占位机器人（不真实出音符，靠 tick 给自己侧加分）；玩家侧真实出音符、真实判定。双方 HP ≥ 1。机器人侧场地内以半透明方式**提前显现玩家自己的音符**（代码层隐身，仅预览）。曲结束自动循环。

### 制作内容
- 复用 BattleScene，注入 `ModeContext(isPractice=true)`。
- `BotPracticeController.cs`：
  - 机器人占位：放在「对方侧的玩家主位」，其余队伍位置无角色直接显示为空。
  - tick 计分：`intervalSec`（默认 5.0，1–30，步长 0.5）、`scorePerTick`（默认 50，0–500，步长 10）每跳给**机器人自己侧**加分。
  - HP 下限：机器人侧与玩家侧均 ≥ 1（不致死）。
  - 不出音符（无判定、无输入）。
- `NoteMirrorPreview.cs`（半透明提前显现）：
  - 把玩家音符**以半透明方式渲染在机器人侧场地内**，从机器人判定线即可看到自己要打的音符（正常需越过粉杠才可见）。
  - **代码层这些音符仍为隐身**：不进入判定管线、输入系统忽略，仅视觉预览，保证附魔等需判定「未显现音符」的代码正常运行。

### 验收标准
- 仅玩家侧真实出音符并判定；机器人侧无音符、无判定。
- 机器人侧场地内可见玩家音符的半透明提前显现；该预览不参与判定/计分。
- 双方 HP 不低于 1。
- 曲结束自动重新循环（HP 不重置，仍浮空在 1）。

## 9. 单人练习暂停层（P1）

### 需求描述
随时可暂停（ESC + 屏幕暂停按钮）。暂停层 6 项：继续战斗 / 调整机器人参数 / 回歌曲选择 / 回角色选择 / 回乐队规模选择 / 退出个人练习模式。

### 制作内容
- `PracticeBattleHUD.cs`：
  - 顶：曲名 + 速度/难度 + 实时分数。
  - 底：暂停按钮 + 实时 HP（含「HP≥1」标识）。
  - 暂停层：6 项按钮（见需求）。
  - 「调整机器人参数」展开 `intervalSec` / `scorePerTick` 滑条，可实时调（恢复后生效）。
  - 触发：ESC + 屏幕暂停按钮（移动端仅按钮）。

### 验收标准
- ESC / 暂停按钮均可暂停；6 项跳转正确。
- 调参滑条可实时调节并在恢复后生效。
- 「回乐队规模选择」「退出个人练习模式（→主界面）」路径正确。

## 10. 存档系统

### 需求描述
独立于场景的存档：3 槽（可配），JSON 落盘 `Application.persistentDataPath/saves/slot_{N}.json`。练习相关字段：乐队规模、双方阵容（含皮肤）、曲目、速度、难度、AI 阵容模式。

### 制作内容
- `SaveSystem.cs`（静态类）：`Load(n) / Save(n,data) / Delete(n) / GetLastSlot() / HasAnySave()`。
- `SaveData.cs`：`lastPracticeBandSize`、`playerTeam`、`botTeam`、`lastAIRoster`、`lastPracticeTrackId`、`lastPracticeSpeed`、`lastPracticeDifficulty`、`skinSelections` 等。

### 验收标准
- 乐队规模 / 阵容（含皮肤）/ 曲目 / 速度 / 难度 / AI 阵容在对应时机正确读写。
- 默认阵容：主角 = 小熊（固定主位），其余队伍槽位首次为空（玩家需自选），之后记忆上次完整阵容。
- 开放槽位在开局时不得为空（GO 前必须选满）。

## 11. 顶部总览

### 需求描述
角色选择界面顶部显示当前所选下方角色成员（主角 + 队伍）的**战斗力 / HP / 攻击力合计**。

### 制作内容
- 在 `CharacterSelectPanel` 顶部状态栏实时计算并展示合计值（卡片底部单体值之和）。

### 验收标准
- 合计值随角色选择实时更新；口径 = 当前队伍成员单体值之和。

## 12. 美术占位与替换接口

### 需求描述
所有 UI / 立绘 / 图标先以 UGUI 纯色 + 文字 + 占位图标实现；通过 ScriptableObject 留好替换入口，美术到位只换资源不动逻辑。

### 制作内容
- `UIStyleConfig.cs`（SO）：按钮 / 面板 / 字体 / 图标 Sprite 路径集中配置。
- `CharacterDataSO.prefabPath`：角色立绘预制路径。
- `BeatmapSO.cs` / `CosmeticSkinSO.cs`：曲目(已存在, 需扩展 name/difficulty/speed 字段) / 皮肤数据驱动列表。
- 替换流程：美术到位 → 改 Sprite/Prefab/SO 字段 → 不动 C#。

### 验收标准
- 全部可视元素经 SO / prefabPath 引用，无硬编码资源路径散落。
- 替换美术资源无需改 C# 逻辑。
