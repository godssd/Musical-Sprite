# 美术资源替换方案（替换 Demo 占位方块）

> 目标：把 `Musical Sprite` 战斗 Demo 里的"粗糙方块/圆柱"逐步替换为正式美术资源。
> 范围：角色方块、音符、提示灯、判定飘字、技能/元状态 VFX。
> 适用工程：`D:\unity\plan go\Musical Sprite`（Unity 6 + URP）。

---

## 0. 结论先行

- 工程当前**零美术资产**：`*.prefab / *.fbx / *.png / *.psd / *.mat / *.anim` 全部为 0。所有可见物都是 `GameObject.CreatePrimitive` 程序化方块/圆柱，或代码生成的网格。
- 你看到的"粗糙方块"分三类，替换难度与代码改动量差异很大：
  1. **角色方块**（场景预摆 Cube + `CharacterCubeMarker`）：主角小熊 + 4 个乐队角色。最显眼，需要真实模型/预制体替换。
  2. **音符**（圆柱/圆角矩形，命中变黑→白→放大）：需要新网格+材质，但**判定数学依赖当前尺寸**，替换有约束。
  3. **占位 VFX 方块**（能量冒烟、技能光罩/电流、过热 tint、技能 Shockwave）：代码已标注"后续整体替换"，用真实粒子/特效预制体替换最干净。
- **需要改代码，但不多**：核心是让 `CharacterCubeMarker` 支持多网格模型 + 正确驱动 URP/Lit 的 `_BaseColor`/自发光（项目里 `AuraMat` 已证明 URP/Lit + `_BaseColor` 是现行约定）。

---

## 1. 设计视角：占位方块不是"丑"，是"反馈通道"

（游戏设计师视角）替换美术时不能只图好看，必须**保留这些方块正在传递的游戏信号**，否则游戏会"更不好玩"：

| 信号 | 当前由方块表达 | 新美术必须保留 |
|---|---|---|
| 身份色（灰/橙/绿/白/黑） | `material.color = blockColor` | 5 个角色一眼可辨；若用统一模型靠 tint，tint 必须生效 |
| 按键 ack | Flash 放大+提亮 | 按下即时视觉回应 |
| 主动技能激活中 | Grow + 发光 | 明显的"变大/发光"状态 |
| 沉睡状态 | 变灰 + 缩小 | 状态一眼可辨 |
| 过热元状态 | 向主题色混合 60% | 不掩盖身份色 |
| 可输入性 | 提示灯亮度 | 提示灯必须可见、不被特效遮挡 |

→ 任何新美术都不能遮挡这些信号；VFX 特效尤其不能盖住**提示灯**与**身份色**。

## 2. 现状盘点（每个方块的来龙去脉）

| 视觉物 | 生成方式 | 上色机制 | 控制代码 |
|---|---|---|---|
| 角色方块 ×N | 场景预摆 Cube + `CharacterCubeMarker` | `material.color = blockColor` | `CharacterCubeMarker`（scale/pos/color/emission）、`CharacterBattleSystem.ColorMarker`、`FeverVFXPlaceholder`（tint）、`SleepController` |
| 提示灯（每轨 1） | 场景物件 + `LaneIndicator` | active/idle 材质切换 + color | `LaneIndicator` |
| 音符（普通） | `NoteSpawner.notePrefab` 实例化 → `NoteMover` 改写网格为 Cylinder | `material.color` 黑→白 | `NoteMover`（尺寸=noteRadius 0.45、厚 0.12） |
| 音符（连轨） | 同上 → `RoundedRectMesh` | 同上 | `NoteMover` |
| 判定飘字 | `JudgeFeedbackManager` 预制体（当前无预制体回退运行时模板） | 预制体内 Text | `JudgeFeedbackManager`（**已预制体化**） |
| 技能 Shockwave | `SkillSO.shockwavePrefab` 实例化 | 预制体自带 | `ActiveSkillRuntime`（**已预制体化**） |
| 能量冒烟 | `EnergyVFXPlaceholder` 程序化 Cube | `material.color = cubeColor` | `EnergyVFXPlaceholder` |
| 技能光罩/电流 | `TeamAuraVfx` 程序化 Cube（4 处） | `AuraMat`（URP/Lit 发光） | `TeamAuraVfx` |
| 过热 tint | `FeverVFXPlaceholder` 屏幕 overlay + 方块变色 | `material.color` | `FeverVFXPlaceholder` |
| 其它技能方块 | `ActiveSkillRuntime` 程序化 Cube（4 处） | `material.color` | `ActiveSkillRuntime` |

**关键事实**：角色、提示灯、音符、判定飘字、技能 Shockwave 已经存在 `prefab`/`material` 字段入口；只有"占位 VFX 方块"是完全程序化生成的。也就是说——**多数替换是"填字段"，不是"改架构"**。

## 3. 资源准备清单与规格

### A. 角色模型（最重要）

- **数量**：主角 小熊 ×1；乐队 大狗/嘟嘟/布姆/小黑 ×4；建议加一个"通用占位角色"以备阵容扩展。
- **两条路线（二选一）**：
  - **路线① 统一模型 + tint（推荐）**：5 个角色共用同一套造型，靠 `blockColor` 上色区分。优点：美术量小、身份色一定生效；缺点：辨识度靠颜色。
  - **路线② 每角色独立模型**：辨识度最高；要求每个模型材质允许代码 tint（或代码不改色、纯靠自身配色）。
- **硬性规格**：
  - **枢轴(Pivot)**：放在模型几何中心（与现有 Cube 中心一致），保证放大/跳跃以中心为基准。
  - **世界尺寸**：以现有 Cube 的 `Transform.Scale` 为基准（请在 Unity 检视面板读取该值记为 S）。新模型在 scale=1 时约 1 单位高，放入场景后整体缩放 ≈ S 匹配原占位体积；跳跃/放大用的都是相对 `localScale`，无需改数值。
  - **渲染器**：**强烈建议单一 `MeshRenderer`**。若多网格（身体+眼睛+乐器），**必须做代码改动 #1**，否则 `GetComponent<Renderer>()` 只命中第一个，上色/发光/沉睡只作用局部。
  - **材质**：用 **URP/Lit**（与 `AuraMat` 一致）。tint 路线下 Base Map 用接近白/中性色让 tint 明显；启用 **Emission** 通道（代码发光用）。
  - **命名/路径**：`Char_Xiong`、`Char_Dog`、`Char_DuDu`、`Char_BuMu`、`Char_XiaoHei`，预制体放 `Assets/Art/Characters/Prefabs/`。

### B. 音符视觉

- **普通音符**：扁圆柱/圆盘，直径 ≈ 0.9（半径 0.45）、厚 ≈ 0.12；材质中性可 tint（黑→白命中反馈靠 `material.color`）。
- **连轨音符**：沿 Z 跨 2 轨的拉长扁块（当前 `RoundedRectMesh` 比例）。
- **约束**：只换材质、保留现有圆柱/圆角矩形网格 → 判定数学零风险；若换**自定义网格**，必须保持上述比例，并可能要调 `NoteMover` 的 `noteRadius`/厚度常量（见改动 #3）。
- 命名：`Note_Tap`、`Note_Chain`。

### C. 提示灯（LaneIndicator，已材质驱动）

- 准备两套材质（常亮=可输入、暗=idle），或一个小发光条模型+材质；尺寸沿用现有。
- 命名：`LaneLight_Lit`、`LaneLight_Idle`。

### D. 判定飘字（JudgeFeedbackManager，已预制体化）

- 准备 `Perfect / Good / Miss` 三个世界空间 Canvas + Text（或 Sprite）预制体。当前无预制体会回退到极小运行时模板（之前已修 CLEAR/PASS 复用 Perfect 预制体）。
- 命名：`FX_Judge_Perfect` 等。

### E. 技能 Shockwave（SkillSO.shockwavePrefab，已实例化）

- 准备冲击波预制体（环/波纹/粒子），在 `SkillSO` 资源里赋值即可，无需改代码。

### F. 占位 VFX（能量/光罩/电流/过热/其它技能方块）

- 能量冒烟 → 上浮粒子（Particle System）或精灵。
- 技能光罩/电流 → 已有 `AuraMat`（URP/Lit 发光），可升级为更精致的网格/粒子。
- 过热 tint → 屏幕 overlay（可保留或换更精致的全屏特效）。
- 建议先保留现有方块逻辑、加 `vfxPrefab` 字段（改动 #4），美术到位后赋值即替换，不必现在动算法。

## 4. 代码调整清单（确认后落地）

1. **`CharacterCubeMarker`（必改）**
   - `GetComponent<Renderer>()` → 缓存 `GetComponentsInChildren<Renderer>()`；`Flash/GrowGlow/PulseGlow/ApplySleepVisual` 对**所有** Renderer 同时设色/自发光。
   - 着色统一走 `SetTint(Color)` / `SetEmission(Color)` helper：同时写 `_BaseColor` 与 `.color`、并 `EnableKeyword("_EMISSION")`（对齐 `AuraMat` 的 URP/Lit 约定）。

2. **`CharacterDataSO`（建议加）**
   - 新增 `public GameObject modelPrefab;` + 可选 `public Material bodyMaterialOverride;`（audit 已标记缺 `prefabPath`/`type`）。让角色外观数据驱动，便于后续动态生成与皮肤系统。

3. **`NoteMover`（保守改）**
   - 新增 `public Material noteMaterial;` 字段；默认仍用程序化网格，但允许注入美化材质（保留判定数学）。若日后换自定义网格，再调 `noteRadius`/厚度常量。

4. **VFX 占位类（低风险、可分步）**
   - `EnergyVFXPlaceholder` / `TeamAuraVfx` / `ActiveSkillRuntime` 技能方块：各加 `public GameObject vfxPrefab;`；有值时 `Instantiate(vfxPrefab)` 替换原 `CreatePrimitive(Cube)`，无值回退原行为。

5. **`EnergyVFXPlaceholder` 修 Shader**
   - `Shader.Find("Standard")` → 改 `Universal Render Pipeline/Lit`（与 `AuraMat` 一致，否则 URP 下材质异常）。

## 5. 替换操作步骤（分阶段，每阶段可独立验证）

- **阶段 0（现在，你来做）**：按第 3 节规格产出/收集美术资产，放进 `Assets/Art/...`，命名规范如上。
- **阶段 1 角色方块（核心）**
  1. 在场景中选中带 `CharacterCubeMarker` 的 Cube；
  2. 换 `MeshFilter.mesh` + `MeshRenderer.material` 为新模型/材质（或把新模型预制体作为子物体、移除原 Cube 网格）；
  3. 应用改动 #1 / #2；
  4. 运行：确认身份色正确、按键 Flash、技能 Grow+发光、沉睡变灰缩小、过热 tint 都正常。
- **阶段 2 提示灯 + 判定飘字（低风险）**：赋值材质/预制体，运行确认。
- **阶段 3 音符（按需）**：注入美化材质，确认命中黑→白→放大不变。
- **阶段 4 技能 & 元 VFX**：赋值 `vfxPrefab`/`shockwavePrefab`，确认特效出现且不影响可读性。

---

## 6. 风险与验证

- **着色属性名**：URP/Lit 用 `_BaseColor` 而非 `_Color`；现有 `material.color` 在某些材质下可能不生效。以 `AuraMat` 为样板写 helper 最稳。
- **多 Renderer**：新角色若多网格，必须做改动 #1，否则只上色局部。
- **占位体积**：新模型 scale 要与旧 Cube 的 `Transform.Scale` 匹配，否则跳跃/放大位置错位。
- **判定数学**：音符自定义网格务必保持 0.9×0.12 比例，否则命中/重叠计算偏移。
