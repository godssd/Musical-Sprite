## 4. 有问题 / 需改造（文档与代码对不上）

### 4.1 文档类名 vs 真实类名（已在 01/04 回填修正）

| 文档原写 | 真实代码 | 处理 |
|---|---|---|
| `TrackSO.cs` / `TrackSO` | **`BeatmapSO.cs`**（已存在） | 曲目数据扩展 `BeatmapSO`，不新建 TrackSO |
| `NoteSpawner.Restart()` | **`ResetSpawner()`**（已存在） | 改名对齐 |
| `NoteInputController.cs` | **不存在**；键盘输入在 `NoteSpawner`，AI 在 `OpponentInput` | 文档改造点改指向这两个 |
| `BattleResult.cs` | **不存在**；胜负在 `GameManager.CheckAndShowWinner` | 文档改为「自定义战斗结束回调」 |
| `ScoreManager.ResetForReplay()` / `MinHpFloor(int)` / `isPractice` | 全部**不存在** | 需新增 |
| `ScoreManager.TakeDamage` 钳 0 + HP≤0 触发战败 | 练习需改为**钳 1 + 不触发战败** | 逻辑冲突，必改 |

### 4.2 战斗内核改造点
- `CharacterBattleSystem` 装配为**两侧镜像同阵容**，且从 `CharacterDataSO.laneIndex` 直接读，**不支持**「2/3/4 人队、指定角色、随机卡解析、按 band size 开关 lane」。需新增「按选择装配队伍」入口 + 动态显隐 marker。
- `GameManager` 获胜弹窗（红/蓝胜/平局）在练习模式必须**禁用**（不弹、不结束、曲终自动循环）。
- 单人练习「对方只显示主位方块、其他为空」：当前 marker 场景预置；机器人用对方 `laneIndex=-1` 的 marker 复用即可，但需按 band size 显隐其余。
- 暂停：需给 `Conductor` 加 `Pause/Resume`（冻结 `songPosition` 并不生成音符），`GameManager` 接暂停状态。

## 7. 落地风险与建议

1. **最复杂的新模块是「按选择装配队伍」**（band size→音轨映射 + 随机卡去重 + 主角固定），建议优先设计，它是所有流程的枢纽。

3. **先修订文档再写代码**：4.1 的命名差异已全部回填进 01/04，程序落地可照新文档的类名改。
4. **主角 ID 用 int 1**，不要照旧文档的 `"xiaoxiong"`。
